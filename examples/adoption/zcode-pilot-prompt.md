# ZCode 首轮提示词

在目标项目根目录打开 ZCode 工作区，再启动新任务。下面的内容可以直接作为只读接入检查
请求；若同时提供明确的普通工作项，才继续实现。不要为试点捏造代码修改。

```text
本次先检查低干预规则是否正确接入当前项目，不安装完整 AI Flow。

请先只读确认工作区和 Git 根目录、已有修改、实际读取的项目指令来源，以及相关质量命令。
保留现有 AGENTS.md、CLAUDE.md、局部规则、CI、权限和任务治理要求，不覆盖或自动迁移。
如果当前工具不自动读取局部规则，请在本次修改范围内显式读取，并说明实际范围。
不要把“文件存在”说成“工具已加载”；不能核实的来源明确标记未知。

若我已在同一请求中指定一个低风险、可恢复的真实工作项，请按现有项目规则连续完成
实现、必要测试和可恢复修复，不逐步问“继续吗”。如果缺少决定性业务输入或规定的审核/
动作授权，先完成不依赖它的工作，再一次性说明当前真正缺少的决定；不提前索取未来批准。
若我没有提供具体工作项，本轮只返回接入检查结果，不自行开始修改。

不要复制 harness-model 的 .ai、模型配置或 CI；不要新增 Hook、全局配置、后台采集或
自动任务。本次没有新增 push、merge、deploy、删除、凭据导出或付费调用的授权。
不要通过关闭产品保护或切换 Full access 消除弹窗。

收尾用简短结果说明真实执行过的检查与未验证项。若完成了具体工作项，再根据本轮已有
事实汇总人工决定请求的原因及明确返工；产品权限弹窗单独记录，可见信息不足写 unknown。
不新建必填统计表，不用等待时长估算人时，不宣称单个样本已经证明效率提升。
```

本仓已有项目规则，无须再复制通用片段。首次在本仓运行上述只读检查时，不应创建 task、
修改治理标记、重开历史 BLOCKED 项或索取新的规格/代码批准。
若后续指定了工作项，则按其实际范围重新核对本仓升级清单，不能沿用“只读”结论放行写入。
