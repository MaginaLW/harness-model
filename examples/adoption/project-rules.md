# 可合并的低干预项目规则片段

这是供目标项目按需合并的素材，不是自动加载文件、安装脚本或本仓规则的替代品。
先阅读目标项目已有指令；只补缺失条款，不整文件覆盖，不解除已有任务、审核或权限约束。
下面的代码块不含固定模型、技术栈、审批表或测试阈值。

```markdown
## 低干预协作

- 开始前确认任务范围、已有修改和工作区根目录，读取项目入口及本次目录范围内的局部规则。
  按既有治理决定是否需要任务记录；不要因换了 Agent 就新增审批链，也不要绕过已有流程。
- 将已授权、可恢复的工作连续推进到实现、必要验证和修复完成；普通实现细节自行决定。
  不逐步询问“继续吗”。只有缺少真实方向、风险接受或规定授权时，说明依据并问必要问题。
  当前有效的决定不重复请求；范围或版本变化导致失效时，先核查事实再解释缺项。
- 遵循项目已有测试、静态检查、覆盖率及 required CI；不降低门槛、不跳过失败检查。
  没有定义或无法执行的验证明确写出，不以静态阅读冒充运行结果。
- 保留用户修改、历史证据与失败记录。只做任务相关的最小完整修改，按项目规则小步提交。
  不擅自推送、合并、部署、删除数据、导出凭据或开启付费调用；核对各自所需的具体授权。
  指令约定不替代产品权限、沙箱或服务端保护。
- 可独立并行的工作按文件归属委派，主 Agent 同时推进其他工作并负责整体验证。
  使用当前产品实际支持的能力与资源限制，不复制其他产品的模型或并发配置。
- 收尾说明改动、真实验证、未完成原因和下一步。只从已有事实汇总人工请求与返工；
  不为收集指标增加逐次填报，未知人时或缺陷保持 unknown，不声称未经验证的改善。
```

测试命令和敏感路径沿用目标项目自己的明确规定；如果原来没有，先从项目文件中核实，
不要复制 harness-model 的 Python CI、`.ai` 身份、账本或 bootstrap 标记。
接入顺序和撤回边界见[接入指南](../../docs/operations/adoption.md)。
