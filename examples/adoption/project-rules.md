# 可合并的项目规则片段

从下列条款中选出本项目缺少的约定，填入实际入口和验证命令，合并到宿主会读取的项目文件。已有规则、权限和门禁继续适用。

```markdown
## 项目协作

- 从 <项目状态入口> 确认当前工作、未提交修改和适用的目录规则。以项目现有治理决定是否创建任务；保留其他人的修改与历史证据。
- 围绕用户可观察的结果复用现有代码，只改交付所需范围。在授权内连续完成实现与验证；需要业务决定、风险接受或新授权时说明具体动作和原因。
- 用 <项目验证命令> 验收。接口或配置有变时，核对生产端、消费者与一条真实用户路径；原有必需检查和 CI 继续执行。
- 收尾报告被测版本、实际运行的检查、结果与未验证项。记录失败及后续重跑的关联；推送、合并、部署、敏感数据和付费操作按项目授权办理。
```

项目有重复的专项流程时，把调用条件写入技能描述。可以在项目入口补一行指向该技能或现有文档。插件、MCP 服务和账户配置沿用目标宿主自己的管理方式。跨仓接入不用复制本仓的 `.ai` 身份、账本、模型配置或维护标记。

已登记试点依项目约定使用[反馈流程](../../docs/operations/feedback-loop.md)。接入顺序和验收示例见[接入指南](../../docs/operations/adoption.md)。
