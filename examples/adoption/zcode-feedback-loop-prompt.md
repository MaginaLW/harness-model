# ZCode 任务收尾闭环首次接入提示词

适用于所有者已登记的试点，当前是 `ai-agent-dotfiles` 和 `r3s-VPS`。等当前任务完成、
相关写入权交还后，在对应项目的 ZCode 任务中发送下方内容。每个项目首次执行一次；
之后由持久化入口接续，不需要每轮重新发送。不要将本文件当作 Hook 或后台服务。

```text
当前任务结束后，请为本项目接入 harness-model 的任务收尾反馈闭环。
这是已有试点的文档级接入工作，不启动新的业务任务，也不改变原有安全与审核要求。

先确认当前任务已完成收尾和必要验证、相关文件没有其他活跃写入者；未到安全边界就
保留待处理，不打断正在运行的工作，不覆盖、stash 或提交别人的修改。

定位我已指定的本地 harness-model 检出；未给路径时，只将同级 harness-model 目录
作为候选，核对 Git 根目录、仓库身份、分支和 HEAD 后才能使用，不能仅凭目录名认定。
来源不明、检出不存在或产品权限不允许跨仓库时说明 pending，不自动下载、切分支或扩权。
确认本项目在所有者已明确登记的试点范围内，读取该仓 AGENTS.md、
docs/operations/feedback-loop.md、docs/operations/adoption.md 和所需的规则示例。
同时读取当前项目 AGENTS.md、原有权威进度入口及本次目录规则。

按 feedback-loop.md 为本项目做一次最小接入：
1. 将简短的任务开始复读、任务收尾执行闭环的规则合入现有 AGENTS.md；具体方法放在
   适合的现有项目接入文档。不要整文件替换、复制整套
   harness-model、创建第二份任务账本或改写历史记录。保留项目专有约束。
   ai-agent-dotfiles 复用 docs/ZCODE.md；r3s-VPS 复用 README.md / docs/PROJECT_STATUS.md，
   不为统一名称另建 docs/ZCODE.md。按闭环指南的项目映射执行。
2. 在接入文档记录可信来源仓库、实际采用的上游提交和所用方法文件；来源必须是已有
   提交及已验证的相关修改，不能把任意最新 HEAD 视为已验证发布。记录只在本地获准
   位置可用的来源定位方式，tracked 文档不写本机绝对路径、用户名、凭据或原始日志。
3. 将版本一致性、可读取脱敏摘要、测试发现范围、实测耗时与预算、紧凑交接这五项方法
   逐条适配，已有等价规则不重复添加。不把另一个项目的缺陷当成本项目已有的缺陷。
   按本项目的文档修改规定验证并作本地提交，说明实际应用版本和未验证项。
   r3s-VPS 还须仅同步本次改动的既有文档在 tools/artifacts.manifest.json 的
   localValidationArtifacts 中对应哈希，不改部署条目、Schema、发现范围或无关项；
   最后一次修改后按项目要求完成离线 Strict 和独立审查，回执保存在原有树外位置，
   不为写入 PASS 再改变已验证字节。文档哈希同步不授权其他配置或源码修改。
4. 执行本次收尾闭环：基于当前真实任务记录筛选新反馈；有方向明确、可泛化且在文档/
   示例范围内的改进时，按 harness-model 的规则验证、提交，再回到本项目按版本回灌、
   验证和提交。无新反馈仍检查适用的待回灌差异；两者都没有则不修改、不制造空记录。
5. 今后在任务开始时显式读取本项目已持久化的入口，并在每次真实任务收尾按该入口
   继续闭环；记录下次自然任务的实际效果，不能自行启动下一业务任务来凑观察样本。

两仓写入前及提交前后均核对身份、分支、HEAD、暂存区和文件归属。无法确认安全交接、
版本漂移、验证失败、来源不可读或越界需求时，保留原证据，在既有收尾记录说明 pending
及原因；记录也不能安全写入时只在本任务答复中交接。不要绕过项目门禁、沙箱或权限。

此闭环不授权源码、CI、.ai、技能、全局/live 配置、部署、删除、推送、合并、凭据导出、
付费调用或后台采集；超出文档级范围的反馈只形成提案，按各仓规则取得所需方向与授权。
收尾告诉我：接入文件、实际采用的上游版本、真实验证、反馈处理/回灌结果和待处理项。
不能把入口文件存在、记录已写或单次通过说成自动触发已验证、可靠度改善或阶段三完成。
```

两仓的定位、版本去重、并发写入及验证边界以[闭环指南](../../docs/operations/feedback-loop.md)为准。
只有来源方法可用但没有新的业务工作时，完成首次接入即可，不补造历史反馈或效果样本。
