# 阶段三进入输入

本文档保留阶段二结束后可审计的原进入事实，并记录项目所有者已明确选择的 **B：3-A 低风险建议与校准、3-B 高风险 V3 独立准入和验收**。首个场景为本仓自然治理任务的只读建议，具体范围见[置信度反馈设计](../superpowers/specs/confidence-feedback.md)。阶段三仍为 `not_started`；路线采用本身不等于实现准入完成，也不代替其余统计与来源决定，不批准新私密采集、provider、宿主审批接管或高风险执行。

## 原 Phase 3 三门基线

下表保留原三门及其缺口，不删除或改写历史语义。当前独立进入关系见下一节；现有样本和度量缺口仍须在 3-A 对应用途中解决，真实 V3 缺口仍由 3-B 独立解决。

| 进入条件 | 当前结论 | 已有事实 | 仍缺少的证据 |
|---|---|---|---|
| 已积累足以区分任务类型和角色的内部记录 | `partial` | `.ai/tasks/` 已保留 AUTO、ASK、REVIEW、BLOCK、V0/V1/V2、审核、升级和失败重试记录；阶段二证据索引给出可重放入口。 | 尚未冻结“足够”的样本量、任务/角色分层、保留期、隐私边界和偏差检查；actor 仍只是 task-local 标签，不是身份或模型认证。 |
| 存在明确的真实 V3 用例 | `not_met` | 阶段二证明了 V2、定向变异和受限 Hook/CI fail-closed 语义。 | 尚未选择需要安全检查、故障注入、dry-run 与回滚演练的真实高风险任务，也没有批准的沙箱、回滚目标或损失边界。 |
| 费用、返工、审核缺陷和工具失败有统一采集口径 | `not_met` | task ledger、结构化 review findings、verification checks 和失败 receipts 已分别保留部分事实。 | 尚无统一版本化 telemetry contract；没有模型调用/费用来源、返工归因、缺陷严重度归一化、工具失败分类和脱敏/访问规则。 |

因此阶段二完成只解除“先完成可靠 V2 闭环”这一依赖，不自动打开阶段三实现门。

## 当前采用的 3-A / 3-B 进入与退出关系

项目所有者已选择 B，并选择本仓自然治理任务的只读建议作为首场景；首用途已选[追加机器审核并基于结果积累认识](../superpowers/specs/supplemental-machine-review.md)，首目标协议按 `review_detection` [具体化](../superpowers/specs/review-detection-protocol.md)。3-A 的非评分事实、建议与方法准备可先推进；3-A 生产估计和真实 shadow 不再等待 3-B 的真实 V3 用例，但仍须满足自身数据、方法、用途及治理准入。协议技术审核不冻结统计参数、独立真值或来源责任。两包均不以信心分数代替当前 route/V、批准或硬风险规则。

项目所有者已为 `review_detection` 粗略研究采用 95% 覆盖、等尾双侧 `alpha=0.05`（每尾 `0.025`），区间总宽 `U-L<=0.20`（20 个百分点）；不是 ±20 个百分点、模型 95% 可靠或能力阈值。该决定只确定这项研究精度，不认证来源、总体、独立真值/裁定、相关组、窗口、预算或风险接受已经成立。条件性样本规划只是设计需求，不是实际合格 N、样本充分或新预算；3-A、S2/S3 与整体 Phase 3 的准入状态保持原结论。

| 能力包 | 独立进入条件 | 退出所需证据 | 当前状态 |
|---|---|---|---|
| 3-A 低风险建议与校准 | 获准来源及身份边界；任务/角色分层、独立样本与充分性规则；版本化度量；隐私、访问、保留和偏差规则；统计方法、精度与具体只读用途；对应实现设计、Policy 影响评估和验证准入。非评分准备可先做，不冒充这些条件已满足。 | 固定版本的建议与权限反例验证通过；分层覆盖和缺失可解释；适用范围内的估计/校准及留出真实 shadow 达到已冻结标准；目标场景效果有可比事实，停用后可继续原流程。仅非评分工具、离线 synthetic 或历史回放不构成整包退出。 | 方向、首场景及追加机器审核/结果反馈用途已采用；`review_detection` 首目标方向与粗略研究精度已确定，其余来源、总体、裁定、相关组、窗口、预算、风险及质量条件未全部冻结，生产估计与真实 shadow 未准入。 |
| 3-B 高风险 V3 | 已选真实风险任务与资产；安全检查、故障模型、沙箱、损失、dry-run、备份及恢复边界；每个高风险动作的独立授权；对应设计、Policy 影响评估与验证准入。 | 真实任务中的安全检查、故障注入、dry-run 与回滚/恢复演练按冻结标准通过，原失败和结果未知均保留；V2 或 3-A 通过不能替代。 | 真实用例和执行边界尚未选择，未准入。 |

**Phase 3 整体完成只在 3-A 与 3-B 各自退出后成立**，并须通过两包共同接口、兼容性及证据映射核对。保留原 Phase 1–4 编号：3-A 退出不是 V3 完成，也不是整个 Phase 3 完成。Phase 4 仍依赖整体 Phase 3 真实退出、稳定接口和真实协调需求，不因先交付 3-A 而提前启动。进入状态只有实际实现准入完成后才更新，路线文档本身不把 `not_started` 改为已启动。

完整测试、85% 总覆盖率、90% diff coverage、whitespace、Ruff、format、mypy、required CI 与分支保护均保持；授权与维护模式仍以 [AGENTS.md](../../AGENTS.md) 为准。原件、失败和既有批准继续追加式保留，当前版本覆盖由 CLI `status` / `gate` 判断。

## 原三门路线的后继产物

下列产物保留原 Phase 3 的能力范围。B 将第 1、4 项及相关设计映射到 3-A，将第 2 项及相关设计映射到 3-B；第 3 项负责两包的设计、兼容和整体验收映射。准备材料可先形成，正式冻结与实施分别满足上述对应进入条件，不以材料存在判门通过。

1. 版本化 telemetry contract：定义任务/角色、模型与推理档位、费用、返工、review finding、
   tool failure、隐私和保留规则；缺失值必须显式，不得以默认分数代替。
2. 一个真实 V3 用例与沙箱/回滚边界：给出资产、故障模型、dry-run、备份、恢复目标和每个
   高风险动作的独立批准点。
3. 阶段三设计和实施目录：重新评估 Policy、Schema、兼容性、迁移、验证矩阵和非目标，
   并保持 route/V 与硬风险规则不可被信任度或成本评分覆盖。
4. 模型能力与选择方案：只能基于已定义的数据口径给出可审计理由；在真实 adapter、费用来源
   和身份绑定建立前，不得宣称自动模型路由已经可用。
