# 低干预效果基线

本页把“有可审计记录”与“减少了人工成本”分开。它是观察方法和已核实的账本快照，
不是新门禁、必填表、审批点或阶段三 telemetry contract；不修改 Policy、Schema、CLI
或任务状态，也不实现模型路由、信任评分、费用优化或自动观测。

## 固定提交的事实快照

同一工具提供可选的只读快照；原有默认 text/json 账本统计格式保持不变：

```sh
python tools/analysis/approval_overhead.py --snapshot --format text
python tools/analysis/approval_overhead.py --snapshot --format json
```

当前工具的 JSON 使用 ASCII 转义，解码后字段和原文字保持不变；默认 text 仅将当前输出编码无法表示的字符转义，正常 UTF-8 文本保持原样。上文历史版本的原始输出与 hash 仍按该固定版本复算。

账本 JSON／YAML／事件行超出解析器整数或嵌套能力时，停止报告并按原文件／行定位返回输入错误；默认统计、快照和可用性模式均不输出 traceback 或部分成功报告。根路径无法解析时也返回固定路径错误，不回显路径或换用其他根重试。错误退出码为 `2`，stdout 为空；这些错误不改变账本、批准或原结果。

快照格式版本为 `1.0`，用途标识为 `tracked_ledger_snapshot`。它先固定 `HEAD`，再读取该
提交中明确匹配的 `.ai/tasks/TASK-*/task.yaml`、`classification.json`、`events.jsonl`、
`evidence.json`、`reviews/REV-*-r*.json` 及同 task tracked
`review-contexts/<64sha>.json` Git blob；输出来源提交、实际执行工具的 SHA-256、
各来源文件的 blob 标识及受限字段投影。未被审核引用的 context 不解析或投影，
但仍列在白名单 blob 来源中。它不读取未提交材料、logs/private 目录或另行采集
原始聊天；解析白名单原件后不输出 actor、审核正文、命令或本机路径，不写入文件、账本或
Git 状态。缺少必要的 task/event 原件、参与解析的原件格式损坏或投影字段无效时
拒绝输出，错误信息不回显原内容。

每个 task 暂作为一个保守依赖组，输出原状态/路由、事件顺序及结果、审核阶段/版本/原结论、
当前 evidence 的绑定和各检查原结果。验证尝试按账本的 started/result 事件定位；无法证明
全历史完整性或对应 evidence 的尝试关系时保持 `unknown`；
`historical_first_result`、`history_completeness`、`evidence_attempt_linkage` 继续为 `unknown`。
后续通过、MERGED 或审核修订不会覆盖此前 FAILED/BLOCK/REQUEST_CHANGES；
检查、Finding、修订和重试不增加独立样本数。

context 只投影 Schema、stage、hash 与 base/spec/Policy/classification 绑定，以及
implementation 的 subject、evidence 或 V2 snapshot；design 的 subject/evidence/snapshot
为 `not_applicable`。按 canonical 内容 SHA-256 核对 context 文件名、`context_sha256`
与审核引用，不一致时拒绝快照；通过 hash 校验后，review 与 context 的 stage 对应关系
`context_linkage` 为 `matched` 或 `mismatched`，来源缺失保持 `unknown`。
这项关联核对不重算审核或当前批准新鲜度，不补造执行结果。

review 的 `event_links` 按 `review_id` + `revision` 对应账本事件。
`review_recorded` 的 stage/context 对应关系为 `matched`、`mismatched` 或 `unknown`；
`review_finding_resolved` 只记录 `revision_reference`，不回填原审核或新的验收结果。
REQUEST_CHANGES 后追加 resolved 不提供独立缺陷真值，也不证明重新审核或验证通过。

`coverage` 报告任务记录数及证据、审核、尝试等缺项；review 子记录计数为
`review_records`、`review_records_with_context`、`review_records_with_matching_record_event`。
来源存在与事件对应分别计数，不等于整条链已验收，也不增加独立样本数。实际模型身份、费用、人类工作分钟和
真实宿主事件始终为 `unknown`；缺失不补零，不据 actor 或工具耗时推断。快照没有重新验证
账本声明，不输出评分、概率或授权结论，也不认证独立样本。它是 S0 既有事实的离线输入，
不冻结 S1 统计/隐私参数，不启动 telemetry 采集、影子评估或阶段三实施。

## 四目标证据可用性

同一工具可输出非评分的证据可用性矩阵：

```sh
python tools/analysis/approval_overhead.py --availability --format text
python tools/analysis/approval_overhead.py --availability --format json
```

`--availability` 与 `--snapshot` 互斥；原默认统计及 snapshot 格式保持不变。
该模式直接复用固定 tracked HEAD 的白名单快照，不新增来源、发现私密目录或采集数据。
用途标识为 `confidence_evidence_availability`；`targets` 中的四个 ID 为
`author_first_acceptance`、`author_after_repair_acceptance`、`review_detection`、
`review_false_positive`，对应作者首次验收、修复后验收、审核检出与误报。
各目标的 `denominator_definition` 是候选定义文字，`required_facts` 列所需事实，
均不计算分母或确定纳入单位；
方法候选见[只读置信度方法设计](../superpowers/specs/readonly-confidence-method.md)。

| 证据标签 | 含义与边界 |
|---|---|
| `projected` | 该事实已由固定快照投影；不等于原声明已独立验证、缺陷真值或目标已可估计。 |
| `source_missing` | 该 fact 所需的白名单原件在固定提交中至少缺少一件，可能是部分缺失；不判断未提交、私密或其他来源中是否存在。 |
| `not_projected` | 所需字段没有被快照投影；不证明原仓不存在该事实。 |
| `linkage_unknown` | 已有投影不足以证明所需对应关系，或存在已知冲突；不以当前状态或最后一次通过补全链路。 |

`tasks` 按 `task_id`、保守 `dependence_group` 与 `facts` 展开；各 fact 给出
`availability` 和 `source_refs`，引用只列固定白名单中实际读取的文件。
`observations` 完整保留原 snapshot task 投影；部分来源缺失时，已有原值与冲突仍保留。
`coverage.task_records` 和 `coverage.by_fact` 只按任务事实计数，后者为每项事实列出
四种标签的计数，包括零；text 展示全部 `by_fact`，JSON 保留完整可复核投影。
这些覆盖计数只描述该快照，不提供目标真正分母或独立样本数。
原失败、取消、skip 和未知保留；关联、resolved 或缺少失败记录不生成新的验收与缺陷真值。
输出保持 `method_status=design_pending`、`probability_status=unestimated`、
`execution_allowed=false`；不输出评分、可估计资格、新门禁或授权。
S1 的数据、方法、用途、隐私和质量条件仍须分别形成并准入；矩阵不宣告全部冻结，
也不启动生产估计、真实 shadow、provider、V3 或宿主执行。
该模式继承 snapshot 的安全拒绝：必要原件缺少或参与解析的原件格式损坏时以退出码
`2` 拒绝，不输出空来源矩阵。

## 审核结果回读

[审核结果回读工具](review-feedback.md)复用上述固定 Git 白名单，以显式反馈投影增加
Finding 的 ID、严重度、状态和解决时间，以及解决事件的 Finding ID；原默认统计、snapshot
与 availability 的字段和格式保持不变。它保留 review 各修订的原 outcome、
受限 context/event 引用、验证尝试和 evidence 原值，输出原件的 commit/path/blob/locator。
不输出正文、reason、reviewer、actor、任意路径或 evidence refs，不补读 PR、会话或私密材料。

报告按 task/review/Finding 展示已观测历史与异常；resolved 只表示原件状态，
不补作者采纳、修复、独立复核或缺陷真值。实际身份与类别未有来源时保持未知，
task-free 审核反馈为 `not_projected`。可选外部榜单参考与这些事实并列，
不混分或更新模型能力；`model_score_update_status=not_implemented`。
它补结果回读，不证明完整反馈闭环、评分/真实 shadow 准入或效果收益。

## 最小 telemetry 与效果口径候选 v0.1

本节把长期观察提纲整理为版本化的最小口径候选，承接
[只读置信度数据合同候选](../superpowers/specs/readonly-confidence-data-contract.md)及
[方法协议](../superpowers/specs/readonly-confidence-method.md)。它不是运行时 telemetry
实现、自动采集或已冻结的阶段三合同，不扩展现有严格 Schema、快照白名单或权限。
下表“获准来源”限于当前已有授权；尚待形成的裁定、来源或协议是数据缺口，
不构成读取外部/私密材料、创建新副本或启动 provider 的授权。

追加机器审核用途的专项问题、作者处理与非作者复核反馈，见
[场景候选](../superpowers/specs/supplemental-machine-review.md)；沿用本节口径保留原值，
不把发现被采纳或审核结束解释为已取得效果收益。

每项观察应能对应一个匿名变更/候选链、实际候选版本、来源提交及 blob 或既有获准摘要引用，
并保留阶段、观察边界和原值。缺失使用 `unknown`，有依据的不适用才使用
`not_applicable`；观察期未结束使用 `open`。这些标记不能代替必需门禁或授权。

| 候选指标 | 单位与计量范围 | 获准来源与未知条件 | 不能推导什么 |
|---|---|---|---|
| `request_groups` | 同一答复处理的一组决定请求，单位：组；只计声明的协作窗口，原因另列。 | 已有获准收尾位置的匿名汇总须有直接观察依据；当前快照不投影请求组。窗口不完整或无法区分请求与进度消息则 `unknown`。 | 批准、DU、事件或动作条数不能换算人工打断数；不能据缺记录认定重复请求或 0 次。 |
| `decision_wait_seconds` | 同一请求组的请求到答复经过时间，单位：秒；起止与时区均须明确。 | 既有获准汇总中可复核的成对时间；当前原件的一条答复时间没有请求起点或组绑定，仍为 `unknown`。 | 账本事件间隔、聊天间隔或 Agent 运行时长不能替代等待，更不能替代人类工时。 |
| `human_work_minutes` | 人类在该窗口实际处理审核、决定或返工的工作时间，单位：分钟；分项须避免重复计数。 | 仅已有获准的人类自报摘要；未自报、窗口不符或归属不明则 `unknown`，不为补数再向人索取。 | 工具耗时、批准数、答复等待和费用不能换算人时。 |
| `author_first_result` / `author_repair_result` | 按预定阶段与协议记录候选链首结果 / 真正进入修复后的结果，单位：链上的目标事件。 | 既有 task、事件、evidence 与 review 的版本原件；首链、修复入口、父子版本或 evidence-attempt 关系未闭合时目标事件保持 `unknown`，已有原结果继续保留。 | 首次可见不等于全历史首次；末次通过或 MERGED 不覆盖原失败，检查、重试与修复提交不形成独立分母。 |
| `defect_truth` | 预定审查机会的独立正/负裁定，保留可处置性、严重度及匹配版本，单位由方法协议预先确定。 | 当前白名单不投影独立裁定；须先形成获准的独立真值来源、机会集和报告匹配规则，当前为 `unknown`。 | `APPROVE`、Finding、`resolved`、零 issue 或通过测试不能补成正/负真值、漏检率或误报率。 |
| `rework` | 有证据的返工事件与原因，单位：次；若有人力/耗时来源则另记分钟，不混用。 | 原失败、修订版本及既有获准脱敏摘要须能对应；只有失败或重试记录、原因与工作量不明时相关项为 `unknown`。 | 验证失败次数不等于返工次数；同版本重试、工具故障和预算调整不自动归为作者返工。 |
| `cost` | 同一候选/窗口的实际费用，保留币种、金额及计费范围；配置预算另列。 | 仅已有获准且可复核的计费摘要；本轮不新增费用来源，当前快照为 `unknown`。 | token、运行时长、标价或预算不能补成实际收费；不同币种和范围不能直接合计。 |
| `tool_failure` | 检查的原 `status`、`exit_code`、`timed_out` 及 `duration_ms`（毫秒）；原因另记代码/断言、环境/工具、真实超时、契约不一致或 `unknown`。 | 当前白名单 evidence check 原字段与验证事件；原因须有既有获准摘要支持，字段缺失或数值矛盾保留未知。 | 失败或非零退出码不自动证明工具故障；`duration_ms` 不等于人时，工具失败不自动证明作者能力差。 |
| `delivery_window` | 实际交付版本/结果、观察起点/终点、结束或 `open` 状态；时间使用明确时区，持续时间单位：秒。 | 既有交付 PR 引用或获准脱敏交付摘要及明确检查过的缺陷来源；仅有账本 MERGED、窗口未定或来源未检查则不认定完整交付/零缺陷。 | 创建到关闭的间隔不等于工作量；未完成观察期不计算交付后缺陷率或改善比例。 |

下一步按以下缺口准备具体输入，并在数据合同与方法协议中集中说明：

1. 为未来自然任务明确首候选、修复入口及父子版本、验收阶段与 evidence-attempt 对应的最小公开引用；保留旧链未知，不回填猜测值。
2. 在采用检出/误报目标前形成独立裁定责任、正负机会集、严重度和报告匹配规则；缺少独立真值时继续事实准备。
3. 明确效果比较的同类任务、窗口、请求组和返工口径；人时与费用仅随已有获准事实记录，缺失不阻塞实际交付。
4. 对未来新增来源先界定责任、访问、脱敏、保留与处置范围；具体用途、误差、预算和缺陷观察端点成立后再推进对应估计或真实 shadow。

## 尚不能得出的结论

人类实际被打断次数、审核/决策工作分钟、真实返工工作量、交付后缺陷率均为 `unknown`。
聊天等待时间不是人类工作时间，测试通过数不是缺陷逃逸率，验证失败不等于人为返工。
本页不回填猜测值、不把缺记录当成 0，不宣称已减少某个比例的人工成本。

| 字段 | 本次观察 |

本地测试、远端 CI 与发布各自绑定实际验证或交付的版本；旧提交的 CI 结果不能覆盖新提交，
本地通过也不能代替远端验收。`dirty` 工作区需保留可复核的差异摘要及范围；只有 commit/tree
不能标识未提交内容，收尾后的提交号也不能冒充当时被测版本。产物或接口版本变化时，
检查生产端、测试端及 CI 消费端的版本预期是否一致；记录检查结果，不在本文新增自动门禁。

可复核摘要应包含逐套件/检查名称、结果与汇总，并保留失败、跳过和未执行项及其原因。
在已有授权范围内清理临时产物前，先把可公开的脱敏摘要与证据定位保留在已有获准位置；
哈希只校验内容，不能代替已不存在的内容。只有文字完成声明且底层证据不可读取时标为
“仅项目记载”，没有相关记录时标为“缺失”；不要为补齐历史而自动重跑、回填或覆盖失败记录。

套件总数增长不能证明原有覆盖没有减少。移到辅助目录、改名或修改发现规则造成不再运行时，
应列出原检查、替代验证及尚未覆盖的行为；若仍待恢复，写明后续处理归属和已有计划，未确定则
记为 `unknown`。这与新增测试一起写进同一次收尾，无须逐项打卡。

验证预算与实际耗时分别写明来源和计量范围；配置上限不能当作真实消耗，聊天等待也不能当作
人类工时。失败原因可按代码/断言、环境/工具、真实超时、契约不一致或 `unknown` 记录；
增加测试导致预算调整、代码返工与同版本重试分别说明，不互相替代。声称“超时”前核对实际值、
阈值和单位；数值矛盾无法解释时保留疑点。模型身份只引用已有可核实元数据，费用、人时及
独立审核缺证据时保持 `unknown`，不从产品名、运行时长或自述推定。

同一次答复处理的一组问题算一个请求组，具体决定可另列原因；Agent 的进度播报、工具
运行、账本写入和阶段提交不算人类打断。可按方向选择、真实审核、外部动作授权、
缺少材料、已有有效决定的重复请求区分原因；没有证据时不判为“重复且不必要”。

只比较同类任务、相同观察窗口且证据可比的样本，先报告任务数 N、数据缺失数和原始值。
质量至少同时观察原有 CI 门槛、已确认返工与交付后缺陷；未定义合理样本和观察期前，
不计算成功率、效果百分比或因果结论。记录 0 个缺陷须同时注明已结束的观察窗口和
明确检查过的缺陷来源，仍不能扩大解释成“绝无缺陷”。
