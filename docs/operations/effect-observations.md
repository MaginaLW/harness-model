## 下一批真实工作如何观察

观察属于 Agent 的收尾记录，不要求人在每一步打卡或新增批准。只在已有、获准的事实
来源能够支持时记录；用户未自报的工作用时保持 `unknown`，不要为补齐统计再问一次。
一个完成的变更窗口汇总一次，后续更正或观察期结束时追加说明，不覆盖此前事实。

最小记录模板如下，全部字段都允许 `unknown`，缺失记录不阻塞交付：

```text
变更/任务及提交范围：
观察开始、结束及任务类型：
账本快照的提交、工具版本与摘要：
实际需要等待人类决定的请求组数及原因：
请求到答复的等待时间：unknown
人类自报的实际工作分钟：unknown
有明确证据的返工次数、原因和证据位置：unknown
交付后缺陷：unknown（观察期未结束时使用 open）
证据引用、缺失项与限制：
```

同一次答复处理的一组问题算一个请求组，具体决定可另列原因；Agent 的进度播报、工具
运行、账本写入和阶段提交不算人类打断。可按方向选择、真实审核、外部动作授权、
缺少材料、已有有效决定的重复请求区分原因；没有证据时不判为“重复且不必要”。

只比较同类任务、相同观察窗口且证据可比的样本，先报告任务数 N、数据缺失数和原始值。
质量至少同时观察原有 CI 门槛、已确认返工与交付后缺陷；未定义合理样本和观察期前，
不计算成功率、效果百分比或因果结论。记录 0 个缺陷须同时注明已结束的观察窗口和
明确检查过的缺陷来源，仍不能扩大解释成“绝无缺陷”。

## 保存与隐私边界

本仓库只跟踪方法、匿名聚合结论及可公开的提交/PR 引用。原始聊天、身份、凭据、逐次
会话记录和运行时材料不入库；不新增身份、模型或费用采集。现有 AI Flow 任务若需要
本地观察材料，可放在已忽略的 `.ai/tasks/<TASK-ID>/logs/` 下，不为此强制创建 task。
task-free 工作没有适合且获准的本地保存位置时，保留 `unknown`，不擅自新增存储位置。

没有持续监控或后台采集在运行。未来若需自动采集、统一数据契约、隐私/保留策略或
外部来源，须另行明确范围与所需授权，本页不提前批准这些能力。
