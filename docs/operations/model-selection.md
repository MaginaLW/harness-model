# 模型选择与代理职责

用户在宿主中选择模型与推理档位，项目按职责分工。

## 用 GPT-6.2 处理一次任务

Codex 提供 GPT-6.2 且用户希望主动选型时，日常改码、处理评审意见可选 Sol。需要跨服务追查故障或比对多种成因时可选 Astra。在应用中用模型选择器，在 CLI 中用 `/model`。可选项以当前会话为准。[OpenAI 模型说明](https://learn.chatgpt.com/docs/whats-new/gpt-62-astra-sol)

推理档位取决于调查深度。快速盘点可以用 Medium，跨系统验证一条假设可考虑 High，多个原因相互作用时再考虑 Extra High。给出完成条件和证据要求，让模型自行安排步骤。例如：“请从 README 的‘接入其他项目’走到项目规则片段。只读核对这条路径，列出实际打开的文件和失效的链接。” [OpenAI 的 Codex 提示指南](https://learn.chatgpt.com/guides/prompting-gpt-6-2-astra)

## 配置归属

项目 `.codex/config.toml` 启用原生子代理，沿用用户的模型、档位和并发设置。主会话与子代理的模型和档位键均未设置。子代理按运行时规则继承。显式选型前核对工具支持的型号、上下文继承限制及用户选择。并发工作量取决于独立任务、文件写入冲突和可用资源。

发布新模型不会触发自动迁移或降级。变更全局配置、外部 worker 路由、预算、权限或付费调用须有相应授权。UI 与后端表现不一致时，核对项目覆盖及该会话首轮 `turn_context`。既有回合的实际型号和档位以其元数据为准。[Codex 配置说明](https://learn.chatgpt.com/docs/config-file/config-basic)

## 文档使用职责名

| 职责 | 应描述的要求 |
|---|---|
| 主代理 | 拆解已授权工作、整合结果、核对验收条件与证据、报告缺口 |
| 执行者 | 在限定范围内完成实现或调查，提交可复核结果 |
| 独立审核者或验证者 | 按当前 Policy 保持身份与实现过程的独立性，审核实际候选及绑定证据 |
| 人类决策者 | 作出必要方向、风险接受及必须由人类作出的批准 |

这些职责不绑定某一型号，也不授予模型额外权限。更强或更新的型号不会替代独立审核、
人工批准或确定性 Gate；同一型号可以承担不同职责，是否独立仍按现有 Policy 与证据判断。

项目指令和通用模板按职责写能力要求、验证方法与失败处理。任务确需绑定型号时，在局部运行记录区分请求值与实际值，注明可核实的日期、运行时版本、推理档位及 worker 类型。缺失的元数据标记为未知。

## 历史回退与验证边界

排查版本 26.901.6511.0 时发现，后端模型目录接受 `max`，桌面端默认档位过滤却排除它，
从而把当时项目的 `gpt-5.6-sol / max` 解析成该模型默认的 `low`。首轮日志确认前端显式
提交了这一组合；隔离执行安装包原有选择函数也复现了回退。这里的型号与版本仅描述
故障证据，不是推荐配置；未完整重演用户发送前的 UI 选择过程。

核查仓库配置时，解析 TOML，确认顶层 `model`、`model_reasoning_effort` 及 `agents.default_subagent_model`、`agents.default_subagent_reasoning_effort` 均未设置。桌面端生效须用新会话首轮元数据验证。
