# 模型选择与代理职责

当前规则自 2026-09-08 起适用。项目所有者已撤销仓库对主会话及原生 sub-agent 的
固定型号与推理档位；具体选择交给用户和当前运行时，文档按职责描述工作。

## 配置归属

- 项目 `.codex/config.toml` 不设置 `model`、`model_reasoning_effort`、
  `agents.default_subagent_model` 或 `agents.default_subagent_reasoning_effort`。
  新会话沿用 UI 选择及用户全局默认；主会话与子代理不由仓库指定型号。
- 子代理未显式选型时沿用运行时的继承规则；如任务需要指定模型，先核对当前工具
  实际暴露的选项、上下文继承限制与兼容性，再遵循用户选择。不要根据旧文档恢复型号。
- `.codex/config.toml` 仍启用原生子代理，保留每会话并发上限 2。这不是整机资源保证。
- 新模型发布不触发自动迁移、自动降级或固定“最新”别名；也不授权修改全局配置、
  外部 worker 路由、预算、权限或付费调用。

UI 与后端表现不一致时，先检查项目覆盖和实际首轮 `turn_context`；不要只凭下拉框
或模型自述判定生效。配置变更不修改既有回合，已运行的会话应以自己的设置和元数据为准。
Codex 配置层级可参照 [OpenAI Docs](https://learn.chatgpt.com/docs/config-file/config-basic)。

## 文档使用职责名

| 职责 | 应描述的要求 |
|---|---|
| 主代理 | 拆解已授权工作、整合结果、核对验收条件与证据、报告缺口 |
| 执行者 | 在限定范围内完成实现或调查，提交可复核结果 |
| 独立审核者或验证者 | 按当前 Policy 保持身份与实现过程的独立性，审核实际候选及绑定证据 |
| 人类决策者 | 作出必要方向、风险接受及必须由人类作出的批准 |

这些职责不绑定某一型号，也不授予模型额外权限。更强或更新的型号不会替代独立审核、
人工批准或确定性 Gate；同一型号可以承担不同职责，是否独立仍按现有 Policy 与证据判断。

当前指南、AGENTS 和通用模板只写职责、能力要求、验证方法及失败处理。任务确需特定型号
时，在该任务的局部选择或运行记录中写明；可用时分别记录请求值和实际返回值，以及
日期、运行时版本、推理档位和原生/独立 worker 类型。缺少元数据就记录缺失。
本页不新增模型路由器、身份认证能力或每次操作必填的模型登记表。

## 本次回退与验证边界

排查版本 26.901.6511.0 时发现，后端模型目录接受 `max`，桌面端默认档位过滤却排除它，
从而把当时项目的 `gpt-5.6-sol / max` 解析成该模型默认的 `low`。首轮日志确认前端显式
提交了这一组合；隔离执行安装包原有选择函数也复现了回退。这里的型号与版本仅描述
故障证据，不是推荐配置；未完整重演用户发送前的 UI 选择过程。

移除项目固定值后，可解析 TOML 并核对上述四个键均不存在；UI 生效仍须用新会话的
首轮元数据验证。不要把配置检查或离线测试通过写成已经完成桌面端端到端验收。
