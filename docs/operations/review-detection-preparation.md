# 契约检出研究的真实观察准备

本页把[已采用的起步范围](../superpowers/specs/review-detection-admission.md)转为后续自然工作的移交流程。当前交付仅为准备：本轮未登记或核定实际合格候选、真实机会或裁定记录，`T0/T1` 未设置，30 日窗口尚未启动。[离线数学工具](review-detection.md)只接受 synthetic 计数，不接收真实记录；准备完成不把它升级为真实评分接口。

## 自然任务出现后的配合与核对清单

真实评分、自动审核和宿主连接继续暂停，等有新材料后再核对。以下清单只整理正常工作本来产生的原件，不为取证创建任务、制造缺陷或追加审核；后文的派发、独立裁定、窗口和真实分析均为条件性流程，不是当前启动指令。自然任务出现或材料齐备也不自动解除暂停，`T0/T1` 保持未设置。

用户在首次非作者专项审核前提供原 PR／任务入口、候选提交和旧契约位置；其余优先由 Agent 在既有来源与授权范围内核对，不要求用户另建表格、手填分数或复制完整输入。按以下顺序保留和核对：

| 顺序与材料 | 用户保留或提供什么 | Agent 核对什么 |
|---|---|---|
| 1. 自然任务入口 | 原 PR／任务链接、候选 SHA、baseline 和适用旧契约的固定版本／条款位置。 | 是否为自然发生、仅含 `docs/**` 且含 `docs/superpowers/specs/**` 契约变更；是否尚在首次非作者专项审核前。已审核工作不追溯纳入。 |
| 2. 事前约定 | 原 PR／CLI 中准备声明的版本、位置和发布时间，以及完整机会清单、相关组／预选理由、允许材料、实际职责和原预算来源。 | 候选及旧契约是否固定，机会边界和选择规则是否完整，声明是否在审核前已有原件。缺失时保留缺口，不把事后补写当作历史事实。 |
| 3. 回读与实际开始 | 发布后的同版本回读，以及正常流程已有的派发、接收／开始记录和实际输入范围引用。 | 各原件能否绑定候选、输入、角色与预算，时序是否可复核；计划、协调者摘要、报告完成时间或 PR 时间不能代填实际开始。 |
| 4. 完整报告与异常 | 原报告 ID／revision／链接、对应候选、覆盖范围和完成状态；失败、partial、timeout、取消与重试分别保留。 | 报告是否完整、覆盖哪个固定候选；后续修复或通过不覆盖首次结果，零 Finding 或 APPROVE 不代填负真值。 |
| 5. 已覆盖的独立判定 | 仅当原职责与预算本来覆盖时，保留裁定者角色、实际可见材料及暴露时序、逐项正／负／争议／未知的理由，以及裁定固定后的匹配原件。 | 裁定者是否既非候选作者也非被测审核者，是否在未读被测报告的条件下裁定；匹配是否在裁定固定后对同候选给出语义依据。原安排未覆盖时只列缺口，不追加裁定轮次。 |
| 6. 预算与收尾 | 原授权及适用工作、预算维度／单位／上限、可证明的实际投入、完整报告范围和停止／关闭原件。 | 各来源是否绑定同一工作且可比；实际投入与剩余无依据时保持 unknown，不由 CI 用时、测试 timeout 或 PR 合并推算。 |

原件继续保存在原 Git／PR／CLI 位置，只移交链接和必要的脱敏摘要，不另存聊天、私有指令、身份或诊断包。实际输入不能公开复核时保留未知，不要求导出受保护内容。后续报告、裁定或关闭原件尚未自然产生时列为待补；本次核对只形成“已核原件、具体缺口、下一步所需材料”的摘要，不登记合格观察、向 synthetic 工具送入真实数据或改变审核安排。

维护方回复另按[回复后的核对步骤](../superpowers/specs/review-detection-host-evidence.md#维护方回复后的核对步骤)处理；宿主资料不能代替本清单的自然任务证据。

## 不依赖真实任务的离线演练

从完整克隆的仓库根运行下列 PowerShell 命令，复用项目 `.venv`；其他平台使用对应的项目解释器。输入是虚构仓库的空声明，不引用真实审核、宿主对象或观察窗口，仅在内存管道传递，不另存输入或输出副本。

```powershell
$declarations = @'
{
  "schema_version": "1.0",
  "repository": "synthetic/project",
  "admission_package": "review-detection-admission-v0.1",
  "window": {"t0": null, "t1": null},
  "candidates": []
}
'@
$declarations | .\.venv\Scripts\python.exe -B tools/analysis/review_detection_input.py
if ($LASTEXITCODE -ne 0) { throw 'Declaration rehearsal failed' }
$declarations | .\.venv\Scripts\python.exe -B tools/analysis/review_detection_sources.py . --resolve-locators
if ($LASTEXITCODE -ne 0) { throw 'Source rehearsal failed' }
```

两次正常退出均为 `0`，表示可输出报告，不表示准入。第一份报告的三个 `coverage` 计数均为零，第二份 `source_checks` 为空；两份均保留 `LOCATE_NATURAL_CANDIDATE`、空窗口、`observation_admission=unknown`、`probability_status=unestimated`、`model_score_update_status=not_implemented` 和 `execution_allowed=false`。原件入口只核显式仓库根，空引用不触发文档正文读取。

需要检查非空声明、冲突、真实临时 Git 对象和定位边界时，复用既有反例测试；这些夹具与测试结果不纳入研究记录：

```powershell
.\.venv\Scripts\python.exe -B -m pytest tests/unit/test_review_detection_input.py tests/unit/test_review_detection_sources.py tests/unit/test_snapshot_git_bounded.py tests/unit/test_review_detection.py -q
```

测试会在测试临时目录创建可丢弃夹具，pytest 可写忽略的缓存；这不是零写入命令。失败先诊断并保留结果，不改用宿主对象验证。演练完成后，可独立完成的入口和机械反例已有实现；下一步按[通道核定结果](../superpowers/specs/review-detection-host-evidence.md#7-已核通道的选择与落实顺序)补宿主资料，并在自然任务出现时按下节固定真实候选。不要把本次准备工作或旧审核追溯纳入未来窗口。

## 准备候选与来源

等本仓自然发生仅含 `docs/**` 普通文档、且包含 `docs/superpowers/specs/**` 契约内容的工作，再核对其首次非作者专项审核。不得为凑样本创建任务、制造缺陷、追加审核或追溯纳入已有报告。直接矛盾类的可检验要求、先前适用契约及版本，以[协议](../superpowers/specs/review-detection-protocol.md#2-机会裁定审核与匹配的顺序)为准。

协调者复用该工作的既有公开 Git／PR 原件。正式 task 仍按原 CLI、context 和 strict Schema 使用；task-free 工作在同一 PR 描述追加匿名来源摘要。可读原件沿用 `commit/path/blob/locator` 或真实公开锚点，先实际核对目标，再记录关系。原报告不存在公开锚点时保留未知；协调者摘要不冒充原报告，也不证明当时输入、机会或报告已固定。

以下只读命令仅是占位用法，日后对自然候选替换实际 commit 与仓库相对路径后使用；当前没有可执行的真实候选值。先核对提交，再定位该提交中的 blob，读取原内容并核对稳定 locator 的目标；本次读取或 hash 不证明观察入口前已固定。

```console
git show --no-patch --format=fuller <CANDIDATE_COMMIT>
git diff --name-only <BASELINE_COMMIT> <CANDIDATE_COMMIT> --
git ls-tree <CANDIDATE_COMMIT> -- <REPO_RELATIVE_PATH>
git show <CANDIDATE_COMMIT>:<REPO_RELATIVE_PATH>
```

候选与先前契约分别使用各自的固定提交；先前契约须核适用关系与入口前存在依据，不用候选中新改文字冒充旧契约。`ls-tree` 核对普通文件的 mode、blob 与路径，符号链接或子模块不按普通原件处理；提交显示的时间不独自证明输入固定或实际时序。

明确供给的 Git 文档引用可用[独立本地原件核对](review-detection-input.md#本地-git-原件核对)检查 commit、精确路径、普通 blob 和实际字节。它不解析 semantic locator，不核定自然变更范围、真实时序、独立真值或准入，PR 与未支持来源继续保留缺口。

不另存审核输入、capture、原聊天、身份、会话日志或 oracle，不新增结果库、采集器或 Schema。公开保存仍按[既有边界](effect-observations.md#保存与隐私边界)执行；本页模板只供原 PR／CLI 流程中的人工语义说明，不是新增必填接口，也不能把模板字段送入现有 v2 块或 CLI Schema。

## 核对入口事实，再声明机会与窗口

准备声明须在本次实际候选的首次非作者专项审核前发布到原 PR／CLI 位置。先固定候选 SHA 和 baseline，列出逐件原件与可重读定位、机会形成及排除规则、完整边界和预选顺序、允许材料、实际职责及已有预算来源；发布成功后回读同一原件，确认候选及声明，再派发审核。真实执行这个顺序可以补齐本次准备动作的证据，不能回溯认证旧报告。精确定位的有界接口见[定位合同](../superpowers/specs/review-detection-locators.md)。

分别记录发布、回读、派发与报告原件；PR 可变描述及 hash 不是历史固定的充分证据，报告完成时间也不是开始时间。派发原件或版本历史不可公开复核时，真实输入及先后时序继续 unknown，不为补证保存聊天副本。没有独立真值、预算端点等条件时仍不登记合格单位或设置窗口。

未来被测审核开始前，核对固定候选、先前契约、允许材料、实际提示暴露、职责来源、平台、原预算及入口／关闭依据。正常契约预期可以提供；答案、被测报告、根因、修复或后继结果的可见性分别核对。正式 context 中的验证摘要原样保留，不能删字段后称未提示审核。

被测审核与独立裁定分别使用新上下文和最小允许材料列表，避免继承含根因、报告、答案、修复或后继结果的完整聊天历史。这是减少提示的操作办法，不是未提示的充分证明；实际输入及暴露时序无法复核时仍为未知。

按[采用范围第 4 节](../superpowers/specs/review-detection-admission.md#4-相关组选择与不足处理)在结局揭示前形成机会列表、实例粒度、唯一定位和相关组依据。每组只取本窗口第一个预声明候选中，按契约引用／对象引用／缺陷类别排序的第一项。跨 TASK／PR 的同任务、候选／修复链、共同输入、共同缺陷来源和共享故障也须关联；排序键无法消歧就保持未知。选中项后来为负或未知，不换正例；每组一项本身不证明组间独立或条件可比。

以下是可复制的准备声明。所有尖括号均为未填写占位，`unknown` 是当前缺口；删除占位或填写引用不产生就绪结论。真实事实核对及实现、数据／方法／质量条件成立后，才在原流程明确 UTC 的 `T0` 与 `T1=T0+30 days`，入口为 `[T0,T1)`。采用日、准备提交日或模板粘贴日都不自动成为 `T0`。

```markdown
研究准备声明：template_only；不是观察入口或真实结果
适用包：review-detection-admission-v0.1
自然工作与载体：<原 TASK／PR 引用；尚无实际候选>
协议与实际候选：<协议版本引用>；<候选 commit/tree 与原件定位>
先前契约与适用关系：<固定版本、要求定位及适用依据>
受检对象与实例粒度：<对象定位、直接矛盾类别及唯一实例规则>
机会形成及排除规则：<审核前固定的规则与完整列表原件引用>
相关组及预选项：<关联原件与理由>；<第一候选、排序及第一项依据>
审核条件与允许输入：<首次阶段、平台及原输入引用>
实际提示暴露与时序：unknown；<可复核依据，未核定不声明未提示>
协调／审核／非作者裁定／匹配职责：<既有职责来源；当前未核定>
原预算：<原授权、适用规则及已有上限引用>；实际投入 unknown；剩余 unknown
入口、输入与机会固定依据：unknown；<原件及可复核时序>
完整报告范围与预算关闭规则：<原安排引用；当前未核定>
观察窗口：T0 unknown；T1 unknown；尚未启动
后续报告／裁定／匹配／关闭原件：unknown；尚无真实结局

```

复用[已有职责与预算](../superpowers/specs/2026-10-09-s1-contract-compatibility-and-review-budget.md#3-有界审核预算与职责合同候选)和自然工作自身的真实授权。数值上限、实际投入和剩余分别引用；未知不补零或无限。独立裁定未被原安排覆盖时，不据本模板增加一轮盲审、付费调用或补样本审核，先保留该缺口。已授权范围内的机械缺项由 Agent 补齐，不重复请求已采用的用途、精度或范围决定；真实来源、范围或风险变化才按现有规则集中交所有者。

## 逐项核对公开时序、裁定和预算端点

### 读取已有公开描述的编辑历史

原 PR 描述保留当前内容，但不能单独给出历史版本。需要核对历史公开文字时，可用已连接账户的 GitHub 原生 GraphQL 只读接口；先替换 `OWNER`、`REPOSITORY`、`PR_NUMBER`，不要把占位命令当成实际来源：

```console
gh api graphql -f 'query={repository(owner:"OWNER",name:"REPOSITORY"){pullRequest(number:PR_NUMBER){id createdAt lastEditedAt userContentEdits(first:100){totalCount pageInfo{hasNextPage endCursor} nodes{id createdAt editedAt deletedAt diff}}}}}'
```

在内存中按实际节点 `id` 定位，分别核对候选 SHA、声明或报告原文的可得内容以及 `editedAt`，原 PR 摘要只记节点定位、平台时间、核对关系和缺口。`diff` 的原生定义是此次编辑的变化摘要，不是完整旧正文或原报告副本；不得按字符串未出现推断内容从未存在，也不把 diff hash 当完整输入 hash。节点 `createdAt` 是对象创建时间，`editedAt` 是内容编辑时间，均不是宿主派发或实际开工时间。不要用任一字段替代另一字段。

检查 `pageInfo.hasNextPage`；若仍有下一页，在原安排范围内用 `after` 与实际 `endCursor` 继续只读查询。没有取得后续页、节点已删除、`diff` 为 null、权限失败或目标不明确时，保留具体缺口，不猜原文。即使本次返回全部页且 `deletedAt=null`，也不认证平台全历史无删除、每次调用原子或审核实际输入。不得为补公开事件请求外部人员审核、另发评论，或复制聊天／capture 建档。

该查询是人工来源核对用法，不改变现有工具：`pr_feedback.py` 的 capture 仍按其原接口供给，不混入 GraphQL 历史字段；`review_detection_input.py` 仍只检查声明；Git source 工具仍不读取 PR。历史节点可写进原 PR 引用的 `locator` 文字，但不是新增输入字段，也不能自动关闭 `VERIFY_PRIOR_DECLARATION`。

### 区分各端点的原件

| 端点 | 应实际核对的原件与关系 | 不足时保留 |
|---|---|---|
| 机会声明公开 | 固定候选／旧契约／完整机会边界的原位置；可得历史节点及内容编辑时间。 | 编辑摘要可得的窄事实；完整旧正文、历史完整性分别 unknown。 |
| 发布后回读 | 对同一来源版本及候选的实际回读依据。 | 本次读取时间不反证此前已固定，也不补派发。 |
| 派发与入口 | 宿主已有、可公开复核的派发／接收／开始原件，绑定候选、实际输入、职责与原预算。 | 公开派发计划、协调者“已派发”说明和报告完成时间均不代填 `entered_at`；缺宿主原件则 unknown。 |
| 完整报告固定 | 原 report ID／revision／公开定位、实际候选、声明覆盖范围及报告端点；失败、partial、timeout、取消分别保留。 | 单条命中、APPROVE、空原生集合或公开转贴不证明报告完整与实际完工。 |
| 独立裁定 | 事前职责及预算来源、非作者且非被测审核者、固定候选／旧契约／机会逐项理由、实际可见材料及裁定原件。 | 缺暴露或时序原件时，裁定报告可读不等于独立条件已认证。 |
| 语义匹配 | 裁定已固定的依据，同一候选、契约对象／机制及具体错误行为的对应理由。 | 同名 Finding、相似文字或后续通过不补匹配；负／争议／未知不换正例。 |
| 预算与结局关闭 | 原授权适用工作、所用预算维度和上限、已观察投入、完整报告范围、停止或关闭原件，彼此绑定。 | 审核结束、预算耗尽、PR 合并和观察结局关闭不是同一事实；缺事实不补未检出或零投入。 |

平台编辑历史可以补证某项声明／报告文字的公开时序；本地 `review_recorded` 只证明本地录入，不能当宿主审核开始事件。独立裁定和预算关闭各有自己的原件要求，不由前一端点的命中传递成立。

[宿主只读接入边界](../superpowers/specs/review-detection-host-evidence.md)固定了已核 CLI 协议能力、版本差异及所有者明确批准过的一轮读取范围；当前 `scope_decision=approved_once`、`read_state=closed`。该轮已结束，不形成重试或常设权限，不授权读取私密会话或启用遥测；实际派发、完整输入、独立性和货币端点仍未因此取得。

[后续最小接入候选](../superpowers/specs/review-detection-host-evidence.md#5-后续最小接入候选)单独保持 pending／not_started：先核真实通道、宿主绑定和必然返回范围，再形成含对象、次数／页数／字节上限及停止条件的一次授权。当前没有可执行宿主读取请求，不复用已关闭额度；派发、完整输入、独立性、时间与费用端点分别验原件，缺口不由候选获批关闭。

[单次握手候选](../superpowers/specs/review-detection-host-evidence.md#6-通道核定与单次握手授权候选)已固定请求内容、四个必需返回字段和拟议次数／字节／时限；实际 Desktop 端点、绑定、server 版本及接收前范围限制仍缺。CLI 版本与 proxy 帮助不补这些事实，当前不连接、不请求空白握手批准；握手也不继承后续任务读取许可。

[已核通道的选择与落实顺序](../superpowers/specs/review-detection-host-evidence.md#7-已核通道的选择与落实顺序)区分 App Server 协议、proxy、终端 UI、Code Mode 出站连接、设备配对及当前应用工具。静态核对已完成，实际接入保持未启动；先补既有入口的宿主绑定、版本、返回面与接收前限额，再形成具体一次范围，不通过启动新 server、读取配置或探测 socket 补缺。

### 先核职责覆盖，再取得独立裁定

新自然任务若已有授权与原安排明确涵盖独立裁定，在首次被测审核前就把专项审核、非作者事实裁定及后续匹配的职责、允许材料和停止范围分别固定到原位置；不能在看到 Finding 后把未覆盖的一轮改名为“初始批次”或“残余复核”。通用的一批初始专项审核及一次受影响残余复核，不自动提供额外独立裁定职责或预算。

固定被测原报告后，向裁定者只供原先固定的候选、旧契约和完整机会规则，不把被测报告、作者处置、根因、修复、匹配或后继结果放入允许材料。由裁定者逐对象给出可检验预期、适用关系、候选实际行为、冲突及影响依据，分别保留正、负、争议或未知；不能从零 Finding 或 APPROVE 推出负真值。裁定原件固定后，才向匹配者提供两份原件。新上下文和材料清单只是减少暴露的操作措施，实际输入与未提示充分性仍须原件；没有原件就不认证独立性。

### 在原位置关闭预算关系

原 PR／CLI 的关闭摘要可沿用以下人工说明，不增加 strict Schema 或 v2 字段：原授权与适用工作引用；各职责及允许范围；采用的预算维度／单位和上限原件；各阶段已观察投入与失败原值；完整报告及裁定／匹配定位；实际停止／关闭来源；剩余事实与具体缺口。

若原安排只有审核批次或受影响范围限制，就只描述该限制及实际取得的阶段结果，不换算为时间或费用。各适用维度的已用与剩余只有来源可比时才计算；未知数值不填零或无限。测试的 timeout、CI 用时、报告公开时间和 PR 合并时间都不能转作审核预算或实际耗用。原安排未覆盖的职责或动作先保留缺口，不由摘要追授，不复活已消费动作。

以上逐端点核对只补实际可得的来源。未满足来源、独立性、预算及方法／质量条件时仍不登记合格单位，不设置 `T0/T1`；已审核候选不追溯进入未来窗口。

## 固定报告后独立裁定，再匹配与关闭

被测报告及其实际候选、完整报告范围和预算端点先固定。由既有安排覆盖、非候选作者且非被测报告作者的裁定者，在未读取被测报告的条件下，按固定候选、契约和机会规则裁定；其职责、实际可见材料与时序须有可复核依据。不同 Agent 或一句“未读”声明不代替这些事实。修复后的受影响残余复核不能冒充首次独立裁定。固定裁定依据和争议后，才对照被测报告匹配；无需建立私密存储或提前公开答案。

正真值须有可检验预期、候选专属冲突及归因、适用关系和可处置影响；负与未知分别保留。匹配须同一实际候选、契约违约对象／机制和足够具体的错误行为，并引用理由与原件。重复 Finding 不增加机会；范围外新发现保留为后续反馈，不能倒填本轮列表。争议只在原预算内作受影响残余复核，保留双方依据，未闭合为未知。

仅在 `T1` 前实际关闭、独立正真值及预算内正确报告均有依据时，才支持预算内检出；未检出还须完整报告范围、明确入口、预算及关闭端点。取消、timeout、partial、工具／权限失败或未关闭保留原值，不能由“未见 Finding”补零；首次审核、受提示复核和修复后审核分别保留，不用后来通过覆盖原结果。

## 关闭后回读原值，条件满足才推进评分

正式账本回读使用[固定 Git 工具](review-feedback.md)的既有 `repository`／`--task` 接口，读取所选仓库固定 `HEAD` 的白名单原件；`--task` 仅过滤输出，不缩小底层读取与校验范围，也不接收 stdin 来源包。Task-free 回读使用[公开 PR 工具](pr-feedback.md)，才按其原接口在内存中组织 capture 并经标准输入读取，不落盘新增副本。

原报告、裁定和匹配依据继续引用原位置，公开 PR 只追加脱敏关系摘要。`matched_reported` 核对声明关联，不认证语义匹配、真值或实际修复；hash、APPROVE、resolved、CI 通过和填写完整均不证明真实观察就绪。

| 后续阶段 | 需要核对的真实事实 | 不足时的处理 |
|---|---|---|
| 观察入口 | 实现及数据／方法／质量条件、实际候选与来源、固定输入和机会、职责／预算、明确 UTC 窗口均成立。 | 保留准备声明与缺口，不设置 `T0` 或先行观察。 |
| 结局关闭 | 独立裁定及其信息条件、同候选语义匹配、完整报告与预算端点可复核，且在 `T1` 前关闭。 | 原值和冲突继续保留；不补检出、未检出或正真值。 |
| 真实分析与评分接入 | 机会选择、正真值、相关性、条件可比性、提示、缺失及方法适用性均能支持本窗口声明，并有相应真实输入实现与质量验证。 | 有影响主声明的未知即停止主比例／区间，只回读原值与缺口；不把真实计数标成 synthetic。 |

窗口结束后只作一次计划分析；不因精度不足延长窗口、重试、换机会或凑满 104。95% 覆盖／20 个百分点总宽和条件规划 104 沿用协议，不是样本配额或检出率阈值。[记录级合成分析](review-detection-analysis.md)已提供记录结构、预选后的必要条件、整批不足回退及数学调用的离线实现与演练；它只接受 synthetic，不替代真实来源与方法核定。真实条件成立仍须另核对应输入启用与实现准入，当前工具不会自动切换；模型评分更新、3-A 真实评分／shadow 与 Phase 3 不由本页准备完成。

[合成反馈演练](review-feedback-simulation.md)已补充完整评分快照重算、分开的拟合／留出校准诊断及模拟路由。其虚构时序、组隔离和显式阈值只验证离线逻辑，不选择真实校准方法、生产参数或审核安排，也不将本研究的一次分析改为滚动更新。真实条件仍按上表逐项核定。

最小反例：选中机会裁负后换成已检出正例，破坏预选规则；仅有可变 PR 摘要及 hash，不能证明审核前固定；裁定者已读 Finding 后与报告一致，不能补独立真值；窗口内入口但 `T1` 时未关闭，不能算未检出。上述情况均保留原件及未知，继续不依赖它们的已授权准备。
