## 3. 依赖与并行安排

主链：**P0 现场和基线 → P1 成本定位 → P2 入口修复 → P3 失败与重复工作修复 → P4 条件代码减法 → P5 验收和收口。**

P3与P4均以证据为前提：P1未发现值得修复的问题时，记录理由后跳过P3/P4；不把无必要的代码变更变为P5的强制前置。P1完成后，P2文档工作与P3只读诊断可并行；P3实现必须等候选、边界和红例明确。每次只让一个治理变更进入正式完整验证。

| 角色 | 归属 | 并行限制 |
|---|---|---|
| 整合负责人 | 方向、基线、范围、当前状态、串行集成和最终结论。 | 唯一集成写入者；不得由多个agent同时改同一主工作树或冻结根。 |
| 实现/诊断负责人 | 一个清楚的故障边界及其必要回归。 | 在任务自有工作树；实现和必要测试通常由同一人负责，避免来回移交。 |
| 独立审核者/验证者 | 按当前项目要求保持独立，检查变更和实际证据。 | 不把自审当独审；同资源域重型验证/安装/整树扫描不叠加。角色独立性以实际契约为准。 |

默认最多3个并行角色，受实际宿主上限约束；不是新增固定团队或代理层级。阶段内若只有一个强耦合步骤，直接串行。共享环境与资源的完整执行只能有一个明确归属。

## 4. 分阶段工作包

### P0：保全、定界和选择基线

**输入：** 用户新的治理启动指令、届时有效AGENTS/Policy、当前Git/worktree状态、已有交付与停止记录。

**工作：**

1. 只读核对HEAD、暂存/未暂存/未跟踪状态、活跃任务与写入者；记录WIP路径和内容校验值，留在既有任务记录或获准的私有证据位置，不复制到公开docs。
2. 用一张短表区分：主根WIP、当前维护基线、已验收候选、停止的消费候选、历史证据。每行只含版本、用途、所有者、可用结论、禁止推断。
3. 明确本轮只修复仓库的边界，确认继续暂停的工作线。根据实际差异选一个有授权的干净工作树，不从旧整文件覆盖已交付代码。
4. 按现有AGENTS升级清单路由：安全文档/测试与治理面修改分开；src/aiflow、CI、Policy/schema等仍走所需AI Flow。治理任务获准后可使用其自己的流程，不得借此推进旧接入任务。

**交付/验收：** 一个确定维护基线、一个写入者、完整WIP保全清单、清楚的暂停范围。无法区分版本或已有其他写入者时，停止写入，继续只读分析。

**回退：** 此阶段只读；不改变旧根或执行状态。

### P1：用最多3个样本定位成本

**依赖：** P0。此阶段先取现有证据，不重跑旧任务。

**工作：**

- 样本优先选择：一个安全小改、一个治理面小修、一个真实失败恢复。已有单行权限修复和Stage B停止记录可作历史参照，但不是重放授权。
- 分开统计读取/搜索、材料准备、实现、审核、完整测试、等待和失败恢复。记重复打开文件数、无失效理由的重复步骤及默认读取字符数；可取得的实际token单列。
- 给每项重复一个原因：必要的新输入、真实失效、历史/当前混淆、工具重复执行、缺少可读诊断，或未知。不要把正常安全检查统称为浪费。
- 只选成本和证据最明确的一项进入P3。没有可证实重复时，停在入口治理，不为“彻底治理”硬造重构。

**交付/验收：** 现有任务/PR里一张成本表，至多3个优先问题；每项有来源、影响、最小修复和不做的内容。没有token基线就写“未测”，不推算节省金额。

**回退：** 只读复盘，保留来源；不建立自动采集器、计时服务或新评分系统。

### P2：压缩当前入口，保持历史可发现

**依赖：** P1；可与P3只读诊断并行。

**范围：** README、当前维护状态、现有接入计划和历史索引中与本轮相关的部分。不修改授权正文，不另立规则权威。

**工作：**

1. 当前入口只保留“现有能力、接受版本、当前阻塞、下一步是否获准、证据导航”。逐窗口过程移出默认阅读路径，优先引用既有账本/PR和Git固定版本，不复制一套新历史。
2. 保留原历史可检索性。账本/证据不重写不删除；如果文档移档涉及既有记录要求，先按现行规则审核，不能把“压缩入口”当作删除许可。
3. 明确旧“先完成接入再瘦身”仅为历史方向；本轮治理优先，Stage B停止不变。旧NEW/BLOCKED不自动变成待执行队列。
4. 规则表只保留在原权威处，入口提供链接；按相关任务读取必要章节，不强制全量读取所有计划、审核包和历史。

**量化验收：**

- 以P1同一任务默认阅读集合为基线，目标字符数减少至少50%；若达不到，说明必须保留的决策信息，而非删安全边界。
- 两次独立查找能在现有入口找到：当前候选、停止原因、有效规则、WIP归属、下一步缺项。每次最多经过2个导航跳转是建议目标，不用增加新索引体系凑指标。
- 原历史引用仍能定位，历史失败和UNKNOWN没有变成PASS；没有新的日期流水账。

**回退：** 文档调整保持小而独立，普通反向补丁/经授权revert恢复导航；不回写旧账本。

### P3：修复一个已证实的失败或重复边界

**依赖：** P0/P1、明确的实施基线与授权；P2不应阻塞独立诊断。

**优先选择：** 能解释多次昂贵失败的准备问题、晚发现材料错误、同输入重复构造/读取或没有可操作诊断的失败。原Stage B probe5根因仍UNKNOWN，本计划不批准再次探针；只使用可合法读取的既有材料，无法定位即报告精确缺口。

**实施顺序：**

1. 从原失败证据形成一个具体假设。先确认哪个函数/输入/操作出错，区分产品缺陷、fixture准备错误、环境问题与未知。
2. 在获准范围内增加最小可重复的反例与合法正例，不创建外部动作、真实付费调用或新旧任务重演。
3. 若能便宜检测，接入已有准备边界并复用正式检查判定；保留完整门禁，不建立第二套预检合同。
4. 失败诊断只包含安全的错误类别、失败操作和可回溯证据指针；失败材料保留必须遵循其实际访问/传输许可，不能默认私有CI可收任何原件。
5. 在合同明确允许的范围内复用输入未变、仍适用的证据；若改动绑定范围或失效规则，先单列契约变更及风险供审议，不能混入“性能优化”。

**验收：** 原红例先红后绿；合法/篡改/过期/越界/清理未知路径按原边界处理；所选已知错误在昂贵完整轮之前被明确识别；同有效输入无理由重复次数为0；适用完整测试、覆盖率和独审通过。

**停止：** 新证据不足、恢复范围扩大、费用/资源/权限越界，或需接受未解决风险时，暂停受影响动作。已授权且有诊断的修复按现行规则继续，不因固定轮数强行问“是否继续”。

**回退：** 一次一个边界；代码反向补丁或经授权revert，保留所有失败与已消费动作状态。代码回退不退款、不重置次数、不恢复旧批准。

### P4：有证据才做代码减法

**依赖：** P3完成，或P1已经独立证明某处代码重复值得单独修复。一次只选以下一个边界，不做全仓模块拆分。

| 候选 | 先验证什么 | 可接受的最小变化 | 必须保持 |
|---|---|---|---|
| status与gate事实计算 | 两者是否对同一输入重复作相同判定，是否存在真实不一致或耗时。 | 展示层复用既有纯结果；语义不同则不合并。 | 只读性、Missing/stale/错误语义；扩展已有gate parity回归。 |
| 验证产物采集与回放 | 现有一次记录/同产物消费是否被调用方重复绕行，绑定为何失效。 | 删除一次重复调用或复用已有产物。 | 版本/身份/用途适用性；不新增缓存服务，不缓存失效批准。 |
| mutation职责 | 当前交付基线与旧WIP各自有哪些真实消费者、故障和共同变化。 | 调整一个明确边界或去除真重复，保留直接实现。 | 单次消费/锁定/再校验、落盘完整性、主树快照和原件历史。 |
| 无消费者工具/分支 | 调用、CLI入口、安装包、外部使用合同与历史恢复路径。 | 证据充分且获准后退役一个未接线实现。 | 不以本仓零引用推断外部无人使用；不删除用户数据/恢复材料。 |

**拒绝的方案：** 为压行数拆成大量文件；合并不同安全契约的runner；新增factory/registry/DSL/数据库；将所有流程抽象成统一执行平台；为未来宿主/模型提供未经要求的扩展点。

**验收：** 公有CLI、错误码、序列化字节和必要schema兼容；改动边界回归及适用完整验证通过；新旧路径不长期双写；没有真实收益则记录“不实施”。

**回退：** 保持兼容的小批次；必要迁移先获批准并验证可逆性，不改写历史证据或已发布提交。

### P5：用自然任务验证并关闭治理

**依赖：** P2交付，P3/P4完成或基于证据明确跳过。

1. 比较最多3个获准自然任务与P1样本的类型/风险/检查范围。未发生可比任务时，只交付已验证修复与未测效果，不人为制造工作。
2. 目标：同输入无理由重复为0；默认阅读字符目标降50%；可比小任务主动处理时间建议降30%；新后台服务/数据库/DSL/新账本为0。目标不是质量豁免，实际结果不足时如实报告。
3. 保留必要阶段耗时，区分等待与主动处理。少量样本不推断长期稳定节省，不将部署/加载/使用等同于效果改善。
4. 收口说明只列：实际差异、真实通过检查、未跑/失败检查、实测收益、保留WIP、回退入口和后置项。
5. 完成后停止新增治理机制。用户另行决定是否恢复Stage B、旧mutation任务或其他能力；不得凭本计划自动开启。

**出口：** 能清楚说出消除了哪项重复，或为何没有值得实施的修复；说明入口收益、保留的保护、适用质量检查和仍未测的效果。有未解决风险则写精确阻塞，不以百分比包装完成。

## 6. 风险、保护与回退

| 风险 | 保护措施 | 触发后的处理 |
|---|---|---|
| 旧WIP被整文件覆盖 | P0路径/哈希基线，任务自有工作树，唯一集成者。 | 停止相关写入，比较实际差异；只恢复本任务确知的改动，不reset用户树。 |
| 导航精简丢失有效约束 | 引用原权威，历史映射与独立查找验收。 | 恢复导航，不复制更多规则层。 |
| 复用失效证据 | 明确输入、版本、环境、用途与失效条件，沿用现有判定。 | 保留失败；重验需实际授权，不换task洗掉额度。 |
| 简化破坏安全边界 | 先有拒绝路径回归，再改实现；独审关注消费/锁定/身份/清理。 | 不交付或回退代码；不降低发现严重度。 |
| 失败材料泄露私有信息 | 最小脱敏诊断，原件留获准位置，发布前审接收范围。 | 停止传输并报告具体范围，不扩大日志收集。 |
| 治理再次变成新项目 | 每批一个问题、每项替代对象、明确停止；无新框架/新账本。 | 删除未实施的扩展设想，保留必要修复；不把所有候选做完才收工。 |

本轮不需要破坏性清理。磁盘占用、旧工作树、失败原件和archive refs的处理另列建议即可；没有精确清单、恢复证据和授权，不执行删除。回退只撤销本轮实现，不改历史事实、额度、审批或原件归属。

## 7. 工作量与重新估计点

以下是规划预算，不是承诺日期；“工作日”为合计主动工程工作量，不等于日历耗时。未经P0确认的CI、审核、用户决定和资源等待另计。

| 阶段 | 初步预算 | 重估条件 |
|---|---:|---|
| P0 | 0.5工作日 | 版本或WIP归属不清时先报告，不无限盘点。 |
| P1 | 0.5–1工作日 | 至多3样本；证据不足时停止扩大采集。 |

| P3 | 1–2工作日/一个已定位问题 | 根因UNKNOWN、涉及契约/权限变化则重估，不计为已知修复。 |
| P4 | 0–2工作日/一个边界 | 允许跳过；证据不足不实施。 |
| P5 | 0.5–1工作日整理，另等自然任务 | 不为完成效果统计启动无关任务。 |

总主动工作量粗估3–7.5工作日，另加适用正式验证和外部等待；不是可靠完工ETA。P0/P1后先重估P3/P4，再承诺具体批次。不同候选的历史58.3分钟Native和16.3分钟record+verify仅作成本参照，不能相加成新任务保证时长。
