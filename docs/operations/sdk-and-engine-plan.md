# 应用自管 SDK 与完整引擎跨仓初始化方案

本文记录两条路线的范围、前置条件、风险和验收要求。
[应用自管 SDK 单次只读审核](../superpowers/specs/sdk-readonly-review.md)已由 [PR #109](https://github.com/MaginaLW/harness-model/pull/109) 交付，并完成一次真实工程审核与 PR 反馈回读；
完整引擎跨仓初始化尚未交付。当前状态以[维护收尾与待办](maintenance-status.md)为准；
真实统计评分、自动审核安排及现有 Desktop 附着继续暂停，`T0/T1` 不因本文设置。

## 两条路线的关系

| 路线 | 目标与交付 | 不由本路线证明的事项 |
|---|---|---|
| 应用自管 SDK 客户端 | 应用自行创建、管理和记录未来的新调用，返回结构化结果及生命周期回执。 | 现有 Desktop 会话来源、旧审核身份、独立真值、自然样本充分性或执行授权。 |
| 完整引擎跨仓初始化 | 在确需完整引擎的目标仓安装自己的资源、建立身份并适配治理与 CI。 | 模型已接入、真实评价已准入、目标保护已生效或可信执行器已具备。 |

两者互不构成前置依赖：SDK 客户端不必先完成跨仓初始化，完整引擎也可以不调用模型。
它们均不能替代[维护方通道资料与自然任务原件](maintenance-status.md#剩余缺口与推进条件)。
现有 Desktop 只读问题保留在 [Codex issue #55904](https://github.com/openai/codex/issues/55904)；
另建应用自有运行时不关闭该问题，也不继承已关闭的一次有界读取授权。

## 应用自管 SDK 客户端

### 最小范围与实现步骤

首版已交付薄 Python 客户端，只支持“手动提交固定输入 → 单次处理 → 返回结构化结果”。
首个用途为本仓固定文档契约候选的只读专项审核，模拟验证和一次有界真实工程验收均已完成；真实报告与反馈记录见该 PR。这不是统计观察或整个实现的模型审核。
不启用自动审核安排、真实评分、Git 写入、后台常驻或自动恢复。这里的客户端指 Codex SDK，
不扩展为通用 provider 路由平台。

1. **固定用途及合同。** 选择一个实际用途和目标候选，定义允许输入、预期输出、失败条件、
   完成条件及权限范围。明确是否只返回建议，以及哪些事实仍只能标为 `unknown`。
2. **核验 SDK 能力。** 官方已有 Python Codex SDK，可控制本地 app-server；本次固定
   Python SDK／运行时 `0.163.0`，复用现有 Windows 与 Codex 登录。将所需接口、权限、
   事件、取消和限制能力逐项映射到实际版本。协议有能力不等于 SDK 已暴露相同能力；
   无法满足必需限制时停止或收窄合同，不默默换通道。
3. **管理自有生命周期。** 首版由应用启动私有 stdio 运行时，只管理自己创建的线程，
   不发现、附着、停止或改写 Desktop 会话。记录应用与运行时版本、仓库身份、候选提交、
   输入摘要、职责、线程和 turn ID，以及开始、完成、失败、取消请求和确认停止。
4. **约束输入、权限与预算。** 明确允许发送的文件、正文、指令、配置和工具输出，以及已知
   不可见上下文；凭据留在用户控制的认证环境。推理所需通信与工具网络访问分开定义，
   初版不开放用途不需要的文件写入、任意 shell、网络工具或高风险动作。
5. **先离线验收，再单独决定真实调用。** 启用检查须早于 SDK 客户端构造和子进程创建。
   第一阶段只用模拟运行时；以后按具体用途、数据、权限、时间和费用决定是否进行一次
   有界真实验收。当前仅推进新合同中的自有运行时；现有 Desktop 的附着与读取继续暂停。

上述 SDK 与 stdio 能力依据[官方 SDK 文档](https://learn.chatgpt.com/docs/codex-sdk)和
[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。其余约束是本路线的拟议设计，
不是官方平台已经替应用强制执行的保证；升级前须重新核验所选版本。

### 启动前材料

| 材料 | 需要明确的内容 |
|---|---|
| 首个用途与目标 | 实际用途、目标仓或固定材料、候选版本、预期输出及验收人。 |
| 数据清单 | 允许发送的范围、禁止材料、可见与不可见上下文、本地和服务端保存要求、保留期及删除办法。 |
| 权限清单 | 读写路径、工具、网络和真实动作边界；不需要的能力关闭。 |
| 认证及环境 | 用户选择的认证方式、运行位置、版本兼容要求和凭据管理方式，不提供或入库密钥正文。 |
| 完整预算 | 时间、调用及重试次数、金额和币种、计费及实费来源；包含工具、子代理、失败和取消后的费用。 |
| 异常处置 | 取消未确认、断线、结果未知、重复请求和崩溃后的核对、停止及恢复办法。 |

这些材料是未来启动输入，不是要求现在提供空白调用许可。没有可靠来源的实际模型、费用和
结果继续为 `unknown`；请求模型与实际返回元数据分开记录，新线程不直接证明独立性。

### 风险与验收

| 风险 | 处理方案与必须验证的行为 |
|---|---|
| 自有线程被误当作 Desktop 来源或独立裁定 | 回执明确来源及缺失项；不能追认旧审核、独立真值或自然任务。沿用[模型元数据边界](model-selection.md)。 |
| 输入越界或隐式配置带入材料 | 固定发送清单和摘要，核对运行时配置与工具范围；未覆盖上下文保留未知，秘密不进入日志。 |
| 只读预设被当作完整隔离 | 分别验证文件、工具、网络和执行能力。文件系统只读不证明零调用、零费用、无状态保存或完整沙箱。 |
| 超时、断线或取消后仍继续执行 | 取消请求与确认停止分开；没有最终回执时记录结果未知，先核对原调用，不自动重发。 |
| token 用量被当作实费或强制金额上限 | 区分用量、估算、已结算费用与未知；核验哪些上限真正可执行，不把本地超时当服务端停机证明。 |
| 返回结果被当作执行批准 | 结果只作为材料返回；模型文本、Gate PASS 和本地 actor 字符串不产生可信执行授权，见[Hooks](hooks.md#what-the-high-risk-action-approval-requirement-is-actually-worth)。 |
| 未启用时仍启动或恢复运行时 | 模拟测试证明构造前检查有效；无自动重试、后台常驻或借旧授权恢复连接。 |

离线退出条件：固定输入输出及来源合同通过独立审核；用模拟事件覆盖输入越界、身份缺失、
超预算、超时、断线、取消未确认、重复请求及崩溃恢复；缺最终回执不报告成功，结果不自动授权。
离线通过不替代真实调用准入，也不自动打开真实评分或审核策略接入。

本次单次审核采用普通只读预设与拒绝批准，读取范围不声明为仅输入目录。root-deny、目录外拒读探针及由此引出的 Linux 环境不是首版验收要求；不为它们安装环境或修改系统权限。具体命令、回执和反馈方式见[单次审核合同](../superpowers/specs/sdk-readonly-review.md#使用)。

## 完整引擎跨仓初始化

### 当前能力与真实缺口

完整克隆内的根目录、子目录、linked worktree 定位及仓库级 Schema 作用域已经具备；
TASK-0083 已交付显式风险事实 `facts` CLI，不再作为缺口。资源包候选是否可用以实际源码
和所装 wheel 为准；初始化、目标 Policy 采用、新仓身份及目标验证和 CI 适配仍未交付，
见[接入边界](adoption.md#完整引擎的跨仓库边界)。
项目所有者已选择 agent-bridge 为完整引擎目标；目标选择不代表接入、目标验证或 V2 已交付。

目标 CI 适配涉及核心验证代码，不只是修改 YAML：当前[验证器](../../src/aiflow/verification.py)
约束了本仓覆盖率源 `aiflow`、`tools/analysis`、`tools/ci/check_coverage.py`、部分阈值与
命令白名单。只复制 `.ai` 不能让完整验证在外仓成立，也不能承诺支持任意语言和 CI。

### 资源包候选的读取与构建

以下候选用法依赖对应源码纳入实际构建，不表示发行、目标接入或完整引擎验收已完成。
候选从本仓 `.ai` 固定清单构建 20 项资源：15 个 Schema、四份待目标审阅的 Policy 种子和一份
规格模板。普通 wheel 将资源与 `manifest.json` 放入 `aiflow/_bundled_resources`；源码包携带
构建所需的原始资源，可再构建普通 wheel。资源使用 UTF-8 和 LF 规范字节；构建将 CRLF 转为 LF，
拒绝裸 CR 和无效 UTF-8，不修改源文件。

从安装了该普通 wheel 的环境，可用以下入口读取完整资源包：

```python
from importlib.resources import files
from aiflow.resource_bundle import read_bundle

manifest, resources = read_bundle(files("aiflow").joinpath("_bundled_resources"))
```

`resources` 的键为包内相对路径，值为字节。读取会核对固定清单、版本、文件长度和 SHA-256；
缺项、多余项、内容不符或不兼容时拒绝。manifest 上限为 64 KiB，单项资源上限为 1 MiB，资源总量
上限为 4 MiB。摘要检查包内一致性，不认证发行者。可编辑安装不提供 wheel 内的资源目录；
需验证分发内容时应使用普通 wheel。运行时仍从目标仓自己的 `.ai` 读取 Schema 和 Policy，
包升级不会自动替换目标文件；Policy 种子须按目标规则单独审阅并决定是否采用。

在可信源码和已准备构建依赖的环境中，使用新建空输出目录构建；下面的路径是占位符：

```powershell
python -m build --no-isolation --wheel --outdir "<EMPTY_WHEEL_OUTPUT>"
python -m build --no-isolation --sdist --outdir "<EMPTY_SDIST_OUTPUT>"
```

构建后端对其负责的资源、源码和部分输出路径检查链接、冲突及现存内容，但这些检查不证明
检查与使用之间没有竞态，也不约束所有前端的最终输出行为。源码、工具链与输出位置须可信；
重试时使用另一个新输出目录，不覆盖或清理来源不明的材料。

### 最小分阶段交付

| 阶段 | 具体范围 | 退出条件 |
|---|---|---|
| 0．确定目标 | 已选择 agent-bridge；核对其完整任务、审核、验证和 Gate 的需求及当前规则。首版建议要求已有 Git 提交且没有 `.ai`。 | 目标、负责方、基线、原规则及质量要求明确；不为假设的其他目标建设通用安装框架。 |
| 1．版本化资源 | 分发允许使用的 Schema、模板、待审核 Policy 种子和必要验证工具；保持单一资源源头，清单绑定 CLI 兼容范围、资源版本、Policy 版本及文件哈希。 | 构建后的 wheel 在源码树外可读取全部必需资源；不包含历史、本机状态或秘密。 |
| 2．非覆盖计划与应用 | 拟议入口分只读计划和显式应用；计划展示 Git 根、HEAD、写入清单、差异、冲突、拟建身份及原文件哈希，应用前重核。已有 `.ai` 首版整体拒绝自动拼接。 | 预览零写入；冲突或基线变化零覆盖；重复应用能识别已完成，恢复不重复生成身份。 |
| 3．指令与验证适配 | AGENTS 仅生成精确补丁供审核，与资源安装分开。为首个目标设计受约束验证配置，固定参数、检查类别、解析器、源码范围、阈值、超时、环境和输出路径。 | 配置版本及摘要绑定任务与验证证据；保留目标原规则和本仓质量门，不开放任意 shell。 |
| 4．外仓端到端验收 | 先在可丢弃 Git 仓完成 wheel 安装、任务创建、facts、分类、规格、受控审核、验证和 Gate，再审阅真实目标应用计划。 | 不借用父仓或 harness-model 克隆资源；本地与 CI 检查同一候选并覆盖真实目标源码。 |
| 5．更新与恢复 | 首版可只检查更新并生成迁移计划；对比原安装版本、目标现文件与新版，不自动迁移历史。 | 包升级不暗改目标资源；修改过的配置、任务、批准、事件和证据保持可读、可追溯。 |

阶段表中的初始化入口尚不存在，不是当前可执行命令。目标仓身份应生成自己的规范 UUIDv4，
重试保持同一身份；另需明确克隆与 worktree 的身份和资源规则，不能根据相同 remote URL
就猜测属于同一授权范围。运行时继续读取目标仓已安装资源，不随包升级静默切换 Schema。

资源、初始化、目标 V0/V1 验证、V2 证据和真实目标应用应分别形成可审核、可验收的结果；
每个切片实施前核对必要输入及验证路径，输出证据在对应验收前齐备。V2 的缺失条件只阻塞
依赖它的步骤，不阻止独立的 V0/V1 工作，也不放行 V2 或完整接入验收。目标仓规则允许时，
可并行用自然发生的低风险任务评估[轻量接入](adoption.md)；不为试点制造任务，也不将其
结果当作完整引擎或 V2 验收。

资源包排除本仓身份、历史 task、批准、证据、维护模式标记和常设授权。目标治理模式与权限
由目标规则决定，不自动继承本仓维护模式或授权。required checks 与分支保护的变更不由初始化
自动执行，仍按目标仓和所有者的具体决定处理。

多文件中断需要单独设计：可先完整暂存新 `.ai`，再受控落位，并保留可识别的未完成状态。
现有[存储实现](../../src/aiflow/storage.py)的单文件原子写入不等于整套初始化的事务保障。
AGENTS 和 CI 补丁独立审核；未知文件保留，不递归清理目标目录。

### 风险与验收

| 风险 | 处理方案与必须验证的行为 |
|---|---|
| 覆盖原配置或指令 | 已有 `.ai`、AGENTS、大小写冲突和未知文件均保留；冲突时不应用，指令与 CI 差异单独审核。 |
| 根目录、路径或 worktree 混淆 | 覆盖根/子目录/linked worktree；拒绝嵌套仓越界、路径穿越、符号链接或 junction 越界。 |
| 身份与历史串仓 | 新身份不同于源仓；不导入源仓 task、批准、证据、维护标记或授权。 |
| 缺资源或版本混用 | 缺文件、损坏、哈希或兼容版本不符在写入前失败；包升级不暗改已安装资源。 |
| CI 通过但未检查目标源码 | 使用目标自己的验证合同和源码范围；验证失败路径、结果解析及本地/CI 一致性，保留原有 required checks。 |
| 中断及并发覆盖 | 故障注入后能识别未完成状态；重核基线和文件哈希，不覆盖后来修改，不重复建立身份。 |
| 更新或卸载误删历史 | 修改过或非安装器拥有的文件不删除；历史事件、批准和证据字节保留，不能删除 `.ai` 重新初始化来回滚。 |

卸载 Python 包只移除环境中的程序，不删除目标仓 `.ai`。尚未产生历史时，恢复也只能按清单
处理安装器新建且未变化的资源；已有历史后通过正常 Git 提交恢复配置，并核对旧程序与
现有资源及历史的兼容性。实际删除仍须遵守目标规则和具体授权，本文不提供删除许可。

## 后续依赖与项目流程

SDK 单次只读客户端已交付，后续按实际文档需求维护和显式调用；不重复首轮工程验收，
也不因已有回执自动安排新审核。完整引擎跨仓初始化已选择目标，尚未交付。
新用途或目标准备先固定共享合同和边界，再按实际独立性安排准备：

| 路线 | 可并行的独立准备 |
|---|---|
| SDK 新用途或版本变化 | 核对与已交付合同的差异、实际 SDK 能力与版本；仅补受影响的数据/生命周期/预算及治理验证映射。 |
| 跨仓初始化 | 资源分发；初始化及故障恢复；目标治理与 CI 映射。 |

并行准备后，串行完成候选整合、独立审核和正式验证；真实调用或真实目标应用再核具体范围
与授权。涉及 `src/aiflow/**`、`.ai/**`、打包配置、`tools/ci/**` 或 CI 的实现按
