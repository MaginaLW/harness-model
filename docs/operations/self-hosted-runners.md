# 自托管执行基础设施

本模块保留 GitHub Actions 的触发、队列、日志与 Checks，只为已核定的可信私有工作负载
提供可复查的运行环境、运维检查和执行回执。公开仓库的标准托管 CI 保持原行为；本仓
没有把公开 PR 路由到个人电脑，也没有新增调度守护进程或收费 fallback。

当前实施范围和未完成验收见[任务 02 执行记录](../superpowers/plans/2026-09-13-runner-infrastructure-execution.md)。
运维工具入口见[盘点与健康检查](runner-health-checks.md)，数据接口见[执行回执](runner-receipts.md)。
盘点使用私有机器配置，回执使用可移植的冻结执行要求；两者是独立契约，不能直接互传。
运行观察须经过来源与版本核对后另建回执，不能把盘点输出或示例配置充作执行证明。
历史[首次盘点](self-hosted-runner-inventory-2026-09-12.md)和
[后续准备](follow-up-preparation-2026-09-13.md)保留各自观察时点，不升级为本轮运行证明。

## 接入决定

| 工作负载 | 执行位置及条件 |
| --- | --- |
| 公开或不可信 PR | 标准 GitHub-hosted 或另行核定的隔离设施；不接个人日常主机 |
| 已登记可信私有 Windows job | repository-level Windows 实例，独立低权限身份和工作目录 |
| 同一私有目标的 Linux/POSIX 检查 | 真正 Linux guest 中的独立实例；保留原 shell、依赖和必要检查 |
| 第二个仓库 | 独立注册或已核定的组织授权；不能复用第一个仓库的注册声明 |
| 模型、训练、专业软件或自动 Agent 执行 | 各自核定接口、许可、费用和阶段准入，不从 runner 能力推导 |

注册 scope 控制可接入仓库，labels 只选择执行环境。单 workflow 的 concurrency 不提供
整机互斥；首批采用每台机器最多一个接单实例的受控窗口。新增 Linux guest 可以进行
尚未注册的环境准备，但成为接单实例前必须核对另一实例是否空闲及暂停接单。

## 安装与重复执行

真实实例的路径、账号、服务名称、repository ID 和凭据引用保存在树外私有配置中。
公开示例只包含逻辑身份，不能把示例 profile 当成实际主机事实。不得将 `.runner`、
credential 文件、token、私钥、个人登录态、下载包或工作目录提交到本仓。

安装前先执行只读盘点，再与预期实例核对：

| 观察 | 下一动作 |
| --- | --- |
| 配置、注册和服务已匹配 | 保留现有实例，检查健康；不重新注册或覆盖凭据 |
| 没有安装且相关目录确实可读取 | 按核定的官方安装流程准备独立目录、身份、工具和版本校验 |
| 路径访问被拒绝或状态未知 | 保留 unknown；不能把 `Test-Path=false` 当成未安装而覆盖 |
| 名称、scope、账号、版本或目录冲突 | 保存差异，先解决冲突；不静默迁移或扩大 ACL |
| 已在接单或存在 Worker | 不升级、不切换、不清理；以实时 job/process 状态等待空闲 |

已有 Windows 实例复用其原受审查部署流程和官方更新机制，不为统一脚本而重复注册。
此前的机器特定安装材料与新通用只读工具分别保管。新环境的 provisioning 必须有
明确 apply 步骤、输入版本、实际身份和停止/恢复方法；预览完成不能记为安装成功。

Windows 服务和 Linux systemd 服务遵循各自官方配置方式，不互相套用安装脚本。
专用运行账号不能获得日常管理员权限；观察者自己的 token 不能证明服务账号的权限。
注册令牌只在实际配置时短暂使用，不打印、不写入持久 profile，不能把个人 `gh` 登录态
移交给服务账号。健康检查的本地结论不代替真实账号的凭据不可读性测试。

## Linux 与必需 root 用例

独立 Linux guest 提供真实内核、文件权限、进程和 shell 语义。Hyper-V、其他受审查
虚拟机或 QEMU 用户态仿真均需核对实际运行和资源；配置文件中的 OS 字符串不是证明。
虚拟化方式变化需保留性能和兼容性结果，不能删减检查或放宽原 fixture 超时来掩盖失败。

不能在共享 guest 中给普通 runner 通用 sudo 以运行会安装生产形状路径、按进程名清理
的 root fixture。隔离容器应从第一条 fixture 指令起处于正确的 UID 和独立 PID、网络、
文件系统、user namespace，快照只读挂载，保留默认安全策略和明确资源限制。

创建配置、内核实际生效、用例结果和回收结果分别验证。必须在危险操作前建立可信
启动屏障，采集和绑定实际进程/namespace/mount/cgroup 事实；不能执行后补验再声称
执行前已有隔离。镜像 digest、工具清单、入口、环境和继承配置都需要核对。

必需 fixture 的 SKIP、缺行、非零退出、超时、日志截断或清理未知一律不能计为通过。
日志 parser 的字节上限不限制容器 overlay、log driver 或宿主磁盘；这些预算及完整性
需要另外实施。停止前台客户端不代表容器进程树已退出，回收只针对本次已核验完整 ID。

## 健康、重启与日常维护

1. 核对实例注册、服务状态、Listener/Worker、运行账号、工具版本和磁盘，记录观察时间。
2. 核对 GitHub 返回的实际 runner ID、scope、online/busy 与 job 身份；仅本地进程存在不等于在线。
3. 从真实运行账号验证必要工具和权限；使用受控 canary/ACL 检查，不读取用户秘密正文。
4. 空闲时定向停止/启动或重启实例，保留操作返回和新进程身份，再运行真实冒烟与原必要检查。
5. 主机重启恢复必须单独记录实际启动后 job；服务 `Auto` 或 `systemctl is-enabled` 只证明配置。

工具默认只读，不增加定时 GitHub workflow、提醒或监控。离线时报告排队/阻断；不自动
更改 Billing、预算、仓库可见性、组织归属或收费执行路径。托管分钟、artifact/cache
存储、电力维护及模型费用分别记录；无法取得账单时保持 unknown，不报告虚构节省。

## 回退与证据保管

| 层次 | 回退与验证 |
| --- | --- |
| workflow | 定向回退本次路由/适配差异，保留原质量门；额度不足时不能保证托管立即恢复 |
| 实例 | 空闲后停止确切实例，保留诊断；注销/卸载核对独立授权和精确目标 |
| Linux guest | 停止已核验 PID/实例，保留基础镜像、该次 overlay、串口日志及版本回执；不结束所有虚拟机 |
| 回执接口 | 新独立校验器不改旧 verification/Schema/Gate；停用它后仍使用原 CLI 与 evidence |
| 推广 | 停止新增接入，不批量复原其他仓库或改变其信任范围 |

缓存、临时产物和正式 evidence 分开。清理前核对受控根、路径解析、实例和非运行状态，
拒绝空路径、通配符、symlink/junction 逃逸；失败输出和唯一回执不是缓存。故障后先保存
真实退出、日志、snapshot、inspect 和 cleanup，再做明确范围的修复。

执行结果只报告 PREPARED、RUNNER_ONLINE、SMOKE_PASS、PILOT_PASS、ADOPTED、BLOCKED
或 NOT_APPLICABLE 中有当前证据支持的状态。试点分支 PASS 不能代表 main 已采用，
执行回执结构正确不能代表来源真实，任何新文件都不能自行授予 merge 或 Gate PASS。
