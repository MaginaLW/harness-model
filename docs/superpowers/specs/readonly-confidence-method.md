# 非评分置信度证据可用性与方法协议候选

状态：S1 可评审方法协议候选。项目所有者已选择 B、本仓自然治理任务的只读建议首场景，以及“追加机器审核并基于此积累认识”的首用途；研究描述作为审核结果的反馈与次级用途。首个 `review_detection` [协议](review-detection-protocol.md)的粗略研究精度已选 95% 覆盖、区间总宽不超过 20 个百分点，本稿继续保留四类目标的证据需求、预先分析规则及集中决定包，不重新提出用途或精度选择。首研究的[有限范围](review-detection-admission.md)已采用；真实独立真值、样本与观察条件尚未全部核定，其他目标/评分接入规则仍须按用途确定；方法候选不等于生产评分准入。

## 1. 适用范围

本稿承接[置信度反馈设计](confidence-feedback.md)、[四类合同提案](2026-10-08-review-confidence-contract-proposal.md#3-能力与概率合同)及[合同兼容与审核预算补充](2026-10-09-s1-contract-compatibility-and-review-budget.md)。旧提案中的固定窗口、接口和任务例子是历史设计输入，不作为当前执行指令，不恢复归档任务或模块。

[数据与效果合同候选](readonly-confidence-data-contract.md)负责请求、决定、执行与结果的来源链、单位和缺失口径；本稿负责在这些关系成立后，某项估计可以支持什么声明。两稿引用原件，不建立第二权威账本，不向旧 strict Schema 或当前可用性映射追加字段。

已选用途的具体流程见[追加机器审核与结果反馈](supplemental-machine-review.md)。当前可继续按已有事实准备范围内的非评分专项审核与结果来源；用途选择不自动冻结评分触发规则、扩大审核预算或完成 3-A 准入。

当前输入限于[固定提交事实快照](../../operations/effect-observations.md#固定提交的事实快照)已获准的 tracked Git 原件白名单。报告只描述该提交中的原记录，不证明 live current、全历史完整性、模型身份或原结果已经重新验证。[只读准备建议](../../operations/review-advisory.md)继续使用原生状态；本方法不重算 route、Missing、批准新鲜度或 Gate，不执行建议、不写账本。

本稿与对应可用性映射均为非评分准备，固定 `method_status=design_pending`、`probability_status=unestimated`、`execution_allowed=false`。实际报告不输出估计、`estimable`、样本充分性、eligible N、分母数、真实区间或能力阈值，也不将缺失补零。首协议另可完成已选参数下的[数学精度规划](review-detection-protocol.md#51-条件性精度规划与复算)，不读取真实观察或补合格数。3-A 生产估计与真实 shadow 仍须满足[对应准入](../../implementation/phase-03-entry-inputs.md#当前采用的-3-a--3-b-进入与退出关系)，本稿不启动 S2/S3 或改变 Phase 3 的 `not_started`。

## 2. 四目标的事件与分母

以下为可评审的目标语义。真正分母是符合该目标协议的单位集合，不是已有文件数、task 数、检查数或审核人数；当前报告不计算其数量。总体、单位粒度、纳入规则和观察边界须在相应用途估计前确定。

| target ID | 预测事件 | 真正分母与单位 | 所需来源关系 |
|---|---|---|---|
| `author_first_acceptance` | 预先指定的首个作者候选，在声明条件和有限预算内达到指定阶段验收。 | 符合纳入规则的作者尝试链，每条链对应明确的阶段和首候选；后续修复不是新的首次单位。 | 链起点及完整性依据、首候选版本、作者角色与适用身份来源、阶段协议、条件/预算和该候选的验收原件。 |
| `author_after_repair_acceptance` | 已进入修复的链，按声明策略、支持条件和预算达到指定验收。 | 实际进入修复的合格链，是修复群体的条件分母；不能用所有任务、所有首次失败或所有修复提交代替。 | 原候选与原失败、修复入口、父子候选关系、修复策略/支持/预算、验收协议及修复候选结果。 |
| `review_detection` | 在固定受审候选、可见信息和预算内，正确报告一个独立裁定存在的可处置缺陷。 | 独立裁定为正的审查机会或缺陷单位；先声明审查单位和缺陷粒度，重复报告不增加正真值单位。 | 受审版本与范围、独立正真值及裁定协议、可处置性/严重度口径、审核报告与真值的对应关系、信息与预算。 |
| `review_false_positive` | 在独立裁定不存在对应可处置缺陷的审查单位上，错误报告该缺陷。 | 独立裁定为负的预定审查机会；须有明确机会集，不能用全部报告或 Finding 数充当负真值分母。 | 受审版本与机会集、独立负真值及裁定协议、审核报告和被报告缺陷的对应关系、信息与预算。 |

审核机会可按预先声明的候选、可检查对象和缺陷类别定义；若采用缺陷级单位，其正负机会及匹配规则也须明确。检出与误报使用相容单位，不能在结果揭示后切换粒度或只挑已报告对象。首次与修复后目标适用于不同群体，二者差值不直接表示修复的因果效果。

取消、skip、未运行、partial、工具失败和结果未知均保留原值；它们如何进入分母或映射为目标事件，须按第 5 节在观察结局前确定。工具或权限失败可以证明当轮未验收，不能自动证明作者能力差。模型身份仅接受获准且可复核的实际运行元数据；actor、线程名、UI 选择和自述不构成身份依据，本阶段不采集或按模型归层。

## 3. 当前投影能支持什么

| 已有投影 | 可以说明 | 尚不能补出的目标事实 |
|---|---|---|
| task、分类及事件原状态；verification started/result 顺序和原结论 | 固定窗口内记录了哪些状态及验证尝试，后续通过不覆盖先前失败。 | 全历史链完整、真正首候选、作者/修复角色、验收协议、预算和真实交付；当前 evidence 不能自动绑定旧尝试。 |
| 指定 review ID/revision、原 outcome、同 task context 的 canonical hash 与适用版本绑定 | review 与 context 的引用对应，事件与具体修订的匹配、冲突或缺失。 | 审核正确性、当前新鲜度、独立模型身份、缺陷正负真值；`APPROVE`、零 Finding 和 `resolved` 均不能提供独立真值。 |
| evidence 的绑定、各检查原结果与来源引用 | 所保存 evidence 声明的候选和检查结果。 | 未重新验证的声明不能升级为目标验收；多个检查不是多个独立候选或样本。 |
| 每个 task 的保守依赖组及原件 blob 标识 | 同 task 的修订、重试和检查应保留关联，固定输入可复核。 | 不能认证统计独立性；共同输入、缺陷来源或跨 task 相关性仍待对应来源与规则。 |

`historical_first_result`、`history_completeness` 和 `evidence_attempt_linkage` 继续按当前快照保留 `unknown`。上下文的 `matched` 仅指声明引用、stage 或 canonical 内容对应，不提供目标真值或授权。设计 context 的 subject/evidence/snapshot 不适用性沿用原投影，不改称缺失。

报告的 `targets` 使用第 2 节的四个 target ID；各项的 `denominator_definition` 是分母候选文字，`required_facts` 引用下列闭合 fact ID，不产生纳入单位清单或分母计数：

| fact ID | 当前映射与限制 |
|---|---|
| `candidate_version_bindings`、`verification_evidence`、`recorded_verification_results` | 按固定候选绑定、evidence 和验证事件的原投影及所需来源是否存在判断；保留失败、partial、unknown 等原值，不推定作者验收。 |
| `review_results`、`review_context_bindings`、`review_event_references` | 按 review 修订原结果、同 task context 绑定及事件对应判断；匹配、冲突和缺失分别保留，不认证独立真值或当前有效性。 |
| `first_candidate_lineage`、`repair_candidate_lineage`、`evidence_attempt_linkage` | 当前 snapshot 尚不能闭合相应目标链，固定为 `linkage_unknown`；不从事件先后或末次成功补成首候选、修复链或旧结果关联。 |
| `actual_model_identity`、`task_conditions`、`acceptance_protocol`、`dependency_independence` | 当前为 `not_projected`；task 的保守 `dependence_group` 不提供统计独立组认证。 |
| `repair_strategy_and_budget`、`independent_positive_truth`、`independent_negative_truth_and_opportunities`、`defect_report_matching`、`review_information_and_budget` | 当前为 `not_projected`；不能用重试次数、审核 outcome、Finding 或 resolved 补成策略、预算或正负真值。 |

`observations` 完整保留相应原投影，包括已有 `unknown`、`not_applicable`、冲突与部分结果。fact 的 `projected` 只表示来源投影或所检查关系可得，不表示协议已冻结、真值成立、样本充分或任一 target 可估计。

当前报告只使用四类 availability，不把它们合并成一个“可评分”判断：

| availability | 含义 | 典型例子 |
|---|---|---|
| `projected` | 对应事实已由白名单原件投影；附实际引用，保留原值及关系限制。 | 已记录的验证失败，或受审 context 的版本绑定；不表示已验收。 |
| `source_missing` | 该 fact 所需的白名单原件在固定提交中至少有一件缺席，可以是部分缺失；其他原投影仍保留。 | review 引用的同 task context 文件不存在；不据此宣称所有来源或全仓均无该证据。 |
| `not_projected` | 当前白名单投影未收集或未输出该目标事实。 | 作者身份、修复策略和独立缺陷真值；不表示原仓库或其他来源不存在。 |
| `linkage_unknown` | 有记录但缺少支持该目标关系的依据，或存在已知冲突；保留冲突原值。 | 验证结果与候选关系未闭合，或 review/context stage 不对应；不推断成功或失败归因。 |

availability 只映射一个具体事实或关系。来源齐全不自动形成充分样本；关系 `matched` 也不解除其他未知项。缺失原因与设计未定分别表达，字段和原件仍按对应来源的适用性解释，不扩展旧严格 Schema 或归档候选 API。

## 4. 当前可验证的反例

- 首次记录失败、后续记录通过：原失败保持，不能回填首次成功或增加独立样本；窗口内首次观察不能补成全历史首次。
- 两份审核报告可能指向同一缺陷：保留两份 review 的原投影与来源；当前 snapshot 不投影 Finding 匹配，缺陷对应关系仍为 `not_projected`，不能认证缺陷或样本的独立性。
- `APPROVE`、零 Finding 或追加 `resolved`：仍缺独立真值，不补“无缺陷”、检出或误报结果。
- 有 Finding 而没有负真值机会集：只报告原记录与未投影的真值需求，不计算误报率。
- 当前 evidence 通过，但旧尝试绑定不明：保留通过原值和旧关联未知，不从当前 HEAD 补写旧候选。
- 同一 context hash 仅在另一 task 出现：不借用；同 task 来源缺席按 `source_missing` 说明。
- 原记录存在，但正文、身份或费用不在投影中：按 `not_projected` 说明，不读取私密材料补齐。

验收只证明这些固定输入下的纯映射、原值保留、来源引用与隐私边界正确；不验证统计精度、实际校准、人工成本下降或真实 shadow。

## 5. 在结局揭示前固定的分析协议

首用途的审核决策单位是**一个真实受审候选及一个具体专项问题**，预先绑定候选版本、范围、可见信息与已有预算；它与第 2 节各目标的统计单位分别定义。追加审核应针对有来源的问题，不按审核人数、历史成功次数或一个泛化能力分数扩大整轮审核。

首个估计候选仍只处理**一个目标、一个声明总体、一项主要声明**，现按 `review_detection` 形成[契约专项审核协议候选](review-detection-protocol.md)，有限首研究范围与精度已采用，真实观察事实仍须核定；四目标继续分开。`author_first_acceptance` 可以作为定位作者尝试与验收问题的辅助指标，不能证明追加专项审核的收益、检出能力或低误报，也不因此成为默认首目标。`review_detection` 与 `review_false_positive` 另依赖独立正负真值、机会集及匹配规则；可用性不足时先积累原件与未知，不以作者指标替代它们。四目标不合成一个能力分数，不为每个目标设计一套算法。

每次拟估计前形成带版本的简短分析协议，至少固定下列内容。协议冻结、获准来源和 3-A 准入成立后才允许估计；本轮不生成数据集、预测或估计结果。

| 协议项 | 必须固定的含义 | 对纳入判定的依赖 |
|---|---|---|
| 已选用途、目标与主要声明 | 首用途为追加机器审核并积累认识；固定一个 target ID 和主要声明，明确其如何支持该用途，而不是泛称“模型可靠”。 | 目标及声明决定需要哪些身份、任务类、独立真值、质量与精度事实。 |
| 总体与单位 | repository、任务/阶段/角色及运行条件的范围；作者链或审查机会/缺陷的具体粒度。 | 单位可识别且不重复；全历史首候选不闭合时，不纳入首次目标。 |
| 纳入与排除 | 可观察的入口、来源要求、适用版本及排除理由；规则不得依成功、失败或是否有 Finding 改写。 | 每个候选单位给出可复核理由；入口事实未知时标记待裁定，不能计为合格或静默丢弃。 |
| 条件与观察端点 | 预算、可见信息、工具/平台、验收协议及窗口起止的来源；开放与关闭依据。 | 入口与端点不可核实就不能裁定有限预算目标。验收与交付仍分别绑定。 |
| 相关组与必需层 | 第 6 节的关联规则、层定义及不满足规则的处理。 | 不用 task 数、审核人数或检查数替代独立单位；层缺失保留。 |
| 真值与匹配 | 验收或独立缺陷裁定责任、协议、严重度/可处置性与报告匹配规则。 | 检出、误报分别依赖完整正、负机会集；争议或未关闭裁定保持未知。 |
| 分析与用途判断 | 方法、单侧/双侧、精度指标、整体错误控制、固定分析边界和用途阈值。 | 先判断第 7 节的可估计性，再判断能力与用途；不能看到结果后挑区间或阈值。 |

下表是预先协议的语义候选。具体纳入入口、观察窗口和取消处理须随所选目标冻结；原状态与归因始终分列。

| 原状态或来源情况 | 协议中的处理候选 | 禁止的推断 |
|---|---|---|
| 入口前取消、未运行 | 若预定入口明确尚未发生，保留原件和排除理由；若入口不明，保留纳入未知。 | 不能事后把不利结果改称入口前取消。 |
| 入口后取消、工具/权限失败、timeout | 保留在已进入群体。仅当完整端点来源及协议能裁定“预算内未达到目标”时，记该操作条件下未达成；不能裁定时记未知。 | 未达成不自动归因作者或审核能力；取消记录不一律删出分母。 |
| skip、partial 或必需检查未运行 | 按固定验收要求及闭合端点裁定；已明确未完成必需验收可记未达成，仍开放或绑定不明则未知。 | 部分通过不提供完整验收；缺失不补失败或成功。 |
| 未关闭窗口、结果/历史链未知 | 保留待观察或未知及原因，停止依赖该事实的二元估计。 | 当前最新结果不称最终结果；窗口内首次不称全历史首次。 |
| 审核真值争议、负机会集未闭合 | 保留原报告，真值/匹配未裁定；受影响的检出或误报目标不估计。 | `APPROVE`、`resolved`、无报告不补负真值；报告数不是机会数。 |

基础候选不以完整案例删除未知后推断原总体，也不假定缺失随机。拟改成“已裁定单位”总体时，须明确这是另一项有限声明，说明选择限制并重新判断用途；不能用它冒充全部合格单位。缺失机制、选择偏差或最坏情形敏感性若影响结论，须先冻结处理与可接受边界；敏感性范围不冒充置信区间。

## 6. 独立组、分层与防泄漏

关联依据包括同一自然任务、候选/修复链、共同受审版本、共同输入或缺陷来源，以及有依据的共享运行故障。相关关系跨 task 时仍须连到同组；同组中的重试、阶段、检查、审核与重复缺陷不能当独立二项试验。组规则、来源引用与已知未决关联保留；当前 `dependence_group` 只作保守关联线索，不认证组间独立。

最小二项候选仅适用于可说明独立性、相同目标语义及条件可比性的单位集合。若一个相关组贡献多个相关单位，不能只把记录数改成组数继续套二项区间，也不能随意挑成功或失败代表。可在协议中预先定义每组唯一目标单位及其选择规则，并相应缩小声明总体；做不到时维持非评分描述，相关数据方法另行评审，不在本轮加入聚类模型或“有效 N”算法。

必需层由用途及条件定义，至少检查任务类型、阶段/角色、Policy、验收、工具/平台和预算版本是否需要分开。只有拟作特定模型声明时才将获准实际身份作为该模型层必要条件；身份未知不默认归入任何模型层。不要为填空层事后合并、删除或借用不可比外部记录。若要作总体混合声明，需预先明确目标构成、权重来源与可比性，不能把便利样本的频数直接当部署总体权重。

| 数据用途 | 预先固定规则 | 防泄漏要求 |
|---|---|---|
| 训练/估计 | 拟合估计器或选择模型所用集合；简单固定条件比例候选没有额外学习模型。 | 只使用拟预测边界前可得的输入；验收、修复后结果和最终缺陷裁定只能作为结局。 |
| 校准 | 仅在采用需要校准的预测方法时单列校准集及选择规则；本轮未实现校准。 | 不用同一数据同时选择方法、调整阈值并宣称独立校准；没有独立校准证据不称已校准。 |
| 留出评估 | 在方法、用途阈值和预测固定后评估未参与选择的结局；不自造划分比例。 | 同一依赖组不跨集合；适用的时间边界同样冻结，不能利用未来结果构造过去的输入。 |

先固定组与划分，再揭示结局；真实 shadow 还须在当时边界固定预测，历史回放不提供该事实。留出结果一旦用于改方法、分层、预算或阈值，该集合就参与了选择，后继评估另需未参与选择的来源。分组可阻止已知关联泄漏，不能证明未知相关性已经消失；不同线程或模型名称不提供该证明。

## 7. 最小估计候选、精度与能力判断

方法候选为：在同一声明条件下，目标已按冻结协议裁成二元、单位独立且具有共同成功概率时，用观察比例及**精确二项比例区间**表达目标事件与不确定性。该本仓概率候选承接历史 S1，不引入外部先验、伪样本量、学习模型或依赖。项目所有者已允许最初评分参考公开排名网站；[外部参考工具](../../operations/benchmark-reference.md)单独计算候选配置的相对参考分，不将其转换成此处的本仓概率或样本。NIST 说明二项模型针对两种互斥结果、各试验的成功概率固定；其比例区间手册给出精确双侧区间构造，适合评审小样本或少量失败的处理。这里采用的是条件性方法候选，网页例子中的数值不移入本项目。[NIST 二项分布](https://www.itl.nist.gov/div898/handbook/eda/section3/eda366i.htm)、[NIST 比例置信区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

区间不修复样本选择、缺失真值、错误版本绑定、相关性或漂移。零观察失败不等于失败概率为零；全通过也须保留方法产生的不确定性。若以特定模型能力为目标，工具故障与权限拒绝的归因协议还须成立；操作条件下的验收概率不能直接改名模型能力。当前只设计规则和首协议的条件性精度规划，不计算本仓真实观察的比例、区间或分母。

| 判断 | 必须满足的条件 | 可报告与不可报告 |
|---|---|---|
| 事实可用性 | 第 3 节来源投影及关系结果。 | 保持四类 availability；来源可得不表示纳入、真值或独立性成立。 |
| 估计可用性 | 已选用途所需的分析协议与来源授权已冻结；单位/分母/真值闭合；独立性、可比性、缺失/选择与漂移规则成立；必需层覆盖及精度达到预定要求。 | 未来才可能在声明范围报告 `estimable`。未定规则为 `design_pending`，已定而证据不足为 `insufficient`，超范围为 `out_of_scope`；当前报告不增加这些推断。 |
| 能力是否达标 | 估计可用后，按预定区间方向、用途阈值及质量条件判断。 | 可估计但未达标仍是有效估计；区间跨越阈值是达标结论不明确，不能改成通过。样本充分不是能力足够。 |
| 估计能否用于审核安排 | 已选用途的效果、质量、当前授权和评分接入条件成立。 | 达标结论不自动改变审核安排、route、Gate 或执行权限；已有权限内的非评分专项审核与结果准备继续。 |

首个 `review_detection` 粗略研究已选 95% 等尾双侧覆盖、区间总宽 `U-L<=0.20`；其他目标或用途的精度另按自身需求确定，稀少事件附近不默认以相对误差判充分。所选方案下的数学最坏宽度规划为 `n_plan=104`，不是任务门、实际合格 N 或样本充分性结论。真实样本规则仍需结合相关性、必需层覆盖和观察条件成立，不照搬 Phase 4 的时间/任务门。观察窗口及分析边界预先确定；不能反复看结果直到区间或达标判断满意才停止，顺序推断另需方法合同。

单个目标/层的区间只支持该项边际覆盖，不能称四目标、所有层或多轮观察同时达到同样精度。若用途要同时声明多个目标或层，应预先列完整声明族与总错误预算；可评审最小方案是为各声明分配错误预算，总和不超过整体预算，再分别构造对应区间。该方案依 NIST 所列 Bonferroni 不等式，不复制其均值比较公式到二项结果；无需假定各声明独立，仍须满足每个区间自身的模型条件。[NIST 总体覆盖与 Bonferroni 方法](https://www.itl.nist.gov/div898/handbook/prc/section4/prc473.htm)

首个候选只作一个主要声明；没有多项共同声明需求就不实现多重比较模块。首声明已选的 95%/20 个百分点不提供多目标、多层或多轮同时覆盖；后续有这种需求时，整体错误预算和分配另按用途后果确定。精度、覆盖与外推范围分别报告，不以最窄层区间代表全体，也不挑有利层代替必需空层。

## 8. 已选首用途、反馈与后续用途

追加机器审核并基于结果积累认识是已选首用途，不再提交三选一。研究描述用于反馈实际审核原值、来源限制与后续方法认识；人工升审是尚未选择的后续用途。当前非评分建议继续按原生事实运行；本表区分已有权限内的准备、尚未准入的评分用途与未来扩展。

| 用途 | 最小准入及判断对象 | 估计可以支持的行为 | 未达条件时 |
|---|---|---|---|
| 追加机器专项审核（已选首用途） | 以固定受审候选和具体专项问题为单位；评分驱动安排还须冻结触发规则、目标、真值、质量/漏检误报代价与预算，并有真实 shadow 支持。 | 在当前权限内建议具体专项审核；估计影响对象、范围或预算时，策略接入另按对应准入。 | 可准备或开展已有权限内、有事实依据的非评分专项审核并保留结果；不依据未定分数触发，不扩大预算或削弱已有检查。 |
| 研究描述（反馈与次级用途） | 先反馈实际审核原值、裁定/匹配、修复复核与未知；如作估计，另须固定目标、总体、来源与方法协议并满足可估计性。 | 描述获准观察范围内的事件、覆盖和不确定性，支持修订后继方法；无执行、审核安排或批准效果。 | 继续原值与缺失描述；一轮新增报告不证明收益，历史回放不称真实校准或效果改善。 |
| 人工升审（后续用途，未选） | 采用前另需选择并冻结真实残余问题、漏升/误升成本、停止条件及具体接入；具备来源链和可比效果证据。 | 条件成立后才可按对应规则提示人工升审；当前真实方向/权限缺口仍按原规则处理。 | 不把所有未知或低分自动变成新的人工批准项；已有有效决定继续按原生绑定使用。 |

已采用的首研究接受只读认识可能遗漏、重复、无法估计或精度不足，不自动改变审核安排。未来以概率触发追加审核的规则、阈值、效果和风险仍须按对应接入具体化；超出现有决定的风险由所有者决定，技术准备不自设通过值。检出目标侧重漏检，误报目标侧重错误报告；作者首次或修复后验收指标均不证明审核检出、低误报或追加审核的因果收益。反馈需保留新增报告与独立裁定、修复及复核的关联，未知不补零。没有结束的质量观察与可比真实任务，不能宣称减少人工打断或保持缺陷率。

## 9. 漂移、停止与恢复

模型实际身份、任务构成、上下文、工具/平台、Policy、验收、预算或真值协议实质变化时，保留旧 cohort 与方法结果，并评估新 cohort；不把新结果回填旧候选，也不自动合并。跨 cohort 可比性、合并和更新规则须事先明确。仅监测计数或漂移提示不能证明估计继续有效，定量漂移边界不得临时自设。

出现版本绑定冲突、纳入入口/结局/独立真值未闭合、用途所需身份未知、必需层缺席、精度不足、已知相关性未处理、数据来源越界或未处理漂移时，停止受影响估计与策略用途，保留原件、失败及原因。继续独立的非评分来源准备；停用建议后可按原流程工作。恢复须有对应补证或新冻结协议及准入，而不是把旧审核通过、后来成功或当前批准当作统计问题已消失。

首用途、`review_detection`、95%/20 个百分点精度及[有限研究范围](review-detection-admission.md)已由所有者采用；下面区分已定规则、Agent 应核定的实际事实，以及未来实质变化才需要的新决定，不重新请求已覆盖的声明、总体、来源职责、窗口或风险选择。普通实现细节和可恢复准备继续按现行授权推进。

|---|---|---|---|
| 首目标的声明与总体 | 纯文档契约首次专项审核的直接矛盾类、窗口指定机会和只读风险回退已采用；新目标/总体另评估。 | 核对实际候选、适用契约与机会边界、审核条件及主要声明对应；作者验收指标只作辅助定位。 | 真实研究保留未知，继续非评分准备与反馈。 |
