# 置信度反馈建设与首个只读建议场景

状态：项目所有者已选择 B，采用 3-A 低风险建议与校准、3-B 高风险 V3 的独立准入和验收关系；首场景已选本仓自然治理任务的只读建议，首用途已选**追加机器审核，并基于审核结果积累认识**。本文是当前方向与范围设计，不记录逐次执行进度。实现与数据条件尚未全部满足，Phase 3 仍为 `not_started`；路线和用途选择不修改 Policy、CI 或授权。

目标是用可复核的真实结果改善机器审核安排，让人类处理尚未解决的方向、权限和风险决定。首个场景限定在本仓自然发生的治理变更：读取已有事实，建议机器下一步与残余决定；执行继续遵循当前规则。评分与执行权限分别判断。

本文复用 [S0–S5 路线](../plans/2026-10-08-confidence-driven-approval-roadmap.md)、[S1 合同提案](2026-10-08-review-confidence-contract-proposal.md)与[合同兼容及审核预算补充](2026-10-09-s1-contract-compatibility-and-review-budget.md)的概率、尝试链、来源和残余问题语义。它们是设计输入，各自固定窗口中的任务状态、接口和动作例子不作为当前执行指令。已归档的 TASK-0063～0071 不恢复推进；退役模块与工具也不因本设计而重新启用。

## 3. 首个场景：本仓自然治理任务的只读建议

首场景用户流程为：在已有自然治理任务的一个真实工作边界，固定受审版本和观察窗口，读取当前原生状态及获准原件，输出机器下一步、真实残余决定与未知来源。建议可以指出应补机械记录、做专项审核、范围内修复或保留未知；它不替原生 CLI 重算路由、批准新鲜度或 Gate，也不执行建议。

例如原生 `Missing:` 同时出现实现记录和一个尚缺的真实方向回答时，机器应完成前者的准备，并集中呈现后者的具体选项。存在有效 spec 批准时不因为历史批准条数或当前 subject 变化一概要求重签；已消费动作不因新审核恢复。每条结论必须落到实际引用和支持关系，缺乏关系则保留 `unknown`。

输入复用现有 task、review、verification 和已获准请求/决定来源。固定 tracked Git facts 可提供可重放的历史事实盘点，不能证明 live current、真实宿主权限或完整请求链。真实边界的当前判断仍需对应原生读取与当时绑定；读件失败分别报告，不能用历史快照补成当前结果。task-free 工作使用其真实变更标识，不创建虚构 TASK-ID。

首个场景验收只看建议是否正确区分机器工作、实际决定和证据缺失；是否保留原失败及当前有效决定；是否能停用建议并继续原流程。它不证明人工打断已下降，也不验证 CreateNew、宿主 consumer 或执行器。旧 CreateNew 候选后移到确有需求且相应准入完成的执行阶段；本场景不依赖完整引擎外仓产品化或 provider 接入，边界见[接入指南](../../operations/adoption.md#完整引擎的跨仓库边界)。

首用途的具体流程见[追加机器专项审核与结果反馈](supplemental-machine-review.md)：以固定候选及具体专项问题为单位，准备非作者审核、作者处理和受影响范围复核，再用可复核结果更新后续判断。项目所有者已允许最初评分参考各种排名网站；[公开榜单初始参考](../../operations/benchmark-reference.md)可先作为配置排序的外部信息，保留原指标、版本与未知，概率仍为未估计。研究描述作为这条反馈链的产出；人工升审沿用真实方向、权限和风险决定的原规则。当前已有依据的非评分准备可继续；概率触发和实际审核策略接入分别满足 3-A 及对应后续准入。

[审核结果回读](../../operations/review-feedback.md)已实现固定 tracked `HEAD` 正式账本的受限事实汇总及 commit/path/blob/locator 来源定位，复用原快照解析与白名单，默认 snapshot/availability 保持不变。它保留审核各修订、Finding 状态和原验证结果；作者处置、独立复核和实际模型配置仍未知，独立真值与 task-free PR 反馈为未投影。可并列外部参考，`model_score_update_status=not_implemented`；结果回读不等于评分改善或审核安排的完整闭环，也不改变 route、Gate、CI 或批准。

## 4. 分开建设的最小范围与验收

| 单元 | 最小实施范围与产出 | 依赖与验收 | 不可据此宣称 |
|---|---|---|---|
| S0 非评分事实基线 | 复用 `tools/analysis/approval_overhead.py` 与[效果观察口径](../../operations/effect-observations.md)；增加固定 tracked Git facts 的只读盘点，列原状态、引用、版本、尝试链及缺失。只给事实计数和来源限制。 | 获准已有数据；证明固定输入可复算、不写原件、不把检查/重试/Finding 膨胀成独立样本，原失败不被末次结果覆盖。 | telemetry 合同已冻结、样本充分、模型成功率或人类成本下降。 |
| S1 非评分建议与方法设计 | 将首场景的问题映射到已有原生事实；形成简明建议、依据、残余决定与未知。分别设计作者首次验收、修复后验收、审核检出和误报的目标与分母。 | 无分数建议保持 `probability_status=unestimated`，无执行、权限或账本效果；治理源码按当前准入实施。方法与兼容候选可先评审，具体参数仍待已选用途的目标与质量规则冻结。 | 多层审核人数提供概率，APPROVE 或 resolved 提供独立缺陷真值。 |
| S2 离线评分与反例验证 | 在 B 对应数据/方法/用途合同已准入后，实现一个声明总体内的估计与不确定性；用固定 synthetic 反例验证身份未知、样本不足、相关链、漂移和权限边界。 | 须完成 3-A 实现准入；不以路线选择代替数据与方法规则。固定候选通过全部规定检查与独立审核，synthetic 和真实评估分开。 | 离线 PASS 证明真实校准、取消人工之后质量相同或执行权限可用。 |
| S3 真实只读 shadow | 自然任务中先固定预测、窗口与候选，再观察真实结局；只输出建议。分别留出估计/校准/评估数据，按依赖组防泄漏。 | 来源、隐私、样本及用途规则先成立；报告覆盖、缺失、精度、误报/漏检和可得质量原值。证据不足保持建议或不估计。 | 历史回放是实际 S3，建议请求数是实际减少的打断，开放缺陷窗口是零缺陷。 |
| S4 有限执行或审核策略接入 | 仅在真实需求与S3证据支持后选择一个具体能力：已有权限内的审核安排，或一个正式宿主支持的低风险动作。 | 分别核真实接入点、当前授权、精确范围、停止/恢复和实际结果；策略变化与动作各按对应准入。使用高风险能力时先满足3-B。 | 高分授权动作，wrapper 是执行器，S4试点放行部署、删除、凭据或付费调用。 |

事实基线、评分方法设计、真实评分 shadow 与执行能力是四种不同产出。任何阶段都不能从上阶段的“可解释”自动晋级到“可估计”，或从“可估计”晋级到“可执行”。相应来源尚无结果时报告 `unknown`；设计参数未定时报告 `design_pending`；已定规则而证据不足时报告 `insufficient`。

## 5. 必要的数据、样本与用途决定

本节集中列后续定稿的实质问题；来源关系、度量与缺失语义见[只读置信度数据合同](readonly-confidence-data-contract.md)，不建立第二权威任务账本。sidecar 若被采用，只引用原生原件，不回填旧 strict Schema。当前已确定的技术规则只覆盖固定 tracked 白名单、来源版本及引用、原值保留、受限投影和非评分输出；它们不等于真实观察、统计精度、独立真值或全部 telemetry 已准入。原始会话、身份、日志、费用和运行时数据继续遵循[保存与隐私边界](../../operations/effect-observations.md#保存与隐私边界)。

| 决定 | 需要明确的最小内容 | 未明确时的处理 |
|---|---|---|
| 具体用途与预测目标 | B、本仓只读建议首场景及“追加机器审核并基于此积累认识”已选择；还需确定首个预测目标、总体、使用者、触发规则及错误后果。 | 不重复请求用途选择；推进非评分事实与方法，剩余规则未冻结时不启用生产估计、评分路由或执行。 |
| 获准来源与数据责任 | 可读取哪些现有原件，身份依据可否用于该用途；新副本保管者、访问、脱敏及保留/处置边界。 | 缺失显式记录；不新增私密采集，不删除既有追加原件。 |
| 样本与观察 | 总体、任务/角色必需分层、独立组、纳入/排除、窗口及取消/skip/缺失处理；选择偏差和漂移的接受边界。 | 不用现有 task 数量证明充分，不因必需层为空临时删层，不借 Phase 4 的30天/30任务门。 |
| 方法与精度 | 适用统计模型、区间方法、置信水平、允许误差、整体误差控制；先验、更新与跨cohort规则。 | 已允许公开榜单的初始相对参考分；保留配置、来源、日期与原指标，不转成本仓概率或伪样本，不合并未证明可比的外部先验。本仓概率方法保持 `design_pending`。 |
| 质量与用途阈值 | 缺陷真值的独立裁定、严重度映射、漏检/误报、校准与返工标准；预测能影响哪一种现有权限内的审核安排。 | 没有真值不估计检出或误报率；不以模型自报分数放行动作。 |

数值应由首个用途的容许错误与所需精度推导，在对应运行前冻结；本设计不凭经验填写样本量、窗口、保留期或阈值。审核预算复用现有已授权范围和来源，普通可恢复准备不因为未来预算参数未定而新增审批。执行动作的次数、时限、费用和消费边界另按实际授权，不从审核轮次推定。

实际模型只能来自获准、可复核的运行元数据；actor、线程名、UI选择和自述不认证身份。requested、reported 与 actual 分开，actual 缺失时不归入某模型层。工具失败、权限拒绝或未知归因可证明当轮未验收，不能自动证明作者能力差。首次结果与修复后结果分开，成功不抹掉失败。

### 5.1 数据使用边界

| 范围 | 当前可做或后续准入所需 | 输出与限制 |
|---|---|---|
| 已有 tracked 白名单的只读准备 | 沿用已获准快照的精确来源及受限字段，固定提交并复核来源关系；继续合同、反例和可用性准备。审核结果回读增加受限 Finding 状态，不扩来源或复制正文。 | 只报告事实、缺口与非评分建议，维持 `method_status=design_pending`、`probability_status=unestimated`、`execution_allowed=false`。普通回读按现行维护授权实施，不额外等待生产概率准入；白名单不是全仓或私密目录读取许可。 |
| 公开排名的初始参考 | 已获项目所有者明确方向；人工核对公开榜单的配置、指标、版本与日期，离线输入保留原值与 hash。 | 只计算声明集合内的相对参考分；本仓概率仍为 `unestimated`，不认证实际运行身份，不读取 private 来源，不改变审核策略、授权或账本。缺失不借旧模型、镜像或 API 文档示例补分。 |
| 获准的自然真实观察 | 在对应用途运行前明确现有原件范围、真实工作边界、纳入与窗口、请求→决定→执行→结果绑定、所观察质量事实及独立真值适用性、保存责任；获准后只观察该范围。 | 涉及预测时先固定预测及结局揭示顺序；缺件保留 `unknown`。非评分观察不自动批准 S2 估计或 S3 评分 shadow，采得记录也不证明独立或充分。 |
| 新私密来源、身份或费用 | 若确有用途需要，提出具体来源、必要字段、读取/复制方式、接收者与用途；新增采集、外部来源和付费调用分别按真实范围核授权。 | 未明确前不采集、不复制、不建立新存储，身份与费用保持未知。已有 tracked 许可、路线 B 和开始准备的指令均不扩展为这些许可。 |

真实观察可以复用已有获准来源，不要求人在每次自然任务中重复签字；来源、用途、范围或风险发生实质变化时才重新评估相应准入。请求组数、批准条数、聊天时间差和 Agent 运行时长不能互换成人类成本，原审核结论与 `resolved` 不能代替独立缺陷真值。

| 最小化与脱敏 | 复用受限投影，不提交原聊天、身份、凭据、会话日志、审核正文或本机信息；匿名聚合须避免通过稀疏分组或引用组合暴露私密内容，必要时只发布方法与可用性。 | 只复制用途必需字段；明确原件引用与脱敏映射谁可读取、是否可重新关联以及公开摘要如何复核。未决定前不创建映射或副本。 |
| 位置、保留与处置 | 既有 tracked 原件、失败和追加证据按现行规则保留；不得借新保留策略删除或改写。 | 复用已有适合且获准位置；无位置则保持未知，不擅自新增。事先约定保留终点、到期/撤回处理及处置责任，不预填天数；删除动作仍单独核授权。新副本处置与既有追加证据保全分开。 |

未来私密副本不是当前交付物。现有任务获准本地材料可沿用已忽略的 `logs/` 位置，task-free 工作不为保存观察而强制创建 task；没有适合且获准的位置时，不用公开仓库替代。来源缺失只保留缺失状态，不补读私密原件。

### 5.3 提交所有者的最小决定包

项目所有者已选择**追加机器审核，并基于此积累认识**。后续估计首先服务具体专项审核建议，审核、处理和复核的真实结果再用于限定条件下的研究描述；原“先采用研究描述”的建议不再作为当前待选方向。追加审核可能增加预算、返工和延迟，也可能重复报告或遗漏问题；具体触发、可接受错误及其后果仍须在对应使用前冻结。研究描述和人工升审的其他用途边界保留，这次选择不赋予动作权限，也不取消原有审核或批准要求。

一次集中决定应引用同一候选合同并覆盖以下内容，而不是为每个字段新增签字：

1. **已选用途的边界与后果**：围绕追加机器审核明确预测目标、适用总体、接收者、触发规则、容许误差及不可接受的错误；反馈研究只陈述来源支持的认识。若会改变审核安排，明确对应策略变化的准入，不再请求同一用途选择。
2. **数据范围与责任**：真实观察可用原件及必要字段，身份/费用是否确需且获准；若采用私密副本，写明责任、访问、脱敏、位置、保留终点与处置边界。无新来源的方案明确保持现有来源限制。
3. **可复核质量协议**：预先明确纳入、必需分层、独立组、窗口、缺失与取消处理、独立真值责任及裁定/匹配规则；再据用途误差确定方法、精度、充分性与停止标准，不由现有记录数量倒推门槛。

上述决定包的来源盘点、合同候选和可用性反例可继续完成；用途已选，但目标、触发、误差、独立真值或私密治理等剩余条件未定时，材料仍是 `design_pending`。普通准备、范围内修复与验证按现行授权完成，不请求逐次批准；集中决定与对应准入成立后再推进受影响的真实观察、估计或评分 shadow。

## 6. 并行工作与串行依赖

下面是对应实施规格的并发安排，人数均不含主 Agent；每阶段按实际独立工作流与容量调整，文件归属在开始时明确。多线程与多人审核不提供统计独立性证明。

| 阶段 | 计划 sub-agent 数量与独占职责 | 主 Agent 的串行工作及依赖 |
|---|---|---|
| S0/S1准备 | 4名：现有来源/样本链；方法/充分性设计；首场景建议与权限边界；效果/隐私缺口。每名只写其被分配材料。 | 统一 B 的两包映射、术语与范围，汇总尚缺的具体数据和用途决定；不等缺失宿主事件而停所有准备。 |
| 方案复核 | 2名非作者：目标/数据效果；权限/兼容及证据强度。 | 作者定点修复，统一最终候选；所有者仅作实际路线或超出常设授权的决定。 |
| S2实施 | 最多3名：事实读取模块；一个估计模块；独立反例测试，分别独占文件。单模块可串行完成，不为数量增设抽象。 | 共享合同/API/Schema和治理准入先串行；整合后固定候选，正式完整验证、账本及Git refs由单一协调者处理。 |
| S3评估 | 最多4名：校准/留出；质量/误报漏检；请求组/决定；来源/缺失与漂移，均读取同一固定快照。 | 先固定预测与窗口，再揭示结局；统一数据版本、适用结论和是否进入下一用途。 |
| S4接入 | 准备阶段3名：接入兼容；异常与停用；效果比较。实际操作时2名只读核证据及结果。 | 正式接入、具体动作、消费和结果按依赖串行；同一UI、账本、refs或资源不并发操作。 |

依赖顺序为：获准事实准备 → B 对应用途合同 → 3-A 准入 → 离线实现及反例 → 固定候选完整验证 → 自然真实 shadow → 有证据支持的有限接入。3-B 在真实高风险任务和边界明确后独立准入、实施与验收；整体 Phase 3 等待两包真实退出。Phase 4 的持久队列、租约、调度与跨主机编排仍须整体 Phase 3 退出、稳定接口及真实协调需求，不只依赖 3-A。

## 7. 停止、恢复与交付判断

无新实质问题时停止扩大审核。来源关系不能支持、身份未知、样本不足或漂移未处理时，停止受影响的估计或策略用途，继续可独立完成的事实准备。原生读取失败、必需检查失败和未知根因分别保留；部分通过、局部诊断与覆盖率不能覆盖必需失败。

停用只读建议后继续原流程，保留原件与失败；新源、新用途、范围或风险变化重新评估相应准入。真实动作已过期、撤回或消费时不自动重跑。常设授权中连续两轮 REQUEST_CHANGES、无法修复的CI失败或范围外动作按现行例外规则提交具体残余问题。

交付报告只说明实际完成的能力、固定版本、检查、来源限制与未决用途。完整测试、85%总覆盖率、90%diff coverage、whitespace、Ruff、format、mypy与required CI继续适用。没有可比真实任务与结束的质量窗口时只报告原值和可用性，不声明人工成本或缺陷率下降。
