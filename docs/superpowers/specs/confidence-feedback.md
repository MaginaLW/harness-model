# 置信度反馈建设与首个只读建议场景

状态：可审阅的方向与范围提案。本文收敛后续建设，不记录逐次执行进度，不修改现行阶段门、Policy 或授权，也不声明 Phase 3 已启动。

目标是用可复核的真实结果改善机器审核安排，让人类处理尚未解决的方向、权限和风险决定。首个候选限定在本仓自然发生的治理变更：读取已有事实，建议机器下一步与残余决定；执行继续遵循当前规则。评分与执行权限分别判断。

## 1. 适用依据与历史材料

当前治理与常设授权以 [AGENTS.md](../../../AGENTS.md) 为准，状态以[维护收尾与待办](../../operations/maintenance-status.md)为入口，实际任务缺项和合并条件以原生 `status`、`gate` 及当前 Policy 为准。[阶段三进入输入](../../implementation/phase-03-entry-inputs.md)仍要求样本、真实 V3 用例和统一版本化度量三门；维护模式不解除这些条件。

本文复用 [S0–S5 路线](../plans/2026-10-08-confidence-driven-approval-roadmap.md)、[S1 合同提案](2026-10-08-review-confidence-contract-proposal.md)与[合同兼容及审核预算补充](2026-10-09-s1-contract-compatibility-and-review-budget.md)的概率、尝试链、来源和残余问题语义。它们是设计输入，各自固定窗口中的任务状态、接口和动作例子不作为当前执行指令。已归档的 TASK-0063～0071 不恢复推进；退役模块与工具也不因本设计而重新启用。

[低干预工作方式](../../operations/low-intervention.md)继续适用：机械缺项由 Agent 完成；实际缺少的 ASK 方向、授权文件或常设授权之外的风险决定才提交所有者。设计准备、观察缺项或 `unknown` 不新增用户逐次签字。

## 2. 两个方向及推荐

推荐 **B：将低风险建议与校准能力、真实 V3 验证分别准入和验收**。只读建议不需要高风险故障执行器；实际引入高风险动作时再接回 V3 依赖。这个推荐仍待所有者选择，不能由文档完成或常设技术批准代为采纳。

| 影响 | A：保持现行 Phase 3 三门耦合 | B：拆分低风险反馈与高风险 V3 |
|---|---|---|
| 首个交付 | 先完成三门；此前限于非评分事实盘点与合同设计。 | 非评分准备照常进行；采纳后，低风险线可按自身数据、方法和质量条件实施评分与真实只读 shadow。 |
| 进入条件 | 样本充分性、真实 V3 用例与版本化度量必须同时具备。 | 3-A 要求获准数据、分层与充分性规则、版本化度量及具体用途；3-B 要求真实风险任务、资产、故障、沙箱、损失与恢复边界。 |
| 退出条件 | 按原 Phase 3 完整能力和原进入关系验收。 | 3-A 验收建议正确性、校准与目标场景效果；3-B 验收真实安全检查、故障、dry-run 与恢复。完成一包不称另一包或整个 Phase 3 完成。 |
| 治理影响 | 不调整阶段路线；实现仍按当前清单准入。 | 需要明确修订阶段三进入关系、实施目录与两包验收映射；保留原编号、历史门及失败原件，不凭本提案改写。 |
| Policy 与授权 | 当前 route/V、批准、硬风险及 CI 门保持。 | 同样保持；建议输出没有权限效果。若后续改变审核策略或程序接口，须单独评估和准入；授权文件与降低门槛仍由所有者逐次决定。 |
| 建设取舍 | 路线简单，但低风险校准持续等待尚未选定的真实 V3 用例。 | 先交付低风险用途；需要分别管理数据适用范围，并在风险扩展前接回 V3。 |

选择 B 的最小决定是：正式采用这两个能力包的独立进入与退出关系，并选本仓只读建议作为首个场景。它不同时批准统计数值、私密采集、provider、宿主审批接管或高风险执行。后续规格把已选择方向映射到准确文件、接口、验证和所需批准；普通实现细节由 Agent 完成。

## 3. 首个场景：本仓自然治理任务的只读建议

候选用户流程为：在已有自然治理任务的一个真实工作边界，固定受审版本和观察窗口，读取当前原生状态及获准原件，输出机器下一步、真实残余决定与未知来源。建议可以指出应补机械记录、做专项审核、范围内修复或保留未知；它不替原生 CLI 重算路由、批准新鲜度或 Gate，也不执行建议。

例如原生 `Missing:` 同时出现实现记录和一个尚缺的真实方向回答时，机器应完成前者的准备，并集中呈现后者的具体选项。存在有效 spec 批准时不因为历史批准条数或当前 subject 变化一概要求重签；已消费动作不因新审核恢复。每条结论必须落到实际引用和支持关系，缺乏关系则保留 `unknown`。

输入复用现有 task、review、verification 和已获准请求/决定来源。固定 tracked Git facts 可提供可重放的历史事实盘点，不能证明 live current、真实宿主权限或完整请求链。真实边界的当前判断仍需对应原生读取与当时绑定；读件失败分别报告，不能用历史快照补成当前结果。task-free 工作使用其真实变更标识，不创建虚构 TASK-ID。

首个场景验收只看建议是否正确区分机器工作、实际决定和证据缺失；是否保留原失败及当前有效决定；是否能停用建议并继续原流程。它不证明人工打断已下降，也不验证 CreateNew、宿主 consumer 或执行器。旧 CreateNew 候选后移到确有需求且相应准入完成的执行阶段；本场景不依赖完整引擎外仓产品化或 provider 接入，边界见[接入指南](../../operations/adoption.md#完整引擎的跨仓库边界)。

## 4. 分开建设的最小范围与验收

| 单元 | 最小实施范围与产出 | 依赖与验收 | 不可据此宣称 |
|---|---|---|---|
| S0 非评分事实基线 | 复用 `tools/analysis/approval_overhead.py` 与[效果观察口径](../../operations/effect-observations.md)；增加固定 tracked Git facts 的只读盘点，列原状态、引用、版本、尝试链及缺失。只给事实计数和来源限制。 | 获准已有数据；证明固定输入可复算、不写原件、不把检查/重试/Finding 膨胀成独立样本，原失败不被末次结果覆盖。 | telemetry 合同已冻结、样本充分、模型成功率或人类成本下降。 |
| S1 非评分建议与方法设计 | 将首场景的问题映射到已有原生事实；形成简明建议、依据、残余决定与未知。分别设计作者首次验收、修复后验收、审核检出和误报的目标与分母。 | 无分数建议保持 `probability_status=unestimated`，无执行、权限或账本效果；治理源码按当前准入实施。方法与兼容候选可先评审，具体参数仍待用途决定。 | 多层审核人数提供概率，APPROVE 或 resolved 提供独立缺陷真值。 |
| S2 离线评分与反例验证 | 在所选路线和对应数据/方法合同已准入后，实现一个声明总体内的估计与不确定性；用固定 synthetic 反例验证身份未知、样本不足、相关链、漂移和权限边界。 | A 须满足原三门；B 须完成正式拆分与3-A准入。固定候选通过全部规定检查与独立审核；synthetic 和真实评估分开。 | 离线 PASS 证明真实校准、取消人工之后质量相同或执行权限可用。 |
| S3 真实只读 shadow | 自然任务中先固定预测、窗口与候选，再观察真实结局；只输出建议。分别留出估计/校准/评估数据，按依赖组防泄漏。 | 来源、隐私、样本及用途规则先成立；报告覆盖、缺失、精度、误报/漏检和可得质量原值。证据不足保持建议或不估计。 | 历史回放是实际 S3，建议请求数是实际减少的打断，开放缺陷窗口是零缺陷。 |
| S4 有限执行或审核策略接入 | 仅在真实需求与S3证据支持后选择一个具体能力：已有权限内的审核安排，或一个正式宿主支持的低风险动作。 | 分别核真实接入点、当前授权、精确范围、停止/恢复和实际结果；策略变化与动作各按对应准入。使用高风险能力时先满足3-B。 | 高分授权动作，wrapper 是执行器，S4试点放行部署、删除、凭据或付费调用。 |

事实基线、评分方法设计、真实评分 shadow 与执行能力是四种不同产出。任何阶段都不能从上阶段的“可解释”自动晋级到“可估计”，或从“可估计”晋级到“可执行”。相应来源尚无结果时报告 `unknown`；设计参数未定时报告 `design_pending`；已定规则而证据不足时报告 `insufficient`。

## 5. 必要的数据、样本与用途决定

本节集中列后续定稿的实质问题，不复制长字段合同，不冻结数值，也不建立第二权威任务账本。sidecar 若被采用，只引用原生原件，不回填旧 strict Schema；新增公开材料仅保留方法与可公开的脱敏摘要。原始会话、身份、日志、费用和运行时数据继续遵循[保存与隐私边界](../../operations/effect-observations.md#保存与隐私边界)。

| 决定 | 需要明确的最小内容 | 未明确时的处理 |
|---|---|---|
| 路线与用途 | A/B；首场景；建议用于追加专项审核、人工升审还是仅供研究；拟采用哪些预测目标。 | 准备非评分事实与方法；不启用评分路由或执行。 |
| 获准来源与数据责任 | 可读取哪些现有原件，身份依据可否用于该用途；新副本保管者、访问、脱敏及保留/处置边界。 | 缺失显式记录；不新增私密采集，不删除既有追加原件。 |
| 样本与观察 | 总体、任务/角色必需分层、独立组、纳入/排除、窗口及取消/skip/缺失处理；选择偏差和漂移的接受边界。 | 不用现有 task 数量证明充分，不因必需层为空临时删层，不借 Phase 4 的30天/30任务门。 |
| 方法与精度 | 适用统计模型、区间方法、置信水平、允许误差、整体误差控制；先验、更新与跨cohort规则。 | 不发明冷启动分数，不合并未证明可比的外部先验；保持 `design_pending`。 |
| 质量与用途阈值 | 缺陷真值的独立裁定、严重度映射、漏检/误报、校准与返工标准；预测能影响哪一种现有权限内的审核安排。 | 没有真值不估计检出或误报率；不以模型自报分数放行动作。 |

数值应由首个用途的容许错误与所需精度推导，在对应运行前冻结；本设计不凭经验填写样本量、窗口、保留期或阈值。审核预算复用现有已授权范围和来源，普通可恢复准备不因为未来预算参数未定而新增审批。执行动作的次数、时限、费用和消费边界另按实际授权，不从审核轮次推定。

实际模型只能来自获准、可复核的运行元数据；actor、线程名、UI选择和自述不认证身份。requested、reported 与 actual 分开，actual 缺失时不归入某模型层。工具失败、权限拒绝或未知归因可证明当轮未验收，不能自动证明作者能力差。首次结果与修复后结果分开，成功不抹掉失败。

## 6. 并行工作与串行依赖

下面是对应实施规格的并发安排，人数均不含主 Agent；每阶段按实际独立工作流与容量调整，文件归属在开始时明确。多线程与多人审核不提供统计独立性证明。

| 阶段 | 计划 sub-agent 数量与独占职责 | 主 Agent 的串行工作及依赖 |
|---|---|---|
| S0/S1准备 | 4名：现有来源/样本链；方法/充分性设计；首场景建议与权限边界；效果/隐私缺口。每名只写其被分配材料。 | 统一术语与范围，汇总具体A/B及用途决定；不等缺失宿主事件而停所有准备。 |
| 方案复核 | 2名非作者：目标/数据效果；权限/兼容及证据强度。 | 作者定点修复，统一最终候选；所有者仅作实际路线或超出常设授权的决定。 |
| S2实施 | 最多3名：事实读取模块；一个估计模块；独立反例测试，分别独占文件。单模块可串行完成，不为数量增设抽象。 | 共享合同/API/Schema和治理准入先串行；整合后固定候选，正式完整验证、账本及Git refs由单一协调者处理。 |
| S3评估 | 最多4名：校准/留出；质量/误报漏检；请求组/决定；来源/缺失与漂移，均读取同一固定快照。 | 先固定预测与窗口，再揭示结局；统一数据版本、适用结论和是否进入下一用途。 |
| S4接入 | 准备阶段3名：接入兼容；异常与停用；效果比较。实际操作时2名只读核证据及结果。 | 正式接入、具体动作、消费和结果按依赖串行；同一UI、账本、refs或资源不并发操作。 |

依赖顺序为：获准事实准备 → 所选路线与用途合同 → 对应准入 → 离线实现及反例 → 固定候选完整验证 → 自然真实shadow → 有证据支持的有限接入。3-B仅在高风险任务确有需求、边界已决定时实施；Phase 4的持久队列、租约、调度与跨主机编排保持其独立进入条件。

## 7. 停止、恢复与交付判断

无新实质问题时停止扩大审核。来源关系不能支持、身份未知、样本不足或漂移未处理时，停止受影响的估计或策略用途，继续可独立完成的事实准备。原生读取失败、必需检查失败和未知根因分别保留；部分通过、局部诊断与覆盖率不能覆盖必需失败。

停用只读建议后继续原流程，保留原件与失败；新源、新用途、范围或风险变化重新评估相应准入。真实动作已过期、撤回或消费时不自动重跑。常设授权中连续两轮 REQUEST_CHANGES、无法修复的CI失败或范围外动作按现行例外规则提交具体残余问题。

交付报告只说明实际完成的能力、固定版本、检查、来源限制与未决用途。完整测试、85%总覆盖率、90%diff coverage、whitespace、Ruff、format、mypy与required CI继续适用。没有可比真实任务与结束的质量窗口时只报告原值和可用性，不声明人工成本或缺陷率下降。
