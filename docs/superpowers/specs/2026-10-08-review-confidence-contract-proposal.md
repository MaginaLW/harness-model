## 1. 最小目标与共同语义

目标是让机器完成授权内的机械步骤和技术修复，只把仍缺少的方向、权限、风险接受或不可验证的问题交给人类；随后用实际结果判断审核建议是否可靠、人工介入是否减少。合同准备不以 F、全部 runner 生命周期或 provider 接入完成为前置；一个真实试点使用这些能力时，才加入对应依赖。

| 对象 | 统一语义 |
| --- | --- |
| 阶段验收 | 固定任务阶段、受审版本、验收协议与预算下的实际结果；验证通过与真实交付分开。 |
| 尝试链 | 首个候选、修复候选和复核的关联；保留每次原结果，最终通过不覆盖首次失败。 |
| 统计独立组 | 同一原任务、修复链、共同输入或缺陷来源的相关记录须分组；记录数、审核人数和 Finding 数不成为独立样本数。 |
| 能力估计 | 明示条件下某个目标事件的估计、来源、覆盖与不确定性；身份或数据不够时不估计。 |
| 审核策略 | 在已有权限内安排机器审核、修复或抽检；其策略概率与成功概率分开。 |
| 授权覆盖 | 依据当前有效的权限、精确动作及绑定事实判断；技术信心和审核建议不提供权限。 |
| 观察状态 | 失败、取消、未运行、skip、partial、unknown 分开保留，并记录缺失原因。 |

## 2. 审核、修复与残余问题

按依赖执行：核当前授权与硬边界 → 检查现有事实和机械条件 → 专项独立审核 → 范围内修复 → 复核受影响问题 → 处理残余问题。独立审核人数不作为可靠度票数，同模型或不同线程也不自动证明错误独立。

| 问题类别 | 首选处理 | 何时需要人类 |
| --- | --- | --- |
| 机械缺项或状态投影差异 | 读取原生 `status`，必要时对照 `gate`、绑定与原件；完成当前范围内的机械步骤。 | 缺项确实是尚无有效决定的 spec/code 或具体动作批准。 |
| 技术分歧 | 固定争议、版本、证据与可检验预期，专项独审并修复；只复核受影响部分。 | 有界处理后仍有会影响方向或风险接受的残余分歧。 |
| 方向选择 | 完成可独立推进的准备，形成具体选项、推荐及影响。 | 互斥业务方向没有现行决定。 |
| 权限缺口 | 判断实际层级与当前覆盖，区分失效、撤回、消费及范围漂移。 | 当前所需权限确实缺失；重复消息不延长或复活旧动作。 |
| 风险接受 | 列出剩余风险、影响、恢复与证据限制。 | 风险超出现有授权或需要明确接受损失边界。 |
| 不可验证 | 记录未知项及最小补证路径，继续无依赖工作。 | 缺失事实必须由所有者提供或决定，且没有获准的补证途径。 |

每轮开始固定问题清单、角色、证据范围、停止条件和预算来源。候选编排为一批初始专项审核加一次受影响残余复核；时间和工具成本上限待定稿，这是设计预算，不是现行 Policy 或重试授权。沿用已有批准中的次数与时限；没有新协议时不自造无限复核或整轮重试。新范围、风险或 Policy 变化按现行准入处理。无新实质问题不重复扩大审核；停止后交付已解决项、残余项、未知项和原件引用。待冻结的共同预算见第 7 节。

TASK-0069 提供一个实际区分例子：初始 DU 的 38 项影响范围与 37 项允许范围不一致，分类拒绝后在原允许范围内纠正并保留拒绝原件；这是机械准备问题。其当前冻结规格 `e785ed663af145f006995980ec146c3ac13bd89568d38e09c203838a551110f1` 已获独立 Design APPROVE、0 findings；`c9e0132933f894ed5c684af08952fd535e863fc5` 的当前原生核定仍为 `WAITING_FOR_SPEC_REVIEW`、仅缺 `spec_approval`，这是实际人类决定点。此例没有证明宿主拒绝原因或人工介入下降，也不替代待定的规格批准。

## 3. 能力与概率合同

拟预测的目标是：指定任务阶段、固定候选在指定条件和有限预算内达到明示验收。条件包括实际模型、任务类型、角色、推理档位、工具/平台版本与可用性、上下文供应，以及 spec、Policy、验收协议和预算版本。超出已声明总体、窗口或条件时不沿用估计。

| 估计对象 | 目标事件与必要分母 |
| --- | --- |
| `author_first_acceptance` | 符合纳入规则的尝试链中，预先指定的首个候选达到阶段验收。 |
| `author_after_repair_acceptance` | 已进入修复的链，在声明策略、支持来源和预算后达到验收；它是修复群体的条件结果。 |
| `review_detection` | 有独立裁定的可处置缺陷时，在固定信息与预算内正确报告缺陷。 |
| `review_false_positive` | 独立裁定没有对应可处置缺陷时，错误报告该缺陷。 |

首次率与修复后率不直接相减作为因果效果。没有独立缺陷真值，不估计检出率或误报率；APPROVE、零 Finding 和 resolved 都不提供真值。工具失败、权限拒绝或未知归因可以证明当轮未验收，不能自动归因模型能力。

`reported_model`、`requested_model` 与 `actual_model` 分开；实际身份没有获准且可复核的运行元数据时为 unknown。actor、线程名、UI 选择和模型自述不认证身份。未知记录用于缺失与覆盖说明，不默认汇入某个模型层。初始状态为 `unestimated`；外部先验只列独立来源，来源可比性、权重与敏感性规则未冻结时不合并，不发明冷启动分数。

更新保留 dataset/cohort/method 版本、纳入与排除理由及原结果。模型、工具、Policy、验收或任务分布发生实质变化时建立新 cohort 并报告漂移；跨 cohort 合并规则须预先明确。修复结果不回填首次结果；留出评估中同一依赖组不跨集合，预测在结局揭示前固定。

充分性候选依次检查：目标和分层已冻结、身份适合用途、相关组处理成立、结局可裁定、缺失/选择偏差和漂移达到边界、每个必需分母非空、估计精度达到冻结标准。二元结果满足所选二项模型假设时，可以精确二项比例区间作为候选方法；方法与精度均待选。[NIST 原始手册](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

设计参数未冻结时为 `design_pending`；已有规则而证据不足时为 `insufficient`；达到范围内规则才可为 `estimable`；超出范围为 `out_of_scope`。充分表示可估计，能力是否达到用途标准另行判断。单层精度不称全体分层同时精度；置信水平、允许误差和整体误差控制待冻结，不套用 Phase 4 的 30 天/30 任务门。

`success_probability` 表达目标事件估计；`review_policy_probability` 若采用，只表示已有权限内追加审核或抽检的策略概率。含义未定的 `approval_probability` 暂不使用。概率和确定性阈值均须先冻结用途；模型自评分不触发实际动作随机放行。校准未完成、身份未知或漂移未处理时保持建议或不估计。

## 4. 样本、效果与记录合同

候选观察记录放在独立 sidecar，引用原 task/review/evidence/event/approval，不向现行 strict Schema 回填新字段，也不建第二个权威任务账本。一个样本主单位绑定 repository、task、阶段和受审版本组；一个自然任务可以有多个阶段记录，统计时仍须评估它们的相关性。

| 字段组 | 最小内容与来源 |
| --- | --- |
| 版本与关联 | repository identity、task 或真实 task-free 标识、stage、base/subject、spec/Policy/context、attempt/parent/chain/dependence group；分别绑定验证与交付。 |
| 角色与条件 | 作者/审核/修复/验证角色、实际身份及来源、任务类、平台/工具/上下文；unknown 附原因。 |
| 结果 | 原 status、check/log/ref、取消/timeout/skip/partial、裁定版本、归因证据与 completion scope。 |
| 请求与等待 | 实际请求组、请求原因、授权覆盖、请求/决定/执行时间；宿主与人的行为无原件则 unknown。 |
| 质量与返工 | 缺陷原严重度与来源、归一映射版本、重复关系、观察窗口、返工原因与可核实投入。 |
| 隐私与保留 | 用途、数据最小化、访问责任、保留规则及缺失/脱敏原因；本稿不批准新采集或原件删除。 |

14 个检查、5 个 mutation、多个 Finding、批准记录和报告副本是子记录，不能膨胀独立样本。不同 Policy/工具/平台和窗口分别标识；保留取消、skip、未运行、超时与 unknown，说明幸存者、选择、缺失与共享环境偏差。二元映射仅在冻结协议支持时进行；缺失不补零、不补成功、不静默删行。

阶段绑定沿用对应原生定义：设计 context 的 subject 不适用性、业务 subject、治理 attestation HEAD 分别保存；未提取的历史字段不从当前 HEAD 补写，脏候选须有当时的 diff/tree 指纹来源。每条尝试区分作者实现、审核、业务验证、入口和收集；入口或收集错误不冒充作者失败。`first_observed_result` 只表示固定窗口中对应执行类别的首次观察，`latest_result` 只表示截止时最新结果；历史链不闭合时首次全历史结果为 unknown，开放窗口不称 final。跨来源时钟缺证时不推定严格顺序。

效果比较固定场景、任务类型、窗口、结果口径与数据来源，同时看质量、误放/漏检、返工、缺陷、人工介入及等待。批准条数、Finding 数和测试用时不转换为人的打断次数或工作分钟。历史回放的建议请求数不称真实减少；没有可比数据只报告可得原值。观察缺项不新增逐次填报或交付门禁。

请求组依实际提问/决定/回复关联定义，仍不自动证明发生一次注意力切换；等待只在端点及同源时钟可核实时测量，重叠间隔不直接相加。没有交付或缺陷观察窗口关闭证据，交付、缺陷逃逸与人工投入保持 unknown。保留期/处置方案仅针对未来新增 telemetry 副本；既有追加原件不因本合同而成为删除对象。

## 5. 最小 adapter 与分层授权

建议首场景为自然工作中，在已获准且独占的 runtime 叶目录内 CreateNew 一份小型阶段报告。范围低、结果可读回、存在即拒绝覆盖；此处只是离线 advisory 合同候选，还没有证明真实重复卡点、宿主接入或减少弹窗。原件保留，不用清理或删除作为恢复。

拟 envelope 至少含：场景/请求组、任务或 task-free 实际标识、固定输入版本、精确 target/参数、固定 UTF-8 payload 的 SHA256/长度、目录与父链所有权/reparse 边界、已有 permission refs、每层覆盖结果、有效期/撤回/消费、宿主决策引用、实际执行结果、结果读回及停止/恢复说明。具体实例、payload 上限与时限尚未填造，目录模板不能替代真实实例。执行前的版本或目标漂移必须重新判断；未来一次性动作的消费须由可信执行边界保证，advisory sidecar 不伪造消费。

离线映射的建议输出拟固定 `mode=shadow`、`execution_allowed=false`、`permission_effect=none`、`ledger_effect=none`，只给建议类别、依据、机器下一步和残余决定。建议类别覆盖继续机械工作、补机器证据、范围内修复、残余人类决定、保留 unknown 及停止范围外候选。调用方给出的布尔值不提升为真实权限；相同待答问题保留原引用，当前有效决定按 native 类型绑定复用，目标漂移只重新判断受影响覆盖。

目标已存在时不覆盖或删除；排他创建失败、部分写入、关闭或终止未证时保留原件与 unknown，停止依赖路径。CreateNew 不承诺多文件事务或硬超时抢占。恢复先停用建议映射并回到原流程；新的清楚版本须在现有权限和已诊断范围内，不能自动重跑 one-use 动作。

| 层级 | 应核实的事实 | 结果解释 |
| --- | --- | --- |
| 仓库 AI Flow | 当前任务状态、Policy、批准类型与绑定、scope、实际 Missing/Gate。 | 完成机械条件与判定缺口；task-free 不伪造 TASK-ID。 |
| 人类动作授权 | 精确目标/参数/版本、现有覆盖及限制、撤回/过期/已消费。 | 当前有效覆盖才可用；一般准备权限不覆盖未来高风险动作。 |
| Codex 宿主 | 真实请求与 auto-review/沙箱决策事件，正式支持的接入点。 | 只有 rc/stdout 时无法归因宿主批准或拒绝，事件缺失为 unknown。 |
| 应用/OS/provider | 实际对象、身份、能力和权限；若涉及服务或费用，核相应授权。 | 本地批准不创造外部能力；只声明有事实支持的范围。 |
| 执行与结果 | 实际动作、资源所有权、结果原件、读回和保留状态。 | 退出码与动作成功、验收成功分别表达。 |

现行 [observation adapter](../../../src/aiflow/observation_adapter.py) 绑定 TASK-ID 和闭合输入；建议/拒绝语义不能当 task-free 执行接口。本提案的离线 envelope 不送入现行 apply，不伪造 task、host event 或执行授权。[pre-command wrapper](../../operations/hooks.md) 只拒绝、不授权；缺正式宿主能力时继续建议模式，不能修改审批配置或绕过拒绝。push、merge、deploy、删除、凭据导出和付费调用分别走实际授权。

## 6. 3-A / 3-B 拆分影响与最小范围

推荐候选：3-A 先限定为已有获准记录的离线解释、能力估计设计与建议输出；3-B 独立承担真实 V3 的资产、故障、沙箱、损失和恢复。正式采纳前，原 Phase 3 的样本、真实 V3 边界、版本化度量三门保持；S2/S3 评分实现必须满足原门或已正式采纳的新路线与相应准入。

| 对象 | 拆分后拟影响 | 本次边界与后续准入 |
| --- | --- | --- |
| 阶段输入/进入门/实施目录 | 明确 3-A、3-B 进入与退出，说明依赖何时接回。 | 这里只提交影响方案；路线方向尚无正式采纳记录。 |
| 样本/telemetry | 3-A 冻结目标、身份、依赖、缺失、隐私、精度和用途；3-B 增加资产与恢复结果。 | 本次不冻结参数、不新增数据采集。 |
| `src/aiflow/**` | 将来离线读取与建议模块、接口和拒绝反例。 | 独立治理 task；规格、正式审核及完整验证后才实施/验收。 |
| `.ai/schemas/**` | 若采用新 sidecar Schema，版本、兼容与零写拒绝独立评估。 | 不扩展既有 schema，不向旧原件追加字段。 |
