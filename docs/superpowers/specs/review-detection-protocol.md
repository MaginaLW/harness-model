# 契约专项审核检出协议候选

状态：S1 协议 `review-detection-v0.3`。承接项目所有者已选的“追加机器审核，并基于结果积累认识”，按 `review_detection` 目标具体化本仓契约专项审核协议。首轮粗略研究精度已选 95% 区间覆盖要求、区间总宽不超过 20 个百分点；[有限研究范围](review-detection-admission.md)也已由所有者整体采用。真实原件、独立真值与方法条件仍须核定，本稿不自动准入真实评分 shadow。

本稿收窄[通用方法候选](readonly-confidence-method.md)，复用[数据合同](readonly-confidence-data-contract.md)与[专项审核流程](supplemental-machine-review.md)。真实研究仍为 `method_status=design_pending`、`probability_status=unestimated`、`execution_allowed=false`。真实数据字段提纲只是可评审语义，不是新 JSON Schema、CLI 输入、任务账本或采集器；首个 [S2 离线数学合同](review-detection-offline.md)只接受 synthetic 计数，不生成真实单位清单、合格 N、比例、区间、预测或模型分数。

## 1. 一个目标与一项主要声明

拟描述：**在预定候选、契约范围、审核可见信息和既有预算条件下，专项审核是否在关闭端点前正确报告了一个独立裁定存在且可处置的契约缺陷。**

声明总体候选限定本仓自然发生的契约专项审核；任务类别、阶段、审核配置、平台与预算条件须在对应运行前固定。它不外推为全仓能力或某模型能力。拟作模型层声明时，实际运行身份及完整配置须有该用途获准且可复核的元数据；actor、线程名、角色声明与榜单名称不补实际身份。

单位候选为“固定候选上，一个预声明的契约违约机会”，以具体对象、契约版本、缺陷类别及实例粒度定位；正真值裁定后确定其具体违约判据。同一根因的多个反例和多个报告按预定规则关联。一个文件、Finding、检查、审核人数或修订不自动成为一个单位。

本目标只关注独立正真值上的检出。它不同时估计误报率、作者验收率、额外审核新增收益或减少人工的因果效果。“此前未报告”若要使用，另需先固定可见的先前报告范围；来源未出现不证明全历史未报告。负真值与未知裁定保留原值，但不能补成误报目标的完整负机会集。

## 2. 机会、裁定、审核与匹配的顺序

1. **先声明机会边界。** 按固定候选、受检契约对象与缺陷类别确定范围、实例粒度和机会集形成规则，不依已报告或已采纳 Finding 选机会。预声明对象可能裁定为正、负或未知；不能只裁定审核已报出的对象后称已覆盖全部正机会。
2. **按独立依据裁定。** 非作者裁定责任须有来源，其契约预期、候选专属违约依据、可处置性与严重度口径不依赖被评价报告。裁定与争议原件先固定，再进行报告匹配；不能为匹配某条报告而修改真值。
3. **固定审核条件与可见信息。** 候选及允许材料、已知提示、预算来源、入口和关闭规则分别引用。正常契约预期可以提供给审核者；正真值答案、缺陷根因、修复或后续结果的暴露需要单独记录。
4. **固定原报告，再处理与复核。** 原候选、报告内容和预算内报告端点先固定，之后的作者处置、修复、非作者复核与 CI 分别引用；后来结果不进入原审核输入或覆盖原失败。
5. **按预定规则匹配并关闭。** 真值、报告对应、预算内检出、作者处置、修复与实际交付分别判断，不合成一个 PASS。缺入口、关闭依据或完整报告范围时，受影响结论保持 `unknown`。

独立裁定是判据与职责的要求，不等于多个机会具有统计独立性，也不由两名 Agent 一致意见证明。一个失败检查可以成为线索；只有实际候选、先前契约预期、复现依据和故障归因对应后，才可能支持具体违约裁定。工具失败、`APPROVE`、零 Finding、`resolved`、作者 accepted 与最终 CI 通过均不能代替该裁定。

公开材料不自动证明审核未受提示。如果审核前已看见答案、原 Finding、修复或最终结果，应记录为受提示核对条件，不能与未受提示检出混合。输入固定、材料可见性或时序无法复核时保留未知；本稿不为实现盲法建立私密 oracle、副本或隐藏存储。

| 独立裁定 | 责任与职责来源、预期、候选违约依据、可处置性、裁定原结果及争议；缺原件或判据时真值未知。 |
| 审核信息与端点 | 实际受审候选、阶段/角色、允许材料、提示暴露、固定输入、已有预算来源、开始及关闭依据；实际投入与预算上限分开。 |
| 报告与匹配 | 原 report ID/revision/reference、报告端点、对应机会、语义匹配理由与裁定来源；不能靠同名 RF 或文字相似度补对应。 |
| 相关组与缺失 | 同任务、候选/修复链、共同输入/缺陷来源及共享故障的关联依据；入口、历史、真值、身份、信息时序、预算和端点分别保留未知。 |

引用沿用 commit/path/blob/locator；公开 PR capture 使用实际输入 hash 与 locator。只有 hash 或引用声明而没有可读原件，不能补成证据。预算复用[已有职责与预算合同](2026-10-09-s1-contract-compatibility-and-review-budget.md#3-有界审核预算与职责合同候选)，不发明时间、轮次、费用或默认无限预算。

来源范围沿用现有获准原件；上述提纲不扩大[Git 白名单与公开 PR 接口](readonly-confidence-data-contract.md#1-固定输入与引用)。新增裁定原件、身份用途、读取范围及保存责任需要在对应观察前明确。没有获准位置时保留未知，不另存审核输入、日期过程档案、私密材料或结果库。

## 4. 报告匹配与有限预算结局

匹配候选规则要求同一实际候选、同一契约违约对象/机制，以及足够具体的错误行为说明。语义等价的报告可以对应，但须有裁定理由；同一文件、同一 RF 或泛称“可能有契约风险”均不足。一条泛化报告不能自动覆盖多个机会；重复报告只关联同一个正机会。新发现可保留为后续反馈，不能倒填本轮机会集。

正机会在预定关闭端点前至少出现一次正确且可对应的报告，才有依据裁为“检出”。“未检出”还需正真值、完整报告范围、预算与关闭依据均成立；空 capture、未见 Finding 或后来 APPROVE 不提供这些条件。未知不能补成 0，也不能静默删掉未知后把结果外推到原总体。

| 状态 | 保留与后续裁定候选 |
|---|---|
| 明确入口前取消 | 保留原取消及排除依据；入口时序不明时，纳入关系未知。 |
| 入口后取消、timeout、工具或权限失败 | 保留在已进入观察的记录中；仅当协议及完整端点支持预算内未检出时裁未达成，否则未知。操作条件下未达成不归因模型能力。 |
| partial、skip、窗口未关闭或报告不完整 | 保留原值与缺口，不补检出/未检出；按预先协议处理，不能因结局不利临时排除。 |
| 真值争议、候选不对应或语义匹配未裁定 | 保留报告、冲突和未知；停止受影响估计，继续独立的来源准备。 |

当前 `pr_feedback` 的 `matched_reported` 只是当前 capture 的 ID/候选声明对应，不是这里的语义匹配或独立裁定。作者采纳、修复 candidate 与复核引用可由 v2 回读，但原链接仍未抓取，真实修复范围和独立复核不因此成立。

## 5. 相关性、条件性方法与已选精度

同一自然任务、候选/修复链、共同输入、同一缺陷来源或共享运行故障需要保留关联，跨 TASK-ID 也适用。同一候选的多个机会通常不能直接当独立二项试验。若后续采用“每个相关组一个机会”的最小方案，必须预定选择规则和相应总体，并说明组间独立与条件可比性；不能事后挑检出机会，或只把记录数换成组数。

在单位独立、事件二元且共同检出概率的条件成立后，复用既有**等尾双侧精确二项区间**作为描述方法候选。二项模型要求每次试验两种互斥结果且成功概率固定；NIST 给出两侧精确区间的二项尾概率构造。方法名称不保证抽样、匹配或真值正确，也不表示已实现或已经达到所需精度。[NIST 二项分布](https://www.itl.nist.gov/div898/handbook/eda/section3/eda366i.htm)、[NIST 比例区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

项目所有者已选择以下首轮粗略研究参数，适用于一个声明总体内的一项 `review_detection` 主要声明；不推广为四目标、所有条件层或多轮同时覆盖：

| 参数 | 已选值与解释 |
|---|---|
| 区间覆盖要求 | `0.95`，对应 `alpha=0.05`；等尾双侧方案每尾为 `0.025`。这是区间程序的覆盖要求，不表示模型 95% 可靠或该次审核的检出概率。 |
| 精度指标 | 区间总宽 `U-L <= 0.20`，即不超过 20 个百分点。不是正负 20 个百分点，也不能因区间不对称而改称估计值正负 10 个百分点。 |
| 方法适用性 | 仍以上述独立二元机会与共同检出概率等条件为前提；参数选择不认证实际样本或方法准入。 |

置信水平描述重复相同抽样及区间程序时的覆盖约定，不能当成本次审核能力；精确二项区间也不保证覆盖恰好等于名义值。[NIST 区间解释](https://www.itl.nist.gov/div898/handbook/prc/section1/prc14.htm)、[NIST 精确二项说明](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/propconf.htm)

固定条件下全检出也不等于能力满分；没有正机会或仍有影响总体声明的未知时不输出比例。区间宽度、样本充分性和能力是否达标分别判断；本次没有定义检出率达标阈值。

观察入口、停止边界、相关组及留出规则须在结局前固定。不能重复看结果直到区间满意再停止，也不能用留出结果调方法后继续称独立评估。历史回放只能检验已有来源与规则，不能补当时冻结预测或真实 shadow；本轮不引入额外学习模型、先验、校准算法或多目标比较。

### 5.1 条件性精度规划与复算

若采用该等尾双侧精确二项方案，定义 `W(n)=max_{k=0,...,n}[U95(n,k)-L95(n,k)]`，并取 `n_plan=min{n>=1:W(n)<=0.20}`。`k` 是全部可能检出数的数学枚举，不是本仓观测；这个规则要求预定数量下所有可能结局的总宽均符合所选精度。

顺序枚举 `n=1..104` 的全部 `k=0..n`，得到首个符合条件的 **`n_plan=104`**。没有假设最大宽度总在中心，也没有借宽度随 n 单调的假设跳过较小 n。

| 数学规划 n | 达最大宽度的 k | 最大总宽（显示值） | 未舍入值与 0.20 比较 |
|---|---|---|---|
| 103 | 51、52 | 0.200299982522412 | 大于，不满足 |
| 104 | 52 | 0.199322149198766 | 小于，满足 |

数值反演以二项 CDF 为依据：`k=0` 时 `L=0`，`k=n` 时 `U=1`；其余下界解 `CDF(k-1;n,L)=0.975`，上界解 `CDF(k;n,U)=0.025`。以下固定参数 Python 标准库片段可在现有 Python 环境复算规划值；它不读取真实记录，不是已上线评分接口：

```python
from functools import lru_cache
from itertools import count
from math import comb, fsum

TAIL = 0.025
MAX_WIDTH = 0.20


@lru_cache(None)
def coefficients(n):
    return tuple(comb(n, j) for j in range(n + 1))


def cdf(k, n, p):
    q = 1 - p
    return fsum(coefficients(n)[j] * p**j * q ** (n - j) for j in range(k + 1))


def root(k, n, target):
    lo, hi = 0.0, 1.0
    for _ in range(56):
        mid = (lo + hi) / 2
        if cdf(k, n, mid) > target:
            lo = mid
        else:
            hi = mid
    return (lo + hi) / 2


def width(k, n):
    lower = 0.0 if k == 0 else root(k - 1, n, 1 - TAIL)
    upper = 1.0 if k == n else root(k, n, TAIL)
    return upper - lower


for n in count(1):
    worst = max(width(k, n) for k in range(n + 1))
    if n in (103, 104):
        print(n, worst)
    if worst <= MAX_WIDTH:
        print("n_plan", n)
        break
```

此参数范围的浮点复算结果另由独立 Decimal 反演和精确有理数括区校验确认。校验全部 5,460 个非端点上界根：将候选根 `p=a/b` 代入 CDF，用精确整数比较 `40*sum(comb(n,j)*a**j*(b-a)**(n-j), j=0..k)` 与 `b**n`；上下括区符号及宽度界证明所有更小 n 不满足，而 104 的全部 k 满足。实际阈值判断使用未舍入值，表格显示精度不承担该证明。这是本项目根据已选参数的推导，NIST 提供区间构造而非本项目的 104 规划值。

104 指同一声明条件下可说明独立性的正缺陷机会，不是任务、审核、Finding、重试或文件条数，也不代表已有可用样本。它是最坏宽度的规划数，不是每个特定结局都必须达到的最低数；较小的固定 n 可能在某些结局满足宽度，但不能据此边看结果边停止。真实总体、真值、相关性、缺失/偏差、提示条件及窗口未成立时，规划不提供样本充分性。它不批准凑任务、追加审核预算、新采集或真实观察停止规则。

## 7. 验收反例与当前交付范围

- 只给已采纳 Finding 裁正真值：机会选择依赖报告，不能形成检出分母。
- 两个相同 RF 指向不同候选/对象：原记录保留，不据 ID 自动语义匹配；两名审核者重复报同一违约也不增加正单位。
- 工具失败而契约是否违约未知：保留失败，不补正真值或模型归因。
- 报告只说“版本可能不匹配”：具体机制与机会未对应时匹配未知。
- 修复后通过或复核 APPROVE：保留后续结果，不证明原报告正确或原轮已检出。
- 审核前看到裁定答案或修复：记录提示条件，不混为未受提示检出；public-only 不证明没有泄漏。
- 原链接非空但未读取、预算或关闭依据缺失：处理声明可回读，预算内检出仍未知。

本轮验收是协议的一致性、原件边界、精度规划的独立复算、既有 CLI 用法、引用/链接、上述反例的独立技术审核及仓库 required CI。文档准备不新增镜像单元测试，也不生成实际评分或真实样本。既有[账本回读](../../operations/review-feedback.md)、[PR 回读](../../operations/pr-feedback.md)与[外部参考](../../operations/benchmark-reference.md)保持当前接口和含义；`model_score_update_status=not_implemented`，Phase 3 仍为 `not_started`，现行 route、Gate、批准及 CI 阈值保持。
