# 契约审核检出研究的集中准入候选

状态：项目所有者已采用 S1 决定包 `review-detection-admission-v0.1`，范围决定已定稿。采用依据是所有者对整包的明确答复；提交、技术审核或 CI 不代替该决定，也不启动观察窗口。首用途、`review_detection` 目标及 95% 覆盖／总宽不超过 20 个百分点沿用。本稿把[检出协议](review-detection-protocol.md#6-集中定稿项与后续顺序)的剩余范围收拢为一个有限起步方案；具体实现与真实来源仍按第 6 节准入。

## 1. 已采用的起步范围

首研究仅覆盖**本仓未来自然发生的纯文档契约变更，其首次非作者专项审核能否检出与既有明确要求的直接矛盾**。结果供协调者研究追加审核建议与来源缺口；本轮不设评分触发阈值，不自动改变审核次数或安排。这是已选用途的首个有限研究步骤。

| 项目 | 本包采用的具体规则 |
|---|---|
| 任务与阶段 | 变更仅含 `docs/**` 普通文档，且包含 `docs/superpowers/specs/**` 的契约内容；观察第一个预声明候选上的首次非作者专项技术审核。混有源码、Policy、配置或 CI 变更的工作保留来源与排除理由，不混入本声明。 |
| 契约与缺陷类 | 受检对象是候选中的可检验要求或声明；缺陷类仅为它与观察入口前已经存在、适用且版本固定的明确要求直接矛盾。候选专属依据须说明冲突对象、适用关系和可处置影响，不能把措辞偏好或工具失败直接裁为正例。 |
| 声明 | 只描述本窗口、指定机会和固定审核条件下的预算内检出，不作全仓、模型能力、误报率或因果收益声明。实际模型身份无获准依据时仍为 `unknown`，不因此补采身份。 |
| 条件 | 入口前固定协议、候选、契约版本、审核阶段、允许输入、提示条件、平台及既有预算引用；条件不同的记录分开保留，不拼成共同概率总体。首次报告、受提示复核与修复后审核分开。 |
| 窗口 | 固定为 **30 个日历日**，从后续真实观察准入记录明确的 `T0` 起，到 `T0 + 30 days` 止；以 UTC 瞬时定位，入口区间为 `[T0,T1)`。本包采用日不自动成为 `T0`，不追溯启动，也不创建后台监控。 |
| 结局与分析 | 仅使用在 `T1` 前实际关闭并有完整预算端点依据的结局；窗口内进入但未关闭的记录保留为 `unknown`。窗口结束后只作一次计划分析，不因精度不满意延长窗口、重试、换机会或凑满 104。 |

30 日是已采用的观察边界，不是审核资源、执行次数或付费上限；`T0` 尚未固定，不能先行观察。对应实现与真实观察仍须按第 6 节核定。

## 2. 来源、职责与保存

当前已有[固定 Git 账本回读](../../operations/review-feedback.md)和[公开 PR 回读](../../operations/pr-feedback.md)，但它们输出的是受限原值与声明关联。独立真值、语义匹配、实际身份、审核信息／预算及完整关闭依据没有被自动认证。来源条数、`APPROVE`、`resolved`、修复或 CI 成功不能补成样本或真值。

采用的获准范围限于本仓**既有可公开 Git／PR 原件**中本研究必要的契约、候选、审核原报告、裁定依据和入口／关闭引用，由协调者维护来源关系与脱敏摘要。Agent 在既有允许范围内承担协调、非作者裁定和匹配职责；没有相应职责与原件就保留缺口，不代为任命新个人或机构。

| 载体 | 可复用内容与限制 |
|---|---|
| 固定 Git 原件 | 沿用 `commit/path/blob/locator` 定位与当前自动白名单；候选及契约可作正常审核输入。正式 task 仍按原 CLI 和 strict Schema 使用 review/context/event，不加真值字段、不伪造 Finding，不改变批准或状态。正文及证据引用的目标核对与现有受限投影分开，须在采用的来源范围内进行。 |
| 同一公开 PR | 在已有描述中追加机会边界、原件引用、裁定及匹配的匿名摘要，保留先前记录。原报告已有公开锚点才引用该锚点；不存在则保留未知，不把协调者摘要冒充原报告。现有 v2 块保持接口和字段，额外语义说明不写成未经实现的新字段。 |
| 缺原件或冻结依据 | 非空链接仍须实际核对；可变描述、读取时间、hash 和 `matched_reported` 不证明完整历史、输入固定或独立性。原件、可见性、时序或端点不能复核时，受影响结论为 `unknown`。 |

复用既有[公开保存边界](../../operations/effect-observations.md#保存与隐私边界)：方法与脱敏摘要可入库，过程留在原 CLI／PR；不另存审核输入、capture、原聊天、身份、凭据、会话日志或日期档案，不新增私密 oracle、映射、结果库或采集器。原件和失败按既有追加规则保留；本包不新增副本或处置期限，也不授权删除。

## 3. 独立裁定与匹配流程

1. 协调者在被测审核开始前固定候选、先前契约、对象／缺陷类别、实例粒度与机会形成规则；机会不得从已报告或已采纳 Finding 反推。正常契约预期可提供给审核者。
2. 固定被测报告及其候选、完整报告范围和预算端点。非作者裁定者不得是候选作者或被测报告作者；仅在既有职责和预算覆盖时，由未读取被测报告的裁定者按固定候选、契约与机会规则判断，裁定依据与争议先固定，再匹配报告。无需先公开答案或建立隐藏存储。
3. 正真值需可检验预期、候选专属违约依据及归因、适用关系和可处置影响；负与未知分别保留。不凭审核一致、作者采纳或后继通过裁真值。
4. 真值争议按原预算内的受影响残余复核处理，保留双方依据；未闭合则为 `unknown`，不投票、不为匹配报告改真值。方向或风险接受分歧按现有例外规则集中交所有者。
5. 匹配要求相同候选、同一契约违约对象／机制和足够具体的错误行为说明，另列理由与来源；重复报告不增加机会，范围外发现保留为后续反馈。
6. “检出”需独立正真值与关闭端点前正确报告；“未检出”还需完整报告范围及明确入口、预算和关闭依据。取消、timeout、partial、工具／权限失败和未关闭均保留原值，不能据未见 Finding 补零。

实际可见信息单独核对。正式 implementation review context 可含验证摘要，不能删字段伪装原 context 或将它称未提示审核。若审核者或裁定者看过答案、报告、根因、修复或后继结果，按各自职责记录实际暴露与影响；不能证明时为未知。不同 Agent、公开可见或仅声明未读都不提供充分性证明，不能混入已确认未提示的主要声明。

## 4. 相关组、选择与不足处理

同自然任务、候选／修复链、共同输入、共同缺陷来源或共享故障连为相关组，跨 TASK／PR 也适用；保留完整关联及理由。每组只取**本窗口第一个预声明候选中、预声明机会列表按契约引用／对象引用／缺陷类别排序的第一项**，在结局揭示前固定列表和选择。相同排序键的实例须先固定粒度及唯一定位；无法消歧则未知。选中项为负或未知时不得换正例；主要声明仅针对这种预先选定机会中的独立正缺陷，不代表全部违约机会。

每组一项仍不证明组间独立或共同检出概率。相关性、条件可比性、机会选择、正真值、提示、预算或完整端点存在影响主声明的未知时，停止主比例／区间，仅给原值与缺口；不删除未知后外推、不假设缺失随机、不制造“有效 N”。与主声明无关的未知单独保留。自然便利来源的选择偏差限制仍适用，不因零缺失声明总体代表性。

满足实际方法条件后，才按既定等尾双侧二项方案判断区间与精度。95%／20 个百分点及条件规划 104 沿用[原协议](review-detection-protocol.md#51-条件性精度规划与复算)，不改成检出率达标阈值、真实合格 N 或任务配额。窗口精度未达到时如实说明；条件不成立时回退非评分描述，本轮不新增先验、聚类估计或校准模型。

## 5. 审核预算、后果与停止

复用[已有职责与预算候选](2026-10-09-s1-contract-compatibility-and-review-budget.md#3-有界审核预算与职责合同候选)及每项自然工作的真实授权：已覆盖的一批初始专项审核和一次受影响残余复核；不为学习增加任务、盲审轮数、付费调用或补样本审核。独立裁定若未被原安排覆盖，就不能借本包开启额外一轮。数值上限、实际投入及剩余分别引用，未知不补零或无限；普通已授权准备不因缺未来预算新增逐次签字。

本包接受的研究后果是：窗口可能无合格正机会、不能估计或未达到精度；只读研究建议可能重复或遗漏问题，所以不能替代已有审核、验收与人工／Agent 决定。不存在以低分或区间直接触发审核的规则，route、Missing、Gate、批准和质量门不变。以后要用概率实际改变审核安排时，再核该接入范围与风险，不反向解释本包已接受此用途后果。

来源越界、条件实质变化、预算耗尽、关键关联冲突或必需失败时停止受影响路径；保留原结果，继续独立且已授权的准备。新条件另固定声明，不回填旧 cohort。已消费、撤回或过期动作不因复核恢复。停用研究建议后继续原流程。

## 6. 一项采用决定与后续准入

项目所有者已**整体采用本包的有限总体、30 日窗口、既有公开来源与职责、相关组选择、未知回退及只读研究风险**。这是范围与风险接受的一次决定；不重复请求同一采用、用途或精度决定，也不转为逐字段审批。

Agent 在该范围内完成对应实现输入合同、来源／质量条件与 Policy 影响核对，按现有治理执行必要验证；合格即可推进 S2 离线实现，不重复请求已覆盖的决定。首个[离线数学实现合同](review-detection-offline.md)仅接受显式 synthetic 计数，验证固定方法的数值边界与拒绝行为。真实观察须在实现验证与自身数据／方法／质量准入成立后，明确 `T0/T1`、实际候选、职责／预算和原件条件；缺机械证据由 Agent 补，真实来源或风险变化才重新集中决定。S2 synthetic／历史回放只验证实现，不启动或补造自然观察。

当前仍为 `method_status=design_pending`、`probability_status=unestimated`、`execution_allowed=false`，模型评分更新未实现；3-A 真实评分／shadow 与 Phase 3 仍未准入。采用决定也不满足 3-B V3 或 Phase 3 整体退出，不提前启动 Phase 4。

[真实观察准备流程](../../operations/review-detection-preparation.md)将上述已采用规则落实为原件定位、职责移交、可复用声明与不足处理；它不登记真实单位、不设置 `T0/T1`，填写模板或技术审核不提供真实入口事实。
