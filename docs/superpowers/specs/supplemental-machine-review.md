# 追加机器专项审核与反馈场景候选

状态：S1 场景设计候选 `v0.1`。项目所有者已选择本仓自然治理任务上的“追加机器审核，并基于此积累认识”作为首个用途；本稿具体化审核与反馈单位，不重新要求用途选择。数据、方法、质量及接入条件尚未全部成立，用途选择不等于 3-A 或 S2–S4 准入。

本稿承接[当前设计](confidence-feedback.md)、[数据与尝试链合同](readonly-confidence-data-contract.md)、[方法协议候选](readonly-confidence-method.md)及[效果口径](../../operations/effect-observations.md)。已有风险、失败或技术分歧事实可以继续支持非评分建议准备；当前工具仍为 `probability_status=unestimated`、`execution_allowed=false`。未来以概率触发追加审核，须先满足对应数据、方法、质量、授权及用途条件。

项目所有者已允许最初评分参考各排名网站。[离线外部参考工具](../../operations/benchmark-reference.md)把公开榜单原分数和完整受测配置保留，并给出声明候选集合内的相对参考分；可作为专项审核候选准备的附带信息。外部参考与本仓审核事实并列，不混成成功概率、不替代具体问题、实际身份、预算或授权。后续仍按本稿的审核→处理→复核链积累认识，真实统计或评分触发继续满足原准入。

[结果回读工具](../../operations/review-feedback.md)已复用固定 Git 白名单，保留正式账本 review 修订、Finding 结构状态、事件及验证原值，并提供原件定位。[公开 PR 回读](../../operations/pr-feedback.md)另支持显式选定的 task-free 来源与下一轮非评分核对问题；它区分协调者摘要、原生集合和所见 workflow，不扩大 Git 白名单。模型评分更新及自动审核安排仍未实现；缺作者处置、独立复核、实际配置和真值的地方继续未知。结果回读可在非评分准备中使用，不以未来生产概率准入增加普通摘要的逐次审批。

## 1. 决策单位与具体问题

决策单位是**一个固定候选，加一个具体专项问题**，不是一个模型、审核人数或完整任务的泛化评分。候选以实际 commit/tree、受审范围及适用规格/Policy 引用定位；有未提交差异时还须能复核当时差异，收尾提交不能冒充原候选。

首个学习问题候选是：**追加专项审核发现了哪些此前未报告、经独立依据裁定可处置的问题；哪些属于重复、被驳回或仍未裁定？**“此前未报告”只针对预先声明的可见报告范围，不能据来源缺席称全历史未报告。先准备已有报告的对应规则、可检验问题和裁定所需来源；独立依据及裁定协议未成立时，保留发现与处置原值，不填造真值。它是技术准备的具体问题，不是已冻结统计 target、检出率或因果收益声明。

专项问题应说明可检验预期、影响范围及来源。例如原失败检查、接口契约冲突或两份报告的具体分歧；保留来源阶段、版本和原结果。不因一个风险标签扩大成全仓审核，也不把工具失败自动归因作者能力。

当前建议只说明“哪一项问题值得核对、依据是什么、尚缺什么”。建议实施仍须落在既有审核安排和授权范围；概率、投票或来源存在均不提供执行许可，也不替代原生 status、Missing、Gate 或批准新鲜度。

## 2. 审核、处理、复核与反馈

| 顺序 | 责任与输入 | 输出及边界 |
|---|---|---|
| 具体问题与来源 | 协调者固定候选、专项问题、允许读取范围、可见信息与既有预算引用。 | 给出可核预期和来源缺口；无具体问题时不为学习制造一轮审核。 |
| 非作者专项审核 | 未实现该候选的 Agent 围绕专项问题只读审查，按现有职责拥有独占审核材料。 | 原报告定位到候选及具体问题，区分新增、重复或对应未知的发现；不能以人数或多数意见认定真值。 |
| 作者处理 | 作者依据原报告及实际规格，在已授权范围内修复或解释。 | 分别说明采纳、驳回或未裁定及理由；修复后引用新候选和实际 diff，原报告与原失败保留。 |
| 受影响处非作者复核 | 非作者检查修复实际影响、相关接口和仍未解决的问题。 | 记录复核范围、受审版本与原结果；不把作者自查标为独审，不借复核扩展动作或恢复已消费授权。 |
| 保留原结果并反馈 | 协调者在既有审核/PR 收尾位置引用各阶段原件和缺失项。 | 汇总可得事实与有限认识；复核、正式验收及实际交付分别引用，后续通过不改写先前失败。 |

专项问题和材料无重叠时可以按独占职责并行审核；共同接口、作者修复、正式验收及共享账本/Git refs 按依赖串行。非作者职责分离提高可审计性，但不同 Agent、线程或 TASK-ID 不证明错误或统计样本独立；共享候选、输入、缺陷和修复链仍按合同关联。

该流程补充现有 Design/Implementation Review、独立 Verifier 和完整质量检查。受影响处复核只说明实际覆盖，不能冒充全部 required checks 或正式验收。

## 3. 最小反馈事实与允许的认识

以下内容是已有审核/PR 收尾的引用提纲，不是新 Schema 或必填副表；原件不复制成第二份审核输入。

正式账本自动回读覆盖受限原值；PR 回读的可选标记块按各轮 `record_id` 保留协调者摘要、原 outcome 和候选引用，不以末轮覆盖原失败。摘要的角色和状态不认证实际身份或独立复核，null 候选不补最终 head，非空原报告链接仍为 `not_fetched`。下表中具体问题、新增/重复、作者处置、修复实际范围和独立复核未有相应来源时保持未知，不因已有 Finding status 或验证通过补齐。原生 resolved 只记状态，不等同作者采纳或独审通过。

| 反馈项 | 必须分开的事实与原件引用 |
|---|---|
| 问题与候选 | 专项问题、触发来源、受审版本/范围、当时可见信息与预算来源；引用数据合同的 source commit/path/blob 与已有语义定位。 |
| 新增与重复发现 | 原报告 ID/revision、具体问题及已知对应关系；同一缺陷的重复报告合并解释，无法匹配时保留未知。发现数不是独立缺陷数或分母。 |
| 作者处置 | 采纳、驳回、未裁定及其理由分别引用；采纳只证明处理决定，驳回只证明不同判断，均不自动成为正/负真值。 |
| 修复实际范围 | 原候选、新候选与实际修改范围；区分源代码修复、文档解释、同版本重试和契约/预算变化，保留原失败。 |
| 复核、验收与交付 | 受影响处复核的范围和原结果、独立验收/evidence、实际交付版本分别引用；缺原件、链不闭合或窗口开放时保持对应未知。 |
| 原始失败与实际投入 | 原失败、取消、partial、skip、未运行和重试理由保留；实际审核轮/工具耗时、预算上限、人时/费用及缺失分别记，不相互换算。 |

反馈可以形成“这个专项问题在声明范围内新增了可检验预期”“某类分歧仍缺哪项来源”等描述，并为后续协议提出反例或来源需求。它不输出模型能力分数，也不把一次发现、作者采纳或最终成功解释为额外审核的因果收益。

`APPROVE`、零 Finding、`resolved` 或处理完成不补独立缺陷真值；审核检出和误报仍须方法协议规定的独立正/负裁定、机会集和匹配。对照/反事实、可比总体或观察端点未闭合时，不声称减少返工、人类工作或缺陷率；当前固定快照覆盖也不是效果分母。

过程只使用已有获准审核记录、报告或 PR 收尾来源，`docs/` 保留稳定设计与用法。不新增日期过程档案、sidecar、结果库或后台采集，不给旧 strict Schema 回填字段；不另采 private 身份/费用或调用付费 provider。缺失按合同保留，公开摘要不得包含原始会话、身份、日志或本机信息。

## 4. 预算、停止与真实决定

审核安排、工具/时间/费用上限和具体动作授权分别引用现有来源，已观察投入与配置上限分开。不发明额外轮次或经验预算；普通可恢复准备已有授权时直接推进，未定未来预算不制造每字段签字门。预算与职责细节沿用[已有补充](2026-10-09-s1-contract-compatibility-and-review-budget.md#3-有界审核预算与职责合同候选)。

- 无新实质问题时停止重复扩大审核；不为积累样本凑任务、重复相同问题或扩大范围。
- 预算耗尽、来源/候选不能对应或必需失败未解决时，保留原结果并停止受影响路径；已授权且无依赖的准备继续。
- 来源、范围、风险或 Policy 实质变化，以及动作过期、撤回或消费，按原生规则处理；新复核不自动提供新动作或重试。
- 技术分歧先固定可检验预期、证据和影响；仍残留的真实方向、权限或风险接受决定集中交项目所有者，机械缺项按现行授权处理。

停用建议后继续原流程并保留全部已有事实。常设授权的连续两轮 `REQUEST_CHANGES`、无法修复的 CI 或范围外动作，仍按 [AGENTS.md](../../../AGENTS.md) 的例外规则处理。

## 5. 离线实现前的具体输入与串行条件

用途已选择，以下内容仍需形成可评审的具体输入，不能由当前记录数倒推：

1. 拟预测的一个目标和主要声明、适用任务/阶段/角色、具体专项问题类别、输出接收者，以及误触发追加审核或遗漏问题的可接受后果。
2. 获准自然任务来源、候选链和审核/验收绑定；相关组、纳入/排除、缺失/取消、窗口及真实观察端点；只用预测边界前可见信息。
3. 若估计检出/误报，明确独立裁定责任、正负机会集、可处置性/严重度及报告匹配；若估计作者目标，则闭合对应首候选或修复链与验收协议。
4. 相应用途的精度、整体错误控制、充分性/漂移、留出与停止规则，以及审核预算、保存责任和隐私边界；数值从用途要求推导，不填写经验阈值。

| 串行条件 | 满足前可继续 | 满足后才进入 |
|---|---|---|
| 对应用途合同与 3-A 数据/方法/质量及治理准入 | 非评分建议、来源引用和反例准备。 | S2 对应离线实现；用途选择或本文提交不代替准入。 |
| S2 固定候选的必要验证、协议和实际来源条件 | 修复实现及独立反例检查；synthetic/历史回放只验证其范围。 | S3 获准的真实只读 shadow，先固定预测/窗口/分组，再观察未参与选择的结局。 |
| S3 的适用质量、校准/留出、效果事实与停止恢复证据 | 保留未知、描述观察与改进协议，不把留出数据反复用于选阈值后称独立评估。 | S4 在现有权限内有限接入该场景；若以概率改变审核安排，另核接入与当前授权覆盖。 |

3-A 与 3-B 的独立进入/退出关系保持[阶段三准入](../../implementation/phase-03-entry-inputs.md#当前采用的-3-a--3-b-进入与退出关系)；追加机器审核不证明真实 V3、整个 Phase 3 或 Phase 4 已完成。

## 6. 假设例子与反例

- **契约问题**：固定候选的接口预期与一个失败检查冲突，已有可见报告未提该差异。专项非作者只核这个接口问题，给出可复核最小输入及预期来源；若按预定协议的独立依据裁定它可处置，再记录新增问题、作者修复及受影响处复核。可描述这一条来源链；没有对照与结束窗口，不能称审核减少了返工。
- **重复发现**：两名审核者指向同一候选的同一缺陷，其中一条被采纳并标 resolved。保留两份原报告与对应关系，不算两条独立检出，也不据 resolved 认定真值或能力达标。
- **投入未知**：额外审核未报新问题，最终 required CI 通过，但人时、费用和反事实结果未知。记录实际结果与缺失，停止无新问题的审核；不称“没有额外成本”或“额外审核避免了缺陷”。
