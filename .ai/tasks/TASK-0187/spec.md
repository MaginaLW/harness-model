# TASK-0187 · 专用回执的无轮次协议

## 目标

在 main `6a4a6456a323d62137d152849f3ca18114ba85bc` 上实现 #197 A01 已批准的 v3。当前 #197 的 head 为 `74222ee5734c21588707cef46a225773caae963d`。生产使用仍须在届时的版本上重新核对与授权。

## 范围

仅修改 `tools/ci/verify_private_replay_receipt.py` 和 `tests/integration/test_private_replay_receipt.py`。复用标准库 SHA-256、既有字节承诺、规范 JSON、SSH 验签、公开绑定与合成夹具。v3 的固定正文省略 replay.round，其余字段和质量门与 v2 相同。

## 非目标

正式 REVIEW/V2、定向变异、真实回放和生产信任登记另批。生产签发责任人和受信指纹留空；3S、3P0 HOLD。#194、#186 保持打开，TASK-0173 和 G 暂缓。

## 验收条件

1. 单一受保护 64 位十六进制承诺精确匹配 v2 或 v3 域之一，公式为 SHA-256(ASCII namespace || NUL || 原始正文字节的 32 字节 SHA-256)。仅采用匹配域构造签名语句的 protocol 和 SSHSIG namespace。v1 保留原有入口和字节。
2. 历史 v2 必须包含准确的字符串 R2；独立 namespace `aiflow-private-v2-receipt-v3` 的正文必须省略该键。全树严格比对继续覆盖准确 head、版本、attempt、14 项检查、变异、覆盖率、维护、Gate 及证据摘要。
3. 仅在本机以合成夹具临时签名。验证 v1/v2 兼容、v3 正例、承诺域/签名域或语句错配、错误轮次、漏检查、head 或 main/attempt 漂移及旧正文与新基线不符。验收现有集成测试模块并运行针对性静态检查。真实材料或回执字段值不进入夹具。
4. 此阶段只交付本地软件、测试结果和本任务账本，正式验证、变异消费及下一阶段运行分别留待批准。

## 禁止动作

私有原件访问、正式签发、远端写入、部署、分支保护更改、公开 CI 重跑和合并均为零。避免触碰历史账本和原件。

## 错误行为

未知或歧义承诺、结构或类型不符、签名失败与运行时漂移均须拒绝，失败后禁止切换协议重试。

## 回滚

改动保留在独立本地分支，由版本历史定位。已发布分支及受保护配置均不在实施范围。
