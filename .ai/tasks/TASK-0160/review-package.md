## 代码地图

## 语义变更

审批可以记录直接批准或常设授权代记。Hook 使用同一任务选择规则处理仓库子目录、歧义和旧记录。Schema 内容变化会使编译缓存切换到当前规则。CI 使用 PR 基线判断需治理的改动，要求其确由候选覆盖，也支持已合并任务的追加式关闭。普通维护、正式实施和独立关闭均保留适用的质量检查。

## 风险

重点复核任务开始前的治理改动及后续改名、FAILED/BLOCKED 既有原件保全、多任务混合提交、工作树与历史提交的差异，以及内容缓存的失效条件。集成时逐项核对 28 个核心文件和 5 个 CI 文件的 Git 模式及内容标识，均与两个受审来源相同。参考分支中的历史审核和验证保留各自的绑定。
