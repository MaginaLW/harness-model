# TASK-0117 审核包

## 审核目标

确认所有者明确授权的具体 push/merge 例外准确落地，同时保留旧任务禁令与质量门禁。

## 背景

项目所有者已同意该限定流程例外，并授权在既定条件下完成公开交付；实际 Hook 或服务器拒绝仍须遵守。

## 代码地图

当前 subject 仅修改 `docs/operations/hooks.md`；wrapper、Policy 和 CI 配置未修改。

## 语义变更

限定具体经所有者授权的 push/merge 不强制主动调用必拒 wrapper；执行前人工核验动作、目标、版本、条件和有效期。例外不解除显式或来源未知任务禁令。

## 风险

push/merge 的授权人身份和单次消费不由 CLI 强制验证。目标仓执行、权限、精确动作批准和 required CI 必须分别核实；不得忽略实际 Hook 或服务器拒绝。

## 证据

已验证：`reviews/REV-0001-r0001.json` 与 `reviews/REV-0002-r0001.json` 分别记录独立设计和当前实现审核。`evidence.json` 记录 V1 十项必需检查通过；同一次 pytest 为 4010 passed、146 项因基线未实现 resource bundle 而 skipped。核心及分析域总覆盖率分别为 89% 与 98%；文档变更无可计覆盖行。

本次 V1 主执行器使用经独立审核的外部 CLI 源码提交 `2cf78ea653b75c421d2fbbde155e55d92e508e78`；预检探针确认 runner 子进程导入本任务目标 checkout。证据中的常规复现命令未固定上述外部执行器；要复现相同执行器须使用该提交。隔离 guest 使用固定本地镜像及独立校验、但不属于 uv.lock 的 setuptools 84.2.1；guest 可写的镜像日志不是隔离的独立证明。

未验证：目标仓 required CI、具体外部动作的最终目标及其实际结果。原始运行日志未承诺匿名化，不作为公开材料。

## 审核问题

- 文档是否准确区分流程例外、真实 Hook 拒绝和具体外部动作授权？
- 证据是否绑定当前 subject，且对不同执行器来源和未验证事项如实披露？

## 推荐结论

APPROVE：当前独立实现审核通过；批准和 Gate 按 CLI 执行，外部动作条件另行核验。
