# Task Specification

## 目标

在阶段一 MVP 设计的「核心设计原则」中新增一条：规则明确、重复出现且需要一致回答或处理的诊断、治理与操作问题，优先沉淀为调用核心程序的统一 CLI 能力；并明确其适用条件与工程边界。

## 范围

- `docs/superpowers/specs/2026-08-01-ai-code-collaboration-mvp-design.md`：在核心设计原则中插入新条目「重复问题优先 CLI 化」，写明命令应提供稳定契约、自动化测试与可审计输出，不以一次性脚本或适配层中的重复逻辑替代；并明确探索性、一次性或仍依赖语义判断的问题不强制 CLI 化。其后两条既有原则的编号顺延。
- `CHANGELOG.md`：在 Unreleased 记录该设计原则补充。

## 非目标

- 不改动任何既有原则的措辞或含义，只顺延编号。
- 不实现、不承诺任何具体 CLI 能力；本任务只补充设计原则本身。
- 不改 `src/aiflow/**`、Policy、证据 schema、Gate 语义、CI 配置或任何既有任务记录。
- 不修改实施目录、验收矩阵或阶段状态文件。

## 验收条件

- 阶段一 MVP 设计的核心设计原则包含新条目，且明确写出适用条件与不强制 CLI 化的例外。
- 原有原则条目的文字未被改动，编号连续、无重复、无缺号。
- 新条目与既有的「程序裁决而非提示裁决」「Policy 单一来源」「适配层保持轻薄」等原则不冲突。
- V1 完整回归、`ruff check`、`ruff format --check`、`mypy src` 通过，总覆盖率不低于 85%，diff coverage 不低于 90%。
- `aiflow scope TASK-0037` 通过，改动不超出允许范围。

## 禁止动作

push、merge、deploy、delete、secret_export、paid_external_call。本任务不执行外部动作、不访问网络、不使用凭据、不产生付费调用。

## 错误行为

- 若编号出现重复或缺号，文档核对必须判定失败。
- 若改动触及允许范围之外的文件，`aiflow scope` 必须拒绝。

## 回滚

改动全部在版本控制内且可逆：还原该设计文档与 `CHANGELOG.md` 即恢复原状。本任务不写入其他任务的证据，回滚不涉及既有审计账本。

## 与 TASK-0033 的关系

本任务重做 TASK-0033 的同一份内容。TASK-0033 在一轮验证被中途终止后停在 `VERIFYING`，其记录绑定 base `7719796`；`main` 已前移，AI Flow 没有受支持的方式移动任务的 `base_commit`，因此其记录无法在当前 main 上继续推进。TASK-0033 的记录作为历史保留，不被修改或删除，其提交完整保存在 `origin/backup/task-0033-work`。

值得记录的是：TASK-0033 卡死所暴露的「验证中断无出口」缺口，已由 TASK-0034 交付的 `aiflow verify --abandon` 补上；而本条新增原则正是对这类「规则明确、重复出现」问题的一般化表述。
