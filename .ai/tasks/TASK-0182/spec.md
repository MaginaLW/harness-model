# 公开 V2 验签器版本字段修复

## 目标

在当前公开 main 的干净基线上，从 TASK-0181 已保留的三个软件对象重建默认关闭的验签器候选。修复实现 d1203caf 对公开 final V2 版本字段的拒绝条件，增加直接覆盖缺陷的回归测试并独立复审。本轮交付为本地候选及一次正式 V2 的预算提案。

## 范围

沿用既有只读手动 workflow、单文件验签器和合成集成测试。以基线 evidence.schema.json 的 2.0 契约校验 spec_sha256、policy_sha256、classification_input_sha256 和 decision_unit_ids。复用标准库和现有字段校验及签名测试路径。前驱 workflow 按原字节采用，软件修复仅在验签器与其测试。隔离环境的 Git 子模块支持另在本机独立验证并保留既有失败记录。

## 非目标

沿用原签名协议、普通 ai-quality-gate、Policy、覆盖率阈值与依赖。不开启在线验签，保留默认关闭和单文件标准库执行方式。

## 验收条件

1. 三个摘要均为 64 位小写十六进制字符串。决策单元列表非空、唯一，每个 ID 为大写 DU- 加至少三位 ASCII 数字。缺失、类型或格式不符均拒绝；合规的多个 ID 与长编号可接受。
2. 通过验签器正常入口验证有效签名下的合规和不合规输入，区分字段校验与签名不匹配。全量验签模块、原质量工作流测试和受影响文件的 Ruff、格式及 mypy 检查通过，证明普通质量工作流与公开基线逐字节相同。
3. 本机复核隔离环境发行版 Git 子模块工具及必要依赖，在新隔离目录直接运行上次失败的唯一 pytest 用例，记录源版本、工具来源、环境及实测结果。原失败任务及原件保留。
4. 由独立评审者核对实际软件提交、测试与环境回执，按 CLI 生成绑定的候选和本地预算提案。正式 V2 需所有者随后明确批准启动、独立验证者、当前绑定和单次 action 全部齐备；仅预留预算不启动。本轮不创建或消费正式动作。

## 禁止动作

本轮不启动正式 V2、native mutation 或真实 CI；不推送、开 PR、合并、签发或公开任何证据。旧任务额度已消费，禁止复用。公开 CI、披露、正式切换、G、#150、费用和配置变更均不在授权范围。

## 错误行为

拒绝缺项、格式或类型不合法、重复或空的决策单元及现有协议规定的其他错误，输出失败。定向检查失败只如实记录，不能替代正式 V2。本地预算提案不改变 Gate 或产生实施审核快照。

## 回滚

保留原任务、原隔离工具树和各自的原始回执。撤回候选时保留追加式本地历史和失败证据，普通质量门继续按原规则执行。
