# 动作执行边界设计

这是 TASK-0047 冻结规格的设计输入，不是外部执行授权或已经实现的服务端能力。

## 能保证什么

| 边界 | 当前事实与本任务目标 | 不能扩大解释为 |
|---|---|---|
| 分类输入 | 有类型的受控动作事实和显式风险类别；Agent 补齐后方可新分类。 | 静态字段能证明随后任意命令的真实语义。 |
| 本地 wrapper | 已支持的 canonical 类别中，只有 Policy 明列 read 可通过；未知和高风险拒绝。 | wrapper 能拦截所有 shell、Git/GUI/IDE 或未接入客户端。 |
| 通用 action 批准 | 现有版本绑定记录与辅助函数；无通用执行消费者。 | 文件、actor 标签或 current/fresh 状态是认证过的人类执行授权。 |
| 定向 mutation | 既有固定操作、锁、二次校验、receipt 和消费边界，本任务不动。 | 它可以直接扩展为任意外部动作或全系统 sandbox。 |
| push/merge | 现有保护与人类流程约定；本地 wrapper 仍拒绝。 | required CI 成功或本地 Gate PASS 已授权外部动作。 |

## 未接通的通用消费者如何处置

本次不为消除一个“未接通”标记而增加伪执行授权路径。`freshness.py` 的通用
`action_approval` helper 保留非执行性的兼容接口，文档明确无生产执行 caller。
Gate/status 不将其作为通用自动执行的放行条件；pre-command 不读取它。
这解决的是边界设计，可信外部执行能力本身仍未完成；不得将拒绝实现列为该能力已上线。

## 未来可信 push/merge 执行器的必要条件

真正允许自动外部动作时，授权与执行须在 Agent 不能自行改写的服务端可信边界内完成：

1. 明确仓库、允许的固定操作和资产范围；通过服务端身份认证的人作决定，使用独立凭据
   或受保护执行身份，不能相信仓库内 actor 字符串、聊天复制文本或自签本地 JSON。
2. 授权绑定精确 repo/ref/head、action digest、参数、期限及单次语义；禁止“任意命令”授权。
   要求新鲜的 subject/spec/Policy/分类/代码接受及精确 head 的 required CI，不接收通配条件。
3. 服务器原子检查并保留消费 receipt，锁定同一动作；重复请求返回同一结果，不能双执行。
   授权失效、参数漂移、已消费、未知执行结果均不能静默重试为一次新执行。
4. 执行前复查 head 与分支保护，采用精确 head 条件调用，权限遵循最小范围；不得 admin
   bypass、强推或以另一个未授权动作修复失败。服务端必须记录授权、执行尝试及真实结果。
5. 故障测试覆盖缺/伪造身份、跨仓库、错误/变化 head、过期、并发双调用、调用超时、部分
   完成和 receipt 持久化失败；没有这些集成证据时不宣称自动执行可用。
6. 服务提供方、身份根、凭据托管、操作范围、审计保留、撤销与恢复政策必须由所有者明确。
   当前没有这些输入，也没有本次授权范围内的真实服务端执行器；不能擅自选择/部署服务。

上述条件不要求本轮新增人工流程，亦不作为已获批的未来产品规格。可选的实际服务方案
需有真实外部边界之后再评审；本轮保持默认拒绝并完成本地修复，不重开历史审批整改方案。
