# TASK-0165 实施审核包

## 审核目标

裁决候选 `e8b97f3822b68f1e95b0a396f9ac43fd802290dd` 的五项原生变异能否在指定 Windows 环境中归因到预期断言，并由公共证据消费者复核。

## 背景

旧候选在 A01 完成五项定向检测，在 A02 完整验证中因私有导入及差异覆盖率失败。新候选修复共享接口，并为已有报告器子进程采集同轮覆盖率。两个旧动作均有独立消费回执。

## 代码地图

`mutation_runner.py` 与 `process_runner.py` 管理受控子进程及其收尾。`mutation_reporter.py` 和 `mutation_protocol.py` 产生并解析检测报告。`mutation_materials.py` 核对提交材料，`mutation_evidence.py` 保存和回放证据，`verification_service.py` 将结果纳入 V2。

## 语义变更

每个基线与变异结果各自绑定报告摘要、退出码及进程生命周期。共同满足预期断言、双流 EOF、自然退出与 Job 清理时，消费者才确认检出。原生检测每流限 16 KiB。历史记录缺少归因所需事实时保留其已知范围。

## 风险

本轮原生执行限定于已核定的 Windows 环境。完整 pytest 有六项因缺固定 Node 材料跳过，另三项受平台条件限制。

## 证据

已验证的本地结果来自一次 `aiflow verify TASK-0165 --actor a03-independent-verifier`，14 项检查全部通过。pytest 为 4,979 项通过、9 项条件跳过。核心覆盖率为 90%，变更行覆盖 956/1,043。五项原生结果均为 killed，主仓回放通过。[定稿证据](evidence.json) · [实施审核](reviews/REV-0005-r0001.json)

未验证的项目包括私有 CI 回放和远端 required check。A03 的预算仅覆盖本地执行。

## 审核问题

- 目标与前提是否满足？指定环境中的五项实际断言和十份生命周期报告均已核对。
- 实现复用了什么？沿用现有受控启动器、Git 原件、标准库及公共证据消费者。
- 是否存在更简单的充分实现？只看退出码无法证明失败发生在预期断言。
- 新增接口有何依据？既有进程限额参数支持原生报告上限，跨模块共享操作采用公开名称，并保留安装包调用者的异常兼容。
- 范围是否受控？实现、模式和测试共 17 个文件均在冻结范围内。S 为 A03 新候选执行预算，H 为旧动作消费回执与最终快照的独立复核。

## 推荐结论

APPROVE。独立实施审核 REV-0005 对当前候选和 A03 快照无未解决发现，定稿证据支持本地代码批准。
