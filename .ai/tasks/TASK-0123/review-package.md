# TASK-0123 审核包

## 审核目标

确认本仓受限常设推送与合并授权可减少逐次人工批准和单次 action 记录，同时保留既有质量门、任务禁令与自动动作默认拒绝。

## 背景

项目所有者已明确授权该受限规则调整及条件性交付。前序任务因新增独立回归测试超出冻结范围而保持 BLOCKED，记录与证据原样保留；本任务在包含独立测试的基线上重新审核和验证。

## 代码地图

`AGENTS.md` 和权限 Policy 定义本仓、分支和交付条件；Policy Schema 限定新授权值；`src/aiflow/policy.py` 拒绝权限 Policy 重复键；`task_service.py` 和 `gate.py` 处理新任务默认禁令及 AUTO 预检。配套测试与用法说明是独立 task-free 基线。

## 语义变更

限于已授权目标的本仓 `codex/*` 单候选推送和满足条件的 `main` merge commit，可依常设授权执行而无需逐次批准或 action 记录。六项动作仍为 deny_automatic；其他高风险动作、显式和来源未知的旧任务禁令继续适用。

## 风险

CLI、Hook 和 Gate 不认证授权人或真实 Git 目标；Agent 必须核对实际仓库、ref、版本与条件，不能忽略已安装 Hook 或服务器拒绝。Policy 变化使旧绑定失效，必须重新分类和审核。公开内容可能已被外部读取。

## 证据

已验证：`reviews/REV-0002-r0001.json` 是当前 Policy 绑定的独立设计审核，`reviews/REV-0003-r0001.json` 是当前 subject 的独立实现审核。`evidence.json` 记录原生 V1 十项必需检查通过；同一次完整 pytest 为 4070 passed、146 skipped（基线尚未实现 resource bundle）；核心与分析域覆盖率分别为 89% 和 98%，核心差异覆盖 100%（38 行）。此前本机轮次达到 1200 秒上限，其失败证据和日志保留；隔离轮次使用当前源码、锁定依赖及受控本地镜像重试。镜像日志为访客可写记录，不独立证明完整网络隔离。

未验证：本次 PR 的目标仓 required CI、实际 push 和 merge 结果。根入口的旧 Policy 版本描述需在独立收尾中修正。

## 审核问题

- 常设授权是否仅覆盖指定仓库、ref 与已授权目标，并继续保留真实任务禁令和外部动作边界？
- Policy、Schema、任务默认值和 AUTO 检查是否保留既有拒绝，且没有将过程核对误称为机器认证？
