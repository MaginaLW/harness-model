# 核心治理修正规格

## 目标

让本仓的审批记录可选地表达授权来源，让本地 Hook 能从仓库子目录准确绑定任务并产生契约有效的观察，同时保证共享契约校验与只读 SDK 路径对真实输入保持新鲜、可复核。基线为 e23b0668，旧候选 a78bcc80 只供对照。

## 范围

- 审批。CLI、服务和 approval schema 接受可选的 direct_human 或 standing_delegation，原样记录在现有批准与事件中。缺省兼容历史字节；执行权限、批准类型、独立审核和 Gate 规则沿用当前实现。
- 两个 Hook。从所处子目录找到 Git 根并使用该根的 schema。显式任务优先；省略任务时优先考察工作树和本分支变更涉及的任务，唯一活动候选可选取，歧义和损坏按原错误类别失败；无候选沿用现有唯一活动任务规则。只依赖本地 Git 和现有路径/状态解析。任务记录缺 subject 时 Hook 将 base 写为观察的实际 subject，服务用同一版本事实核对。公开 observation 入参与已持久化事件始终经完整 schema 校验。
- 契约。批量校验已有受作用域约束的资源快照；如单次校验重用已编译规则，须按当前 schema 实际内容（包含被引用文件）隔离，界限固定。验收以修改后同进程校验结果为准，允许继续使用原有新鲜的单次路径。
- 共享模块。消除跨模块私有符号 import 对 reader、路径、审批标识和恢复、Gate 与状态、任务事件与分类、初始化/manifest 的耦合，保持现有异常、字节、延迟导入与消费语义。封闭的 mutation 双模块授权握手继续使用原通道；没有外部消费者的授权别名无需增加。只读 SDK 的 Git 调用沿用命令、超时、输出与子进程环境，并设置 GIT_OPTIONAL_LOCKS=0。
- 变更仅限 task.yaml 中列出的文件与本任务账本；必要回归放在对应现有测试或候选导入边界测试。原工作树 telemetry 工作、旧任务、CI 路由与文档由各自原归属维护。

## 验收条件

1. 从 approve 入口验证缺省/两种允许值、无效枚举及重试可观察行为；已有授权记录、版本绑定和重复调用保持一致。
2. 在临时 Git 仓库内从子目录运行 Hook；确认显式选择、隐式唯一/歧义、历史 task 无 subject 的合法观察、无效输入的失败与事件写入边界。两种 Hook 运行结果应继续遵守原有拒绝或通过语义。
3. 使用实际 schema 内容在同一进程校验成功与失败，包括直接或引用的 schema 改变且尺寸/时间相同的情况；沿用既有批量漂移测试。
4. 在新 Python 进程检查普通核心模块导入不会加载 installed/Node 重模块；验证共享接口消费者、现有 mutation 双模块授权握手与 SDK Git 环境。复用受影响的正常 CLI 路径与现有回归；按实际分类运行项目完整 verify 和 Gate。没有新增外部服务或需独立准入的集成场景。
5. 取得独立设计与实现审核，以当前规格、代码与证据为准。交付由主任务按常设授权将核实的 codex 分支推送本仓、开 PR，并在当前 head required check 通过后使用 merge commit 合并；本地 verify、Gate 与外部交付分别留证。

## 禁止动作

不部署、删除数据、导出凭据、付费调用、改分支保护或降低 CI 阈值；不启动真实评分/宿主接入/暂停的旧实验，不采用旧 PR 的账本或批准。本任务不改现有授权与业务方向。

## 错误行为

过期版本、非法审批来源、缺少必填绑定、损坏的候选任务与多个活动候选均沿用各自既有失败/拒绝通道。Git 或 schema 读取失败不产生成功授权或观察。合并以 required check 和 Gate 实际结果为准。

## 回滚

在独立分支上分阶段提交；如需撤回，使用新提交恢复 e23b0668 的相关实现并保留历史、原任务和失败证据。禁止改写已推送的历史。
