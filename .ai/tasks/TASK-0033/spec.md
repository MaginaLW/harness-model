# Task Specification

## 目标

在阶段一 MVP 的产品核心设计原则中加入“重复问题优先 CLI 化”：对规则明确、
重复出现且需要一致处理的诊断、治理或操作问题，优先沉淀为复用核心程序的统一
CLI 能力，并明确可测试、可审计边界。

## 范围

1. 仅修改 `docs/superpowers/specs/2026-08-01-ai-code-collaboration-mvp-design.md`
   的“核心设计原则”章节。
2. 新原则必须同时说明适用条件（规则明确、重复出现、需要一致处理）和实现约束
   （统一 CLI、复用核心程序、可测试、可审计）。
3. 新原则与既有“程序裁决，模型辅助”“Policy 是单一规则来源”和“适配层保持
   轻薄”保持一致，不产生第二份 Policy 或状态逻辑。
4. `TASK-0033` 治理目录由 AI Flow 管理，不计入业务文件范围。

## 非目标

1. 本任务不新增或修改任何 CLI、运行时代码、Policy、schema、模板、Hook、CI、
   状态机、Gate 或测试行为。
2. 不把探索性、一次性或仍需语义判断的问题强制转化为 CLI。
3. 不扩展或重写其他历史设计、实施、运行手册或任务证据。
4. 不声称尚未实现的 CLI 能力已经可用。

## 验收条件

1. “核心设计原则”包含一条独立、明确的“重复问题优先 CLI 化”原则，并覆盖范围
   第 2 项的四个约束。
2. 新原则没有让 CLI、Skill、Hook 或 CI 复制 Policy、状态机或规则引擎。
3. 业务 diff 仅包含允许的设计文档，且 `git diff --check` 通过。
4. `python -m aiflow validate TASK-0033`、最终 scope 校验和 active Policy 指定的
   验证全部通过。

## 禁止动作

未经独立批准，禁止 push、merge、deploy、delete、secret export、paid external call
以及任何外部写入；不得手工降低分流或验证等级，也不得删除或改写历史审计记录。

## 错误行为

若准确表达该原则需要修改运行时、Policy、多个业务文件或改变现有 CLI 行为，必须
停止并扩大范围后重新分类；若表述暗示所有重复提问都应机械 CLI 化，或允许在适配层
复制规则，也必须拒绝该表述并修正后再验证。

## 回滚

通过后续受治理提交移除新增设计原则即可回滚业务变更；`TASK-0033` 的事件、分类、
规格和验证记录保持追加式审计，不删除、不改写。
