# Review Package

## 审核目标

说明本次审核需要裁决的具体事项。

## 背景

提供理解变更所需的最小项目和任务背景。

## 代码地图

列出相关文件、入口和关键依赖关系。

## 语义变更

说明行为、契约或配置语义如何变化；核对抽象抽取是否满足“同业务规则、同向演进、合并不增标志位”三条件，确认容错防卫仅设于不可信输入与外部 I/O 边界。

## 风险

列出已识别风险、影响与缓解措施。

## 证据

区分已验证结果、复现命令和仍未验证的场景。

## 审核问题

列出审核者必须明确回答的问题，并附带交付边界五项自检结论：

1. 目标与关键假设是否清楚；
2. 是否已核实语言标准库与代码库既有复用机会；
3. 各修改模块是否存在更简单的直接实现；
4. 新增抽象、分支或配置项是否均有当前明确依据；
5. 是否只触及了任务范围边界内的文件（收尾若含人工打断核验，按 `S / Q / U / H` 汇总：`S`=停下求助、`Q`=自记待定、`U`=多余打断、`H`=高价值护栏）。

## 推荐结论

从 APPROVE、APPROVE_WITH_CONDITIONS、REQUEST_CHANGES、REJECT 或 BLOCKED 中选择并说明理由。
